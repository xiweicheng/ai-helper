引言 ​

本文面向 MCP 协议扩展与 Skill 技能系统的 API 使用者与维护者，说明 Agent 本地代理端暴露的 HTTP 接口契约、MCP 工具注册与调用流程、Skill 类型与执行模型，以及权限与安全策略。文档以仓库中 agent/src/server.js 为路由入口，结合 MCP 注册表、MCP 客户端、Skill 注册表、Skill 执行器与加载器进行代码级分析，并给出可操作的 API 使用示例和实现约束。

本项目采用双进程架构：Chrome 扩展端通过本地 HTTP/WebSocket 调用 Agent；Agent 源码修改后必须重启进程，新接口才生效。

项目结构与协议边界 ​

Agent 端是 MCP 与 Skill 能力的运行时载体，对外暴露统一 HTTP 路由；扩展端通过 local-agent-client.js 封装 /api/mcp/* 与 /api/skill/* 调用。

核心组件总览 ​

  • HTTP 路由层：server.js 负责认证、CORS、请求体解析、日志、安全校验，并将请求分发到 MCP 与 Skill 子系统。
  • MCP 子系统：mcp/registry.js 维护已连接 MCP Server 实例，提供状态查询、工具列表、工具调用、连接/断开、启用/禁用等能力；mcp/client.js 基于官方 SDK 实现 stdio/SSE/streamableHttp/websocket 传输。
  • Skill 子系统：skill/registry.js 管理 Workflow 与 Agent 两类技能的生命周期；skill/executor.js 按 DAG 拓扑并行执行步骤；skill/loader.js 从文件系统加载 JSON/YAML Workflow 与 SKILL.md Agent 技能。
  • 扩展端客户端：local-agent-client.js 封装 Skill/MCP 相关 API 调用，供 side panel 与 options 页面使用。

架构总览 ​

Agent 启动时初始化搜索工具、RAG 检测、MCP 注册表与 Skill 注册表；每次请求根据 Accept-Language 同步各子模块语言；所有需要写操作或敏感能力的接口均要求 Bearer Token 认证。

MCP 工具管理 API ​

通用约定 ​

  • 基础路径：/api/mcp/*
  • 认证：除 GET 列表类接口外，其余通常需要 Bearer Token；GET 列表接口在认证区，但部分实现仍会走认证逻辑。
  • 响应格式：统一 { success, ... }，失败时附带 error。
  • 错误码：常见为 400（参数缺失）、401/403（认证失败）、500（内部错误）。

注意：需求中提到的 /api/mcp/status 在当前路由实现中对应的是 /api/mcp/servers，用于获取 MCP 服务器状态；若前端期望 /api/mcp/status，应改为 /api/mcp/servers。

GET /api/mcp/servers ​

  • 作用：返回所有 MCP Server 的配置、连接状态、工具数量与工具元数据。
  • 典型响应结构：
    • success: true
    • servers: 数组，每项包含 id、name、enabled、connected、toolCount、tools、serverInfo。
  • 未连接时 tools 为空数组，toolCount 为 0。

章节来源

  • agent/src/server.js#L2012-L2015
  • agent/src/mcp/registry.js#L60-L83

GET /api/mcp/tools ​

  • 作用：返回所有已连接 MCP Server 的工具列表，支持按 serverId 过滤。
  • 典型响应结构：
    • success: true
    • tools: 数组，每项包含 serverId、serverName、name、description、inputSchema。
  • 未连接 Server 的工具不会出现在列表中。

章节来源

  • agent/src/server.js#L2017-L2021
  • agent/src/mcp/registry.js#L89-L108

POST /api/mcp/call ​

  • 作用：调用指定 MCP Server 的工具。
  • 请求体：
    • serverId: 必填，MCP Server ID。
    • toolName: 必填，工具名称。
    • args: 可选，工具参数对象。
  • 响应：
    • success: 布尔值。
    • content: 文本内容（来自 MCP 返回的 text 类型 content）。
    • raw: 原始 MCP 返回对象。
    • error: 失败原因。

POST /api/mcp/servers/connect ​

  • 作用：连接指定 MCP Server。
  • 请求体：id。
  • 行为：先断开已有连接，再创建新 McpClient 并连接；成功后返回工具数量。

POST /api/mcp/servers/disconnect ​

  • 作用：断开指定 MCP Server。
  • 请求体：id。
  • 行为：关闭底层 client 与 transport，并从内存映射中移除。

章节来源

  • agent/src/server.js#L1893-L1899

POST/DELETE /api/mcp/servers ​

  • 作用：添加或删除 MCP Server。
  • 添加请求体关键字段：
    • id：必填。
    • transport：stdio、sse、streamableHttp、websocket。
    • command：stdio 模式必填。
    • url：HTTP 类传输必填。
    • headers：HTTP 类传输可选。
    • env、cwd、args：按需配置。
  • 安全校验：stdio 模式下会对 command + args 执行命令安全检查，可能返回 confirm 级别需用户确认。

章节来源

POST /api/mcp/servers/toggle ​

  • 作用：启用或停用 MCP Server。
  • 请求体：id、enabled。
  • 行为：禁用时会先断开连接，确保工具立即不可用。

Skill 技能管理 API ​

通用约定 ​

  • 基础路径：/api/skill/*
  • 认证：Skill 管理接口位于认证区，需要 Bearer Token。
  • 响应格式：统一 { success, ... }，失败时附带 error。
  • Skill 类型：
    • workflow：确定性自动化流程，由 JSON/YAML 定义 steps DAG。
    • agent：AI 能力扩展，由 SKILL.md 描述，适合由 AI 在对话中按需加载与调用。

GET /api/skill/list ​

  • 作用：返回所有已注册 Skill 的轻量信息。
  • 可选参数：type=workflow|agent。
  • 返回字段：
    • name：技能名称。
    • type：workflow 或 agent。
    • enabled：是否启用。
    • builtin：是否为内置技能。
    • editable、deletable：是否可编辑/删除。
    • Workflow 额外字段：stepCount、parameters。
    • Agent 额外字段：resourceCount、resources、dirName。

  • 作用：获取单个 Skill 的完整定义。
  • 参数：name。
  • 返回：skill 对象，包含 type、steps、prompt、resources 等。

POST /api/skill/run ​

  • 作用：执行 Workflow Skill。
  • 参数：
    • name：必填。
    • params：可选，参数对象。
  • 行为：
    • 仅支持 workflow 类型；Agent Skill 直接拒绝。
    • 执行器按 DAG 拓扑并行执行步骤，支持条件跳过、变量注入、超时保护。
  • 返回：
    • success：整体成功标志。
    • execId：执行 ID。
    • results：步骤结果映射。
    • partial：部分成功时存在。
    • message：执行摘要。

    • description、version、parameters：可选。
  • 行为：保存到 ~/.ai-helper-agent/skills/<name>.json，并立即注册到内存。

  • 作用：删除 Skill。
  • 参数：name。
  • 行为：

    • 内置技能不可删除。

MCP 协议自动发现机制 ​

MCP 自动发现基于官方 SDK 的 listTools 与 callTool 能力：

  • 连接成功后调用 client.listTools({})，将返回的 tools 缓存到 McpClient.tools。
  • 注册表聚合所有已连接 Client 的工具，提供扁平化工具列表。
  • 工具调用通过 client.callTool({ name, arguments }) 转发到远端 MCP Server。

Skill 定义格式与模板引擎 ​

Workflow Skill 定义 ​

Workflow Skill 以 JSON 或 YAML 文件保存在 ~/.ai-helper-agent/skills/<name>.json。

关键字段：

  • name：必填，技能名称。
  • description：必填，技能描述。
  • version：可选，默认 1.0。
  • enabled：可选，默认启用。
  • parameters：可选，参数定义，支持 JSON Schema 风格。
  • steps：必填，步骤数组，每个 step 包含：
    • id：步骤 ID。
    • tool：工具名，如 agent_read_file、agent_exec、agent_search_files。
    • args 或 params：步骤参数，支持模板变量。
    • dependsOn：可选，依赖步骤 ID 数组。
    • when：可选，条件表达式，支持模板渲染。

模板引擎：

  • 使用 template.js 的 render 函数对字符串参数进行变量替换。
  • 变量来源包括：
    • 用户传入的 params。
    • Skill 定义的 parameters.default。
    • 前面步骤的结果，如 step.<stepId>、step.<stepId>.success、step.<stepId>.content。

Agent Skill 定义 ​

Agent Skill 以目录形式保存，目录内包含 SKILL.md，支持 frontmatter 与资源文件。

关键字段：

  • name：frontmatter 中的名称。
  • description：frontmatter 中的描述。
  • version：frontmatter 中的版本。
  • enabled：frontmatter 中的启用状态。
  • fullPrompt 或 prompt：SKILL.md 内容。
  • resources：资源文件列表，包含 name、type、size、path。
  • dirPath：技能目录路径。

模板引擎：

  • Agent Skill 不直接执行步骤，而是由 AI 在对话中按需加载完整 prompt。
  • 系统会注入工作目录信息，帮助 AI 解析相对路径。

技能执行框架、权限控制与沙箱隔离 ​

执行框架 ​

  • Skill 执行器构建步骤依赖 DAG，按拓扑排序并行执行就绪步骤。
  • 支持条件跳过（when）、变量注入、步骤结果引用。
  • 执行过程有超时保护（默认 5 分钟），并记录活跃执行状态。
  • 返回 partial 表示部分步骤失败，但仍可继续后续步骤。

Validate --> BuildDag["构建步骤依赖 DAG"]
BuildDag --> Ready["收集就绪步骤"]
Ready --> Batch["并行执行批次步骤"]
Batch --> Condition{"是否满足 when 条件?"}
Condition --> |否| Skip["标记步骤跳过"]
Condition --> |是| Render["渲染步骤参数"]
Render --> ToolCall["执行工具调用"]
ToolCall --> Result{"工具调用成功?"}
Result --> |是| Success["标记步骤成功"]
Result --> |否| Error["标记步骤错误"]
Skip --> NextReady["查找新的就绪步骤"]
Success --> NextReady
Error --> NextReady
NextReady --> Done{"是否还有未完成步骤?"}
Done --> |是| Ready
Done --> |否| Finalize["汇总结果并返回"]

沙箱隔离 ​

  • Skill 执行器不直接暴露任意命令执行给外部；仅允许预定义工具：

  • 命令执行通过统一执行器，支持 Git Bash 等环境下的 Bash 特性。

性能与稳定性特性 ​

  • 并发限制：活跃 Skill 执行最多 100 个，超过上限清理最旧的已完成记录。
  • 超时保护：Skill 执行默认 5 分钟超时，防止长时间阻塞。
  • 清理策略：执行完成后 10 分钟清理执行记录，避免内存泄漏。
  • MCP 连接复用：已连接 MCP Server 的 Client 实例缓存于内存，避免重复连接开销。
  • 工具列表缓存：MCP 工具列表在连接后缓存，减少频繁探测开销。

故障排查指南 ​

常见问题 ​

  • MCP 工具列表为空：
    • 检查 MCP Server 是否已连接。
    • 检查 transport 配置是否正确（stdio/SSE/streamableHttp/websocket）。
    • 查看 MCP Server 是否支持 listTools。
  • Skill 执行失败：
    • 检查 Skill 名称是否存在且启用。
    • 检查步骤依赖是否形成环或缺失前置步骤。
    • 检查命令是否被安全策略拒绝。
  • 认证失败：
    • 检查 Authorization: Bearer <token> 是否正确。
    • 检查 Token 是否有效。

调试建议 ​

  • 查看 Agent 日志，关注 skill_run、mcp_tool_call、auth_missing、auth_invalid 等日志类别。
  • 使用 /api/skill/agent-prompts 与 /api/skill/agent-prompt 验证 Agent Skill 是否被正确加载。
  • 使用 /api/mcp/servers 与 /api/mcp/tools 验证 MCP Server 状态与工具发现。
