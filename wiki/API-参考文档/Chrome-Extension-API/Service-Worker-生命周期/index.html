引言 ​

本文聚焦 MV3 Service Worker 的生命周期管理，围绕启动、运行和终止三个阶段展开，重点说明以下能力：

  • 保活机制：侧边栏长连接保活、任务级心跳、闹钟自动续跑。
  • 状态持久化：内存状态与 IndexedDB、chrome.storage.local 的同步策略。
  • 事件监听器注册与注销：页面事件、定时器事件、系统事件的处理流程。
  • 调试技巧与常见问题：内存泄漏检测、性能优化建议、SW 重启恢复路径。

本仓库采用双进程架构：Chrome 扩展端（Manifest V3，Service Worker）与独立本地代理端 Agent（Node.js）。本文仅讨论扩展端 Service Worker 的生命周期；Agent 端运行时约束在仓库文档中另有说明。

核心组件 ​

  • Service Worker 入口：负责初始化国际化、定时任务恢复、自动续跑接线、keepalive 端口处理、侧边栏路由、全局快捷键等。
  • 会话状态与取消控制：维护 ReAct 循环取消标志、AbortController、工具级中止、keepalive 端口注册表与实例身份。

  • 存储层：IndexedDB 封装与 ReAct checkpoint 的双写策略（IndexedDB + chrome.storage.local）。
  • 侧边栏：建立 keepalive 长连接，上报实例身份，驱动 API 调用。

架构总览 ​

Service Worker 生命周期分为三个阶段：启动阶段完成初始化与数据自检；运行阶段通过 keepalive 端口、心跳与闹钟维持活跃；终止阶段由系统回收或显式卸载触发，但通过闹钟与 checkpoint 实现“可恢复”。

Service Worker 启动流程 ​

  • 初始化国际化，读取语言偏好。
  • 重建定时任务闹钟（从 DB 恢复）。
  • 注册自动续跑闹钟处理器，扫描残留 checkpoint 并尝试续跑。
  • 启动时清理过期 ReAct checkpoint，同时作为 DB 自检，验证 reactCheckpoints store 可访问。
  • 恢复脱离窗口状态，避免 SW 终止竞态下 UI 异常。

保活机制与代码路径 ​

保活由三层保障构成：

  1. 侧边栏长连接保活：侧边栏通过 chrome.runtime.connect('keepalive-<sessionId>') 建立端口，SW 接收并记录端口，防止 Chrome 判定 SW 空闲而杀死。
  2. 任务级心跳：测试用例注释指出，任务执行期每 20s 主动调用轻量 API 重置闲置计时器（参考测试注释中的标准模式）。
  3. 闹钟自动续跑：主任务执行期间注册 30s 周期闹钟；SW 被杀后闹钟唤醒 SW，扫描残留 checkpoint 自动续跑。

状态持久化策略：内存状态与 IndexedDB 同步 ​

  • 内存状态：activeReactLoops、cancelledSessions、sessionAbortControllers、toolAbortControllers、keepalivePorts、keepaliveIdentities 等。
  • IndexedDB：会话、归档会话、UI 原型、token 统计、ReAct checkpoint、书签、定时任务等。
  • chrome.storage.local：配置、checkpoint 后备存储、跨重启消息恢复。
  • 双写策略：saveReactCheckpoint 先写 chrome.storage.local（可靠），再尝试 IndexedDB（性能优化）；getReactCheckpoint 优先 IndexedDB，失败降级到 chrome.storage.local。

TryIDB --> IDBOk{"IndexedDB 成功?"}
IDBOk --> |是| Done["持久化完成"]
IDBOk --> |否| Fallback["保留 chrome.storage.local 备份"]
DecidePersist --> |否| Done

自动续跑与断点恢复 ​

  • 自动续跑决策：根据 checkpoint 的 interruptedReason、activeReactLoops、autoResumeAttempts 判断是否续跑。
  • 闹钟周期：30s（最小周期），多任务并发共享一个闹钟，引用计数管理 start/stop。
  • 恢复流程：SW 启动时扫描所有 checkpoint，对目标会话递增 autoResumeAttempts 并调用 resumeReactLoopFromCheckpoint。

性能与保活特性 ​

  • 长连接保活：通过 keepalive 端口减少 SW 被杀概率，适用于长时间 API 调用场景。
  • 心跳机制：任务执行期定期调用轻量 API 重置闲置计时器，符合 Chrome 官方建议。
  • 闹钟续跑：30s 周期闹钟确保 SW 被回收后仍能恢复任务，避免无限重试风暴。
  • 存储优化：IndexedDB 提供高性能查询，chrome.storage.local 作为可靠后备。

调试与故障排查指南 ​

  • 内存泄漏检测：检查 keepalivePorts 是否正确注销，abortCurrentTool 是否清理工具级 AbortController。
  • 性能优化：避免频繁 IndexedDB 写入，使用 withStore 的事务包装确保事务提交后再返回。
  • SW 重启恢复：检查 checkpoint 是否成功双写，确认 getAllReactCheckpoints 合并逻辑正常。
  • 常见问题：
    • “No SW”错误：SW 终止竞态下 chrome API 可能为 undefined，需使用可选链保护。
    • 面板无法关闭：检查 sidePanel.close 与 fallback 自关闭逻辑。
    • 通知风暴：自动续跑耗尽次数后应静默，避免重复通知。

结论 ​

Service Worker 生命周期管理通过多层保活机制与状态持久化策略，确保了 MV3 扩展的稳定性和可靠性。侧边栏长连接、任务级心跳与闹钟自动续跑共同构成了保活体系；IndexedDB 与 chrome.storage.local 的双写策略保障了数据一致性。事件监听器的注册与注销流程清晰，便于调试与维护。通过合理的性能优化与故障排查方法，可有效提升用户体验与系统稳定性。
