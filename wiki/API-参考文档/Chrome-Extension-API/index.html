引言 ​

本文面向 Chrome Extension（Manifest V3）扩展端与独立 Agent 端的通信契约，聚焦以下目标：

  • 说明扩展端与 Agent 端的消息通信接口，包括 chrome.runtime.sendMessage、chrome.runtime.onMessage 的使用方式。
  • 解释 Service Worker 生命周期管理：保活机制、状态持久化、事件监听与自动续跑。
  • 说明 Content Script 注入机制和页面工具调用接口。
  • 解释权限管理系统：manifest.json 中的权限声明与运行时权限检查。
  • 给出消息路由表结构、请求/响应格式规范与错误处理模式。
  • 提供从 Content Script 调用 Background 功能的实际流程示例，并说明异步消息传递的处理方式。

本项目采用双进程架构：Chrome 扩展端（MV3，src/ 目录，版本 2.3.1）+ 独立本地代理端 Agent（Node.js，agent/src/server.js 入口，npm 包名 ai-helper-agent，版本 2.3.1）。两端版本号保持同步；Agent 源码修改后必须重启进程，新接口才生效。

项目结构 ​

扩展端以 MV3 Service Worker 为后台进程，Content Script 注入到所有页面，Side Panel 作为用户交互面板，Options 页面用于配置 Agent 连接。Agent 端通过 HTTP/WebSocket 暴露文件系统、命令执行、MCP 工具、RAG 知识库等能力。

架构总览 ​

扩展端与 Agent 端的核心通信路径如下：

  • 扩展内部：Content Script / Side Panel / Options → Background（chrome.runtime.sendMessage / chrome.runtime.onMessage）。
  • 扩展到 Agent：Background → Agent HTTP /api/* 与 WebSocket /api/exec/stream，携带 Bearer Token。

详细组件分析 ​

1. 消息通信接口：chrome.runtime.sendMessage 与 chrome.runtime.onMessage ​

Background 使用 chrome.runtime?.onMessage?.addListener 统一接收来自 Content Script、Side Panel、Options 的消息，并通过 message.type 进行路由。部分处理器直接 sendResponse，部分处理器返回 true 表示异步响应，或通过 chrome.runtime.sendMessage 主动推送状态。

  • Content Script 到 Background：Content Script 通过 chrome.runtime.sendMessage 发起页面工具调用，Background 转发到具体 tab 的 Content Script，或直接执行业务逻辑。
  • Side Panel 到 Background：Side Panel 发起会话控制、上下文压缩、RAG 查询、MCP 重载等操作。
  • Options 到 Background：Options 通知 Background 打开/关闭配置页，触发全量 Agent 心跳，并订阅 AGENT_STATUS_CHANGE。

2. Service Worker 生命周期管理：保活、持久化与事件监听 ​

MV3 Service Worker 存在空闲被终止的硬约束。项目实现了两层保活：

  • 任务级保活心跳：在 ReAct 循环执行期间周期性调用轻量扩展 API，重置闲置计时器，避免静默间隙导致 SW 被杀。
  • 自动续跑闹钟：主任务执行期注册 chrome.alarms，SW 被系统回收后由闹钟唤醒，扫描残留 checkpoint 自动续跑，直到达到最大尝试次数。

此外，Background 还维护：

  • keepalive port：Side Panel 通过长连接保活，防止 API 调用期间 SW 被判定空闲。
  • checkpoint 持久化：ReAct 中间状态写入 IndexedDB，支持恢复、过期清理。
  • 事件监听：tabs、windows、tabGroups、sidePanel、commands、storage 等事件驱动 UI 与状态同步。

3. Content Script 注入机制与页面工具调用接口 ​

Content Script 通过 manifest.json 的 content_scripts 声明全局注入，匹配 <all_urls>，在所有帧中运行。其内部维护一个 Map 路由表，按 message.type 分发到页面读取、交互、提取、媒体输出等处理器。

  • 同步处理器：直接返回结果，Background 收到后立即 sendResponse。
  • 异步处理器：返回 Promise 或在 ASYNC_HANDLERS 集合中标记，Background 需保持通道开放，等待 Promise resolve 后回复。
  • 顶层帧限制：部分工具只在顶层 frame 响应，避免 iframe 覆盖主页面内容。

HandlerFound --> |否| Ignore["忽略消息"]
HandlerFound --> |是| RunHandler["执行 handler(message)"]
RunHandler --> AsyncCheck{"是否异步？"}
AsyncCheck --> |是| AwaitPromise["Promise.then(sendResponse)"]

4. 权限管理系统：manifest.json 与运行时权限检查 ​

manifest.json 声明了扩展所需权限与主机权限，包括 activeTab、storage、scripting、sidePanel、debugger、webNavigation 等。Content Security Policy 限制扩展页面的脚本来源。

  • 权限声明：permissions 与 host_permissions 控制扩展对浏览器 API 与网页资源的访问范围。
  • 运行时检查：Background 在调用可能失败的 API 时使用可选链与 try/catch 降级，避免 SW 终止竞态导致整体初始化中断。
  • CSP 限制：extension_pages 仅允许 'self' 脚本与对象资源，防止注入不可信代码。

5. 消息路由表结构与请求/响应格式规范 ​

Background 的消息路由以 message.type 为核心键，常见类型包括：

  • 会话控制：CALL_API、RESUME_REACT、CANCEL_REACT、TERMINATE_COMMAND、ABORT_CURRENT_TOOL
  • 配置与状态：GET_SESSION、GET_CHAT_CONFIG、TRIGGER_AGENT_HEALTH_CHECK、AGENT_CONNECTION_CHANGED
  • 页面工具：IFRAME_SELECTION、IFRAME_CLICK_DISMISS、IFRAME_SELECTION_CLEAR
  • RAG/MCP：RELOAD_MCP_TOOLS、RELOAD_RAG_TOOLS、RAG_LIST_COLLECTIONS、RAG_SEARCH
  • 上下文压缩：COMPACT_CONTEXT_SUMMARY
  • 原型文件：OPEN_LOCAL_PROTOTYPE、DELETE_LOCAL_PROTOTYPE

请求/响应规范：

  • 请求体：通常包含 type 与业务字段（如 sessionId、callId、params）。
  • 响应体：同步处理器通过 sendResponse 返回；异步处理器通过 chrome.runtime.sendMessage 推送 API_COMPLETE、API_ERROR、EXECUTION_STATUS_UPDATE 等。
  • 错误体：统一包含 success、error、httpStatus（Agent 层）、executionLog（截断后）。

6. 错误处理模式 ​

  • 网络错误映射：前端将 Failed to fetch、Load failed、NetworkError 等映射为“网络错误”提示。
  • 超时错误：Agent 客户端将 AbortError 映射为“请求超时”，携带超时时长。
  • 非网络错误：包装为“请求失败”，附带原始错误信息。
  • SW 终止竞态：Background 对 chrome.* API 调用使用可选链保护，避免 SW 即将终止时抛错导致模块加载失败。
  • Content Script 上下文失效：全局捕获 Extension context invalidated 错误与未拒绝 Promise，防止控制台噪音。

性能与保活特性 ​

  • 消息大小限制：Background 对日志条目进行截断，避免超过 chrome.runtime.sendMessage 的 64MiB 限制。
  • 工具预筛选：根据上下文预筛选 MCP/RAG 工具，减少无效调用。
  • 缓存机制：MCP 工具列表、Skill Prompts 等缓存，避免重复网络请求。
  • 保活心跳：任务执行期间每 20s 调用轻量 API，防止 SW 被杀。
  • 自动续跑：闹钟唤醒后扫描 checkpoint，最多尝试 3 次，超限后通知人工介入。

故障排查指南 ​

  • SW 被杀导致任务中断：检查是否处于 ReAct 循环执行期，确认 keepalive port 与自动续跑闹钟是否正常。
  • Content Script 注入失败：检查 chrome.scripting.executeScript 是否成功，查看重试逻辑与指数退避。
  • Agent 连接失败：检查配对状态、Token 有效性、网络可达性，查看 AGENT_CONNECTION_CHANGED 消息。
  • 消息无响应：确认 message.type 是否在路由表中，检查异步处理器是否正确返回 true 或 Promise。
  • 权限不足：核对 manifest.json 中 permissions 与 host_permissions，确认 CSP 未阻止脚本加载。

结论 ​

本项目的 Chrome Extension API 设计围绕 MV3 Service Worker 的生命周期约束展开，通过 keepalive port、任务级心跳与自动续跑闹钟保障长任务稳定性。Content Script 提供丰富的页面工具接口，Background 统一路由并转发到 Agent 端。权限声明与运行时检查确保扩展安全可控。消息路由表清晰，错误处理模式统一，便于扩展与维护。
