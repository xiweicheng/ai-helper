引言 ​

本文面向扩展端（Chrome MV3 Service Worker）与 Agent 端（Node.js）双进程架构的运行问题诊断，覆盖以下关键主题：

  • Service Worker 生命周期管理：空闲终止、保活、消息丢失与状态恢复。
  • 内存泄漏检测与分析：Chrome DevTools Memory 面板、堆快照对比、对象引用追踪。
  • 性能瓶颈识别：CPU 使用率、网络请求监控、渲染性能优化。
  • 日志收集与分析：扩展端日志、Agent 端审计日志、错误信息解读。
  • 调试工具使用：断点调试、变量检查、异步调用追踪。
  • 常见运行时错误与调优建议。

本项目为双进程架构：扩展端位于 src/，Agent 端位于 agent/src/server.js；两端版本号保持同步（当前以 2.3.1 为准）。扩展端通过本地 HTTP/WebSocket 调用 Agent 的文件读写、命令执行、长期记忆与 RAG 能力；Agent 源码修改后必须重启进程新接口才生效。

项目结构 ​

本仓库采用“功能域 + 进程边界”组织方式：

  • 扩展端 background：Service Worker 入口、任务调度、ReAct 循环、工具执行、Agent 客户端、持久化等。
  • 扩展端 side_panel：聊天界面、会话管理、流式输出、交互确认等。
  • 共享模块：logger、i18n、token 计数、主题等。
  • Agent 端 server：HTTP+WebSocket 路由、认证、安全、MCP/Skill/RAG、命令执行、日志等。

核心组件 ​

  • Service Worker 入口与保活：负责 keepalive 端口注册、侧边栏可见性、自动续跑闹钟、过期 checkpoint 清理、SW 重启竞态防护。
  • ReAct 推理循环：心跳包装器、自动续跑开关、checkpoint 持久化与恢复、执行日志裁剪、多模式循环检测。
  • 工具执行与动态注册：内置工具、MCP 工具动态注入、RAG 工具、会话强制 MCP 服务合并。
  • Agent 通信客户端：配对、健康检查、HTTP/WebSocket 封装、可达性缓存、超时控制。
  • IndexedDB 持久化：会话、原型、Token 统计、ReAct checkpoint 双写策略（IndexedDB + chrome.storage.local）。
  • 聊天管理：会话加载、上下文气泡、知识库检索、子任务展示与过滤、恢复提示卡片。
  • Agent 服务端：HTTP 路由、认证、CORS、文件上传、命令执行、MCP/Skill/RAG、审计日志。
  • 命令执行器：跨平台 shell 选择、受管超时策略、输出缓冲截断、进程树终止。

架构总览 ​

扩展端与 Agent 端的通信契约是系统核心：扩展端通过 local-agent-client 发起 HTTP/WebSocket 请求，Agent server 路由到具体子系统（fs/exec/mcp/skill/rag），并记录审计日志。Service Worker 的生命周期由 keepalive 长连接与 alarms 闹钟共同保障，ReAct 循环在 SW 被回收后可通过 auto-resume 机制从 checkpoint 恢复。

详细组件分析 ​

Service Worker 生命周期与保活 ​

  • keepalive 端口：side panel 通过 chrome.runtime.connect 建立 keepalive-<sessionId> 长连接，防止 SW 空闲被杀；重连时检测 activeReactLoops 是否包含 sessionId，若缺失则判定 SW 静默重启并下发 SW_RESTARTED 消息。
  • 自动续跑：主任务期间注册 30s 周期闹钟（chrome.alarms），SW 被回收后由闹钟唤醒，扫描残留 checkpoint 自动续跑；对 user_cancelled/error 终态不自动续，超限次数后仅通知一次。
  • 侧边栏可见性与快捷键：维护 _openPanelsByWindow、_activeTabByWindow、_lastFocusedWindowId 等同步镜像，保证 open/close 在用户手势同步栈内调用。

ReAct 循环与状态恢复 ​

  • 心跳包装器：reactLoop 开启 SW 保活心跳与自动续跑闹钟，finally 中停止；支持嵌套（子任务/子代理）。
  • Checkpoint 持久化：saveReactCheckpoint 先写 chrome.storage.local，再尝试 IndexedDB；失败降级但保证不丢数据；恢复时清理不完整 tool_calls/tool 消息对，注入恢复提示。
  • 执行日志裁剪：EXECUTION_LOG_MEMORY_LIMIT=1000，仅删除非 processing 的旧条目，保留 subtask_plan 以便历史视图展示未执行子任务。

Agent 服务端与命令执行 ​

  • HTTP 路由：startServer 创建 http.createServer，handleRequest 统一处理认证、CORS、路径解析、配置重载、健康检查、配对、重启/更新、文件上传、流式上传等。
  • 命令执行：executeCommand 使用 child_process.spawn，跨平台 shell 选择，受管超时策略（decideTimeoutAction），输出缓冲截断（MAX_OUTPUT_BUFFER=5MB），进程树终止（Windows taskkill /T /PID，Unix SIGTERM/SIGKILL）。
  • 审计日志：appendFileSync 写入 JSON Lines，每日轮转，最大 30 个文件或单文件 10MB，提供 queryLogs/getLogDates 查询接口。

性能注意事项 ​

  • Service Worker 保活：keepalive 端口与 sw-heartbeat 共同防止空闲终止；自动续跑闹钟（30s）确保 SW 被回收后可恢复。
  • 执行日志内存限制：EXECUTION_LOG_MEMORY_LIMIT=1000，避免长任务导致 SW 内存失控；同时保留 subtask_plan 以维持历史视图能力。
  • MCP Schema 压缩：限制 properties 嵌套深度（3）、参数数量（20）、description 长度（150），防止上下文膨胀。
  • Agent 命令输出缓冲：MAX_OUTPUT_BUFFER=5MB，超限时广播 truncated 事件，避免内存无限增长。
  • 网络请求超时：agentRequest/agentGet 默认 60s/30s，uploadFile 60s，downloadFile 120s；可调整 timeoutMs 参数。
  • 渲染性能：side_panel 懒加载大模块（docx 导出），避免首屏 chunk 过大；流式输出增量渲染，减少 DOM 压力。

故障排查指南 ​

Service Worker 生命周期问题 ​

  • 症状：任务中断、API 调用丢失、侧边栏无响应。
  • 排查步骤：
    1. 检查 keepalive 端口是否建立：查看 Background 控制台是否有 keepalive port connected/reconnect 日志。
    2. 检查 SW 是否重启：若检测到 SW_RESTARTED，前端应显示“后台服务异常重启，API 调用已中断”。
    3. 检查自动续跑闹钟：确认 chrome.alarms 是否注册，auto-resume 是否触发。
    4. 检查 checkpoint 是否存在：查看 IndexedDB 中 reactCheckpoints store 是否可用，或 fallback 到 chrome.storage.local。

常见运行时错误与解决方案 ​

  • 错误：IndexedDB store 不存在导致 checkpoint 静默失败。
    • 解决：withStore 检测 store 不存在时重置连接并重试；确保 onversionchange 主动关闭连接。
  • 错误：Agent 未配对或不可达。
    • 解决：检查 pairWithAgent 是否成功，_agentReachability 缓存是否为 false。
  • 错误：命令执行超时或挂起。
    • 解决：调整 commandTimeout 或 timeoutMs，检查 decideTimeoutAction 策略是否合理。
  • 错误：侧边栏无法打开或关闭。
    • 解决：检查 sidePanel.open/close 是否在用户手势同步栈内调用，_openPanelsByWindow 镜像是否正确。
