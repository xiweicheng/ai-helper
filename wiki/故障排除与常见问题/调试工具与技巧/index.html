引言 ​

本指南面向 AI Helper 的开发者、测试人员与高级用户，聚焦以下目标：

  • 在 Chrome 扩展端（Manifest V3）与独立 Agent 端之间建立可复现、可观测的调试路径。
  • 说明如何正确使用内置 debug_page 工具完成页面级调试、网络抓包、截图与环境模拟。
  • 说明扩展端与 Agent 端的日志体系、Token 统计面板、执行时间追踪思路。
  • 提供 WebSocket、HTTP、响应体分析与错误过滤的实操方法。
  • 给出 background 页面、content script、side panel 三类典型调试场景的操作步骤与排错建议。

本项目为双进程架构：扩展端位于 src/，Agent 端入口为 agent/src/server.js；两端版本号保持同步，当前文档以 2.3.1 为准。Agent 源码修改后必须重启进程，新接口才生效。

项目结构与调试边界 ​

AI Helper 的调试边界由三层组成：

  • Side Panel 层：对话界面、执行日志、Token 统计、工作区等 UI。
  • Background Service Worker 层：消息路由、ReAct 执行循环、工具调度、本地 Agent 通信、调试会话管理。
  • Agent 本地服务层：文件读写、命令执行、长期记忆、RAG、MCP 工具注册。

Chrome DevTools 面板使用指南 ​

Console 面板调试 ​

  • 打开扩展后台页面：在 chrome://extensions 中找到 AI Helper，点击“Service Worker”或“Inspect views”。
  • 查看扩展端日志：搜索 [AIH]，这是扩展端 logger 的统一前缀。
  • 查看 Agent 端日志：启动 Agent 后，在终端中观察 stderr 输出的带时间戳、级别、分类标签的行。
  • 过滤技巧：
    • 仅看错误：console.error 或筛选 [AIH] ERROR。
    • 仅看调试信息：筛选 [AIH] DEBUG。
    • Agent 日志可按分类筛选，例如 exec:、security:、auth:。

章节来源

  • src/shared/logger.js#L18-L40
  • agent/src/logger.js#L141-L152

Network 面板抓包 ​

  • 常规抓包：在 DevTools Network 面板勾选 Preserve log，刷新页面或触发操作，观察 XHR/Fetch/WebSocket。
  • 扩展内网访问限制：扩展自身发起的 fetch 不受 Chrome PNA 预检完全约束，因此内网拦截逻辑落在扩展侧；若发现请求未发出，应检查网络范围配置与安全判定。
  • WebSocket：关注 Upgrade 请求与后续 WS 帧；若流式输出异常，优先确认连接是否建立、是否被安全策略拒绝。

Performance 面板分析 ​

  • 关注长任务：ReAct 推理循环、工具执行、截图生成、Markdown 渲染可能产生主线程阻塞。
  • 关注内存峰值：大量 executionLog、DOM 属性膨胀、全量 DOM 扫描都可能造成增长。
  • 结合 Token 统计：若某次调用 token 激增但无对应 UI 反馈，检查 executionLog 是否被截断或 API_COMPLETE 消息是否到达 side panel。

Memory 面板检测 ​

  • 重点观察：
    • IndexedDB 中 token 记录数量增长。
    • side panel 中 executionLog 与 HTML 内容是否被存入 DOM dataset。
    • 长时间使用后是否存在未释放的 debugger session。
  • 清理建议：
    • 清空 Token 统计：通过侧边栏 Token 统计面板的清空按钮。
    • 关闭调试会话：确保 debug_page 最终调用 detach。
    • 重启 Agent：修改 Agent 源码后必须重启进程。

扩展专用调试工具 ​

Background 页面调试 ​

Background 是 MV3 Service Worker，存在生命周期硬约束：

  • 空闲会被终止，需要保活机制。
  • debugger-session 使用 chrome.alarms 在有活动会话时创建短周期 alarm，降低 SW 休眠导致会话丢失的概率。
  • 若出现“会话不存在”“已脱离”类错误，优先检查是否触发了空闲自动脱离、用户取消调试、DevTools 抢占或标签页关闭。

Content Script 注入检测 ​

Content script 适合普通点击、输入、滚动和内容提取；当遇到以下情况时，应切换到 debug_page：

  • 原生事件（canvas、file input、忽略合成事件的控件）。
  • 需要捕获 XHR/fetch 的请求体和响应体。
  • 需要在页面最早时机执行 JS。
  • 需要整页截图或设备/UA 模拟。

Side Panel 界面调试 ​

Side Panel 与 background 的消息传递是常见故障点：

  • Token 统计面板通过 IndexedDB 读取数据并渲染趋势图、分布图和全局统计。

日志系统配置与使用 ​

扩展端日志 ​

扩展端 logger 提供四个级别：DEBUG、INFO、WARN、ERROR。默认级别为 DEBUG，所有级别都会输出到控制台，并以 [AIH] 作为统一前缀。

  • 设置日志级别：通过 setLogLevel 调整当前级别。
  • 获取日志级别：通过 getLogLevel 查询。
  • 输出方法：debug、info、warn、error。
  • 使用建议：
    • 日常开发保留 DEBUG。
    • 生产或性能敏感场景可提升到 INFO 或 WARN。
    • 错误路径必须使用 error，便于在 Console 中快速定位。

章节来源

  • src/shared/logger.js#L1-L51

Agent 端日志 ​

Agent 端日志模块采用 JSON Lines 格式，写入用户目录下的 .ai-helper-agent/logs，并按日轮转，保留最近 30 个日志文件，单个文件超过 10MB 会被清理。

  • 分类标签：auth、fs、exec、security、system。
  • 级别标签：info、warn、error。
  • 输出方式：
    • 前台模式可输出到 stderr。
    • 始终追加写入当日日志文件。
  • 查询接口：支持按日期、分类、偏移和限制查询日志条目。
  • 本地化：类别标签支持 zh/en。

性能监控与 Token 统计 ​

Token 使用统计采集 ​

Token 统计在 API 调用完成后由 background 触发记录：

  • 记录字段包括 sessionId、model、promptTokens、completionTokens、totalTokens、contextWindow、callType。
  • 若模型未返回 total_tokens，则用 promptTokens + completionTokens 兜底。
  • 记录失败不会中断主流程，仅记录 warn。

Token 存储与聚合 ​

Token 明细存储在 IndexedDB 的 tokenStats 表中，并提供多种聚合查询：

  • 会话维度：当前会话的总 token、调用次数、上下文使用率区间、最近 20 条记录。
  • 全局维度：总会话数、总调用次数、总 token。
  • 时间维度：最近 N 天每日聚合。
  • 分布维度：按模型、按 callType 聚合。

侧边栏 Token 统计面板提供三个 Tab：

网络抓包与 API 调试技巧 ​

使用 debug_page 进行网络录制 ​

debug_page 的 network 动作支持三种模式：

  • start：开始录制，可选 filterUrl 过滤 URL。
  • collect：取回并清空缓冲的新请求。
  • stop：停止录制并返回剩余请求。

常见调试场景与问题定位 ​

场景一：无法 attach 调试器 ​

现象：调用 debug_page attach 失败，或提示受限页面。
原因：

  • 目标是 chrome://、扩展商店、PDF 阅读器等受限页面。
  • Service Worker 重启后出现“孤儿附着”，需要先强制 detach 再重试。
  • 用户手动取消调试或 DevTools 抢占。

处理步骤：

  1. 确认目标标签页是普通网页。
  2. 若报错包含“already attached”，让工具自动执行 detach + retry。
  3. 若仍失败，手动关闭目标标签页后重新 attach。

场景二：evaluate 返回空或异常 ​

现象：evaluate 返回“无返回值”或抛出异常。
原因：

  • 表达式无 return。
  • 页面脚本抛错。
  • 调试会话已脱离。

处理步骤：

  1. 检查 expression 是否有效。
  2. 查看异常详情。
  3. 若提示会话不存在，先重新 attach。

场景三：input 点击无效 ​

现象：click 没有触发目标元素。
原因：

  • selector 未找到元素。
  • 元素存在但不可见（尺寸为 0）。
  • 元素在视口外且未 scrollIntoView。
  • 目标在 shadow root 中但未穿透。

处理步骤：

  1. 先用 evaluate 验证 selector 是否能找到元素。
  2. 检查元素是否可见。
  3. 使用工具内部深查询逻辑，确保兼容 Web Components。

场景四：网络录制为空 ​

现象：collect 返回“没有新的网络请求”。
原因：

  • 未先调用 start。
  • 页面未发生相关网络请求。
  • filterUrl 过滤掉了目标请求。
  • 已 collect 过一次，缓冲区已被清空。

处理步骤：

  1. 先调用 start。
  2. 触发页面操作。
  3. 再次 collect。
  4. 如需清空重录，先 stop 再 start。

场景五：Token 统计无数据 ​

现象：Token 统计面板显示暂无数据。
原因：

  • 尚未发生 API 调用。
  • API 调用未返回 usage。
  • recordTokenUsage 静默失败。

处理步骤：

  1. 检查 side panel 是否收到 API_COMPLETE。
  2. 检查 console 中是否有 TokenRecorder warn。
  3. 检查 IndexedDB 中 tokenStats 表是否有记录。

场景六：Side Panel 通知误判可见性 ​

现象：任务完成后通知未弹出或重复弹出。
原因：

  • background 冷启动期间 panel-context 快照不一致。
  • side panel 作用域或宿主 tab 发生变化。
  • port 断开与 onDisconnect 存在跨通道 IPC 竞态。

处理步骤：

  1. 检查 side panel 是否处于可见状态。
  2. 检查当前作用域是全局还是 tab 绑定。
  3. 检查 panel-context 是否正确上报窗口 id、作用域、宿主 tab。

结论 ​

AI Helper 的调试体系围绕三条主线展开：

  • 页面级调试：通过 debug_page 与 Chrome DevTools Protocol 实现 attach、evaluate、原生输入、截图和环境模拟。
  • 网络与 API 调试：通过 debugger-session 的网络录制捕获请求与响应体，并结合扩展侧网络范围判定与 Agent 端日志定位问题。
  • 性能与 Token 统计：通过 token-recorder 与 token-store 将 API 调用沉淀为 IndexedDB 记录，并在 side panel 中以趋势、分布、全局视图呈现。

实际调试时，建议按以下顺序推进：

  1. 先在 Console 中确认扩展端与 Agent 端日志是否正常。
  2. 使用 debug_page 完成页面级验证。
  3. 使用 network 录制抓取 HTTP/WebSocket 数据。
  4. 通过 Token 统计面板确认调用是否落地、token 是否合理。
  5. 若涉及 background 与 side panel 的交互，重点检查消息传递、可见性判断与 Service Worker 生命周期。
