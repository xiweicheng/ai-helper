引言 ​

本地代理服务是 AI Helper 双进程架构中的 Node.js Agent 端，负责为 Chrome 扩展提供受控的本地文件系统访问、系统命令执行、长期记忆、RAG 检索、MCP 工具调用与技能管理。Agent 通过 HTTP API 和 WebSocket 暴露能力，并通过配对码 + Token 机制完成扩展与代理之间的认证绑定。

关键约束：

  • 扩展端（Manifest V3）与 Agent 端（Node.js）版本号保持同步，当前以 2.3.1 为准。
  • Agent 源码修改后必须重启进程，新接口才生效。
  • 扩展端 Service Worker 存在生命周期硬约束，side panel 与 background 消息传递是常见故障点。
  • 所有面向浏览器的响应需遵循 CORS 白名单策略，仅允许 chrome-extension:// 来源跨域读取。

项目结构 ​

Agent 入口为 agent/src/server.js，采用单文件路由 + 多模块职责分离的设计：

  • HTTP 路由与请求处理集中在 server.js。
  • 认证逻辑在 auth.js。
  • 路径沙箱与命令分级在 security.js。
  • 子进程命令执行与超时控制封装在 executor.js。
  • 回收站逻辑在 trash.js。
  • 配置加载、缓存与写锁在 config.js。

核心组件 ​

  • HTTP 服务器：统一解析请求、CORS、国际化、认证拦截、路由分发、错误兜底。
  • WebSocket 服务器：仅开放 /ws/exec/{execId}，用于命令流式输出。
  • 认证系统：配对码轮换、Token 验证、活跃连接窗口、失败锁定。
  • 安全系统：路径白名单 + 硬阻止 + 符号链接校验；命令黑名单/灰名单/白名单三级管控。
  • 命令执行引擎：shell 选择、子进程管理、stdout/stderr 流式广播、超时预算与延长策略、进程终止。
  • 文件操作服务：读、写、列表、统计、删除、移动、重命名、下载、批量下载、流式下载、XLSX 预览。
  • 回收站：软删除、元数据持久化、跨设备回退、7 天自动清理。
  • 配置管理：默认值、内存缓存、mtime 刷新、写入互斥锁、敏感字段落盘混淆。

架构总览 ​

Agent 的请求处理流程可概括为：

  1. 解析 Accept-Language，设置各模块语言。
  2. 处理 OPTIONS 预检，仅放行 chrome-extension:// 来源。
  3. 对无需认证的接口直接处理（配对、健康检查、本机关闭）。
  4. 对需要认证的接口校验 Bearer Token。
  5. 按 pathname 分发到文件、命令、Skill、MCP、Memory、RAG 等路由。
  6. 所有异常进入全局 catch，返回国际化错误。

详细组件分析 ​

HTTP 服务器与路由 ​

HTTP 服务器承担以下职责：

  • 构建 JSON 响应并设置 CORS 头，仅允许 chrome-extension:// 来源。
  • 解析 JSON body，限制最大体大小。
  • 解析 multipart/form-data 上传。
  • 维护工作目录切换、允许路径增删。
  • 提供文件读写、列表、统计、删除、移动、重命名、下载、批量下载、流式下载、XLSX 预览。
  • 提供命令执行、停止、daemon 化。
  • 提供 Skill、MCP、Memory、RAG 路由转发。
  • 提供回收站恢复与列表。
  • 提供审计日志查询。
  • 启动 WebSocket 升级，仅接受 /ws/exec/{execId}。

关键路由分组：

  • 无认证：/api/pair、/api/status、/api/shutdown（远程仍需认证）、/api/heartbeat。
  • 认证后：/api/status/detail、/api/files/upload、/api/fs/*、/api/exec*、/api/trash/*、/api/logs/query、/api/skill/*、/api/mcp/*、/api/memory/*、/api/rag/*。

认证与安全系统 ​

认证系统包含：

  • 配对码生成与定时轮换。
  • 连续失败锁定。
  • Token 验证并更新最近活跃时间。
  • 已配对扩展的 Token 存储于 pairings.json，落盘前混淆。

安全系统包含：

  • 路径规范化、~ 展开、绝对路径解析。
  • 硬阻止目录（配置文件、配对记录、日志、回收站、内置技能状态）。
  • 工作目录永远放行，但 realpath 仍做硬阻止校验。
  • allowedPaths 白名单前缀匹配 + realpath 二次校验。
  • 命令黑白灰名单，支持链式命令拆分、包装器剥壳、解释器内联载荷、命令替换扫描。

文件操作服务 ​

文件操作服务覆盖完整生命周期：

  • 上传：multipart 与流式上传，均做路径安全检查与大小限制。
  • 读取：校验路径、目录判断、大小限制、UTF-8 或 base64。
  • 写入：父目录创建、base64 解码、脚本权限剥离。
  • 列表：递归枚举条目类型、大小、时间。
  • 统计：权限、时间、MIME、符号链接标记。
  • 删除：走回收站。
  • 下载：单文件、目录 zip、批量 zip、流式下载。
  • XLSX 预览：服务端解析前若干行，避免前端引入 SheetJS。
  • 目录创建、重命名、移动：严格目标路径校验，防止静默覆盖。

命令执行引擎 ​

命令执行引擎负责：

  • 平台 shell 选择：Windows Git Bash/cmd/PowerShell，macOS zsh/bash，Linux bash/sh。
  • 子进程标准输出/错误输出流式广播。
  • 输出缓冲区上限截断。
  • 超时策略：基础超时、有输出则延长、最多延长次数、总预算封顶。
  • 进程终止：Unix 进程组 SIGTERM/SIGKILL，Windows taskkill /T /PID。
  • WebSocket 回放：已完成进程输出缓存，延迟连接客户端可回放。
  • daemon 化：显式 detach 豁免超时。

回收站功能 ​

回收站实现软删除：

  • 移动到 ~/.ai-helper-agent/.trash/。
  • 记录原始路径、名称、大小、删除时间、是否目录。
  • 跨设备 rename 失败时回退复制+删除源。
  • 7 天 TTL 自动清理。
  • 每 6 小时定期清理。
  • 恢复时检查原路径是否被占用。

WebSocket 通信 ​

WebSocket 仅开放 /ws/exec/{execId}：

  • 升级前解析 URL。
  • 认证优先 Authorization Header，回退 query token。
  • 将客户端加入运行中进程的监听集合。
  • 心跳 ping/pong 检测半开连接。
  • 断开连接后按受管模式与旧语义分别处理超时。

性能与容量特性 ​

  • 请求体大小限制：JSON body 与 multipart 均限制为 200MB。
  • 文件读取/下载默认大小限制：50MB，可通过配置调整。
  • 流式上传：200MB，按字节计数保护。
  • 命令输出缓冲区上限：5MB，超限后广播截断提示。
  • 搜索最大结果数：5000。
  • 流式下载分块：64KB，使用 setImmediate 或 drain 让出事件循环。
  • 超时策略：基础超时、有输出延长、最多 5 次延长、总预算封顶 600s。
  • 配置缓存：mtime 命中返回内存对象，减少磁盘 IO。
  • 回收站清理：每 6 小时一次，避免长时间运行积累垃圾。

SSL 证书配置 ​

当前 Agent 使用原生 http.createServer，未内置 HTTPS 支持。若需 TLS：

  • 建议在前置反向代理（如 Nginx、Caddy）配置 SSL 终止。
  • Agent 仅监听本地或可信网络地址，避免直接暴露公网。
  • 若未来改为 HTTPS，需确保 CORS、Token、WebSocket upgrade 链路一致。

安全最佳实践 ​

  • 始终启用 Bearer Token 认证，避免无认证接口被恶意网页读取。
  • 仅允许 chrome-extension:// 作为 CORS 来源。
  • 使用 allowedPaths 精确限定可访问目录，不要随意扩大白名单。
  • 避免将 Agent 工作目录设为 .ai-helper-agent 自身。
  • 谨慎使用 force 参数，它只能跳过灰名单，不能绕过黑名单。
  • 监控审计日志，关注 exec_denied、fs_*_blocked、auth_invalid。
  • 定期清理回收站，避免磁盘膨胀。
  • 对脚本类文件上传/写入后，Agent 会剥离执行权限，但仍应避免从不可信来源直接执行脚本。
  • RAG 依赖安装与 Agent 在线更新互斥，避免并发写 node_modules。

故障诊断指南 ​

常见问题定位 ​

  • 端口占用：服务器启动报错 EADDRINUSE，退出进程。
  • 配对失败：检查配对码是否轮换、扩展 ID 是否正确、失败锁定是否触发。
  • Token 无效：检查 Authorization: Bearer <token> 是否正确。
  • 文件路径被拒：检查 allowedPaths、workdir、符号链接、硬阻止目录。
  • 命令被拒：查看 level=deny 原因，确认是否命中黑名单。
  • 命令超时：检查输出流是否有数据，受管模式下无输出会被判定挂起并杀死。
  • WebSocket 断连：检查心跳 ping/pong，确认插件端 SW 保活。
  • RAG 不可用：调用 /api/rag/detect 查看探测错误，必要时重新安装依赖。

日志与审计 ​

  • 审计日志分类：认证、文件、命令、安全、系统。
  • 日志查询接口：/api/logs/query，默认最近 7 天，单次最多 500 条。
  • 前台运行时日志实时输出到终端。
  • 全局未捕获异常与未处理 Promise 拒绝会被记录但不退出进程。

结论 ​

本地代理服务通过 HTTP + WebSocket 将浏览器扩展的能力扩展到本地文件系统与命令行，同时以路径沙箱、命令分级、Token 认证、审计日志构成多层安全边界。其设计强调可控性：工作目录与白名单控制文件范围，黑名单绝对禁止高危命令，灰名单要求用户确认，回收站提供后悔空间，超时与进程树终止保障资源安全。部署时应遵循最小暴露原则，结合反向代理与防火墙规则，配合审计日志进行持续监控。
