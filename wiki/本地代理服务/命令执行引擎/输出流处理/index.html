引言 ​

本文面向“输出流处理机制”，围绕以下目标展开：

  • 标准输出捕获：stdout/stderr 分离、实时流式传输、缓冲区管理与内存限制。
  • WebSocket 消息广播：多客户端支持、连接状态监听、断线重连与回放。
  • 输出缓冲策略：5MB 上限截断、增量追加算法、截断标记通知与回放能力。
  • 流式数据传输：数据分片、顺序保证、错误处理与性能优化。
  • 提供流处理架构图与 WebSocket 消息格式规范，帮助扩展端与 Agent 端开发者对齐协议与实现。

本项目为双进程架构：Chrome 扩展端（Manifest V3，src/）与独立本地代理端 Agent（Node.js，agent/src/server.js）。两端通过 HTTP/WebSocket 通信；Agent 负责命令执行、子进程 stdout/stderr 流式输出与 WebSocket 广播；扩展端 background 负责 SSE 解析、节流发送、工具调用检测与 Agent 命令流转发。

项目结构 ​

与输出流处理直接相关的代码分布在两个进程中：

  • Agent 端
    • agent/src/server.js：HTTP + WebSocket 服务器，路由命令执行、WebSocket 连接生命周期管理。
    • agent/src/executor.js：命令执行器，封装 child_process 子进程、stdout/stderr 流、超时策略、缓冲区与广播。
  • 扩展端
    • src/background/stream-controller.js：SSE 流控制器，负责 OpenAI 兼容流解析、节流、tool_calls 检测、空闲超时保护。
    • src/background/tool-executor.js：工具执行层，负责将 Agent 命令的 stdout/stderr 转换为扩展侧消息并转发到 UI。

架构总览 ​

输出流处理贯穿两条主线：

  • LLM 推理流：扩展端通过 stream-controller.js 读取外部 LLM 的 SSE 流，解析 content/tool_calls/usage，节流发送到 Side Panel。
  • Agent 命令流：扩展端通过 tool-executor.js 调用 Agent 的 HTTP/WebSocket 接口，Agent 端 executor.js 启动子进程并将 stdout/stderr 实时广播给所有连接的 WebSocket 客户端。

详细组件分析 ​

Agent 命令执行器（executor.js） ​

  • 子进程与流绑定
    • 使用 child_process.spawn 启动 shell 命令，stdio 配置为 ['ignore', 'pipe', 'pipe']，分别对应 stdin 忽略、stdout/stderr 管道。
    • 对 proc.stdout 与 proc.stderr 分别注册 data 事件，实现 stdout/stderr 分离处理。
  • 输出缓冲区与内存限制
    • 每个运行中的进程 entry 包含 stdoutBuf 与 stderrBuf，始终收集用于回放给延迟连接的 WS 客户端。
    • 定义 MAX_OUTPUT_BUFFER = 5 * 1024 * 1024（5MB），通过 appendWithLimit 实现增量追加与上限截断。
    • 当追加导致超过上限时，设置 truncStdout/truncStderr 标志，并向所有 WS 客户端广播 stdout_truncated 或 stderr_truncated 消息。
  • 超时策略
    • 受管模式：由 decideTimeoutAction 根据 outputInPeriod、extensions、elapsedMs、baseTimeout 决定 extend 或 kill。
    • 旧模式：到期直接 killProcess。
    • outputInPeriod 在每次 stdout/stderr 数据到达时置为 true，作为“心跳”判断是否静默挂起。
  • WebSocket 广播与多客户端
    • 每个 execId 对应一个 wsClients Set，broadcast 遍历 Set 向所有 readyState=1 的客户端发送 JSON 消息。
    • addWsClient 支持新连接加入运行中进程，或在进程已结束的情况下从 completedProcesses 缓存回放全部输出与结束状态。
    • disconnectWsClient 在所有客户端断开后，仅在非受管模式或已 detach 时才取消超时定时器，避免插件端 SW 被 Chrome 终止导致的误判。
  • 进程终止
    • killProcess 跨平台递归终止进程组：Unix 使用 process.kill(-pid)，Windows 使用 taskkill /T /PID，并在 5 秒后强制 SIGKILL。

Agent WebSocket 服务器（server.js） ​

  • HTTP 路由
    • 提供 /api/exec 等接口，调用 executor.executeCommand 或 executeCommandSync。
    • 提供 /api/exec/stop 与 /api/exec/detach 接口，分别调用 killProcess 与 detachProcess。
  • WebSocket 连接管理
    • 当客户端连接 /ws 时，若携带 execId，则尝试 addWsClient 将其加入对应进程的 wsClients。
    • 若进程已结束，completedProcesses 缓存会回放 stdout/stderr/error/exit 消息。
    • onclose/onerror 时调用 disconnectWsClient，清理 wsClients 并根据规则决定是否取消超时定时器。
  • 语言与国际化
    • 在请求入口设置 setExecutorLang(lang)，使 executor 内部 translate 返回正确语言文案（如 stdoutTruncated、stderrTruncated）。

扩展端流控制器（stream-controller.js） ​

  • SSE 解析
    • feedLine 逐行解析 OpenAI 兼容格式的 SSE 数据，支持 data: 前缀、[DONE]、choices.delta.content、choices.finish_reason、usage、tool_calls。
    • normalizeToolCalls 过滤稀疏数组空洞并补齐缺失 id，防止前端渲染 TypeError。
  • 节流与合并
    • sendChunk 使用 _pendingChunk 累积内容，按 streamChunkDelay 节流发送 STREAM_CHUNK。
    • finish 强制刷新缓冲区，发送 STREAM_DONE，并附带 finalContent、reasoningContent、usage、toolCalls。
  • 空闲超时保护
    • readSSEStream 使用 idleTimer 与 Promise.race，持续无数据达到 STREAM_IDLE_TIMEOUT_MS 时抛出 StreamIdleTimeout，主动 cancel 底层 reader 并 finish。
  • Agent 命令流转发
    • sendAgentStream 与 sendAgentStreamDone 将 Agent 的 stdout/stderr 与 exit 状态转换为扩展侧消息，供 UI 消费。

扩展端工具执行层（tool-executor.js） ​

性能与内存保护 ​

  • 输出缓冲区上限
    • 5MB 上限通过 appendWithLimit 实现，避免长时间命令导致 Node.js 堆内存无限增长。
    • 超过上限时仅追加剩余空间，并设置 truncated 标志，后续追加不再修改缓冲区。
  • 增量追加算法
    • 每次 stdout/stderr 数据块先 toString，再增量追加到 stdoutBuf/stderrBuf。
    • collectOutput 可选开启完整收集，用于同步执行场景返回完整输出。
  • 节流与合并
    • stream-controller.js 的 sendChunk 使用 _pendingChunk 累积内容，按 streamChunkDelay 节流发送，减少 UI 渲染压力。
  • 空闲超时保护
    • readSSEStream 在持续无数据时触发 StreamIdleTimeout，主动 cancel 底层 reader，释放连接资源。
  • 进程终止与资源回收
    • killProcess 跨平台递归终止进程组，并在 5 秒后强制 SIGKILL，防止孤儿进程。
    • completedProcesses 缓存 30 秒后自动清理，避免长期占用内存。

故障排查指南 ​

  • 输出未显示或中断
    • 检查 Agent 端 executor.js 的 stdout/stderr 事件是否触发。
    • 确认 WebSocket 连接状态，server.js 的 addWsClient/disconnectWsClient 是否正确管理 wsClients。
    • 检查扩展端 tool-executor.js 是否成功建立 WebSocket 并转发 AGENT_STREAM/AGENT_STREAM_DONE。
  • 输出被截断
    • 查看 stdout_truncated/stderr_truncated 消息，确认是否触发 5MB 上限。
    • 检查 truncStdout/truncStderr 标志是否正确设置。
  • 命令超时或卡住
    • 检查 decideTimeoutAction 的输出 InPeriod 逻辑，确认是否有 stdout/stderr 心跳。
    • 验证受管模式与非受管模式的超时行为差异。
  • SSE 流空闲超时
    • 检查 readSSEStream 的 idleTimer 与 Promise.race 逻辑，确认是否持续收到数据。
    • 查看 StreamIdleTimeout 异常日志，确认是否需要调整 STREAM_IDLE_TIMEOUT_MS。
