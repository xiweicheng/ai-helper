引言 ​

本文件面向 AI Helper 项目的代码质量与静态检查体系，覆盖以下目标：

  • ESLint 配置规则说明（JavaScript 语法检查、代码风格规范、自定义规则）。
  • 代码格式化策略（当前仓库未集成 Prettier，给出集成建议与自动修复脚本定位）。
  • 静态分析工具链（ESLint、Vitest 单元测试、Playwright E2E、构建产物校验、安全审计文档）。
  • 持续集成中的质量门禁（Release 流水线、安装器验证流程、失败处理与修复建议）。
  • 代码审查清单（常见陷阱、性能与安全注意事项）。
  • 开发工作流集成（Git Hooks 现状、提交前检查建议、PR 自动化验证建议）。

本项目为双进程架构：Chrome 扩展端（Manifest V3，src/）+ 独立本地代理端 Agent（Node.js，agent/src/server.js 入口）。两端版本号保持同步（2.3.1），文档以该版本为准。

项目结构 ​

与代码质量直接相关的根级配置文件如下：

  • package.json：定义 lint、test、build 等脚本，以及 ESLint 依赖。
  • eslint.config.js：ESLint Flat Config，启用基础规则并排除 agent/node_modules 等目录。
  • vite.config.js：扩展构建配置，关闭 sourcemap，避免源码泄露。
  • vitest.config.js：单元测试配置，限定 test/unit 目录，注入 chrome-mock 与 jsdom-globals。
  • playwright.config.js：E2E 测试配置，使用真实 Chromium，CI 下重试一次。
  • .github/workflows/release.yml：发布流水线，构建、打包、上传 GitHub/Gitee Release。
  • .github/workflows/test-install.yml：安装器全生命周期验证（Windows + Unix 管道执行）。
  • agent/package.json：Agent 包元信息、bin 命令、RAG 依赖字段与 Node 引擎约束。
  • docs/AUDIT_REPORT.md：安全与性能审计报告，提供风险项与建议修复顺序。

核心组件 ​

本节聚焦代码质量工具链的核心组成部分：ESLint、测试框架、构建产物校验、发布与安装器验证。

  • ESLint

    • 通过 @antfu/eslint-config 引入通用规则集，并在 eslint.config.js 中追加少量强制规则（如禁止 debugger、重复参数、函数赋值、调用非函数等）。
    • 将 agent 子包纳入 lint 范围，但排除 node_modules 与 dist 等目录，避免扫描第三方代码。
    • 未启用 Prettier；如需统一格式，可在 eslint.config.js 中集成 prettier 插件或新增 .prettierrc 并通过 npm script 驱动自动修复。

  • 单元测试（Vitest）

    • 默认运行环境为 node，全局 API 开启，setupFiles 注入 chrome-mock 与 jsdom-globals，使 content/side_panel 相关逻辑可单测。
    • include 限定 test/unit/**/*.test.js，避免误跑 e2e 或其他测试。

  • 端到端测试（Playwright）

    • 使用真实 Chromium，headless 模式，actionTimeout 10s。
    • CI 环境下 retries=1，forbidOnly=true，防止遗漏 xit/fit 标记。

  • 构建与产物校验

    • Vite 构建输出到 dist，sourcemap 关闭，避免源码随包发布。
    • release.yml 在打包 zip 后再次校验不包含 .map 文件，作为第二道防线。

  • 发布与安装器验证

    • release.yml：触发条件为 v* 标签或手动触发；构建扩展、打包 zip、创建 GitHub Release，并尝试同步到 Gitee（可选）。
    • test-install.yml：在 Windows 上验证 install.ps1 的全生命周期（安装、状态、API、更新、卸载、残留检查），并在 Unix 上模拟 curl|bash 管道执行。

ESLint 配置与规则 ​

  • 规则范围
    • 忽略 dist/、libs/、scripts/、agent/node_modules/、agent/dist/**，避免扫描第三方代码与构建产物。
    • 对 agent 子包启用 lint，补齐历史空白。
  • 自定义规则
    • no-debugger、no-dupe-args、no-func-assign、no-obj-calls 设为 error，用于阻断明显错误与潜在运行时异常。
  • 风格规范
    • 依赖 @antfu/eslint-config 提供基础风格与最佳实践；仓库未显式覆盖更多规则，建议后续按需增强（如 import/order、unicorn 系列、perfectionist 等）。
  • 格式化
    • 未集成 Prettier；若需统一格式，建议在 eslint.config.js 中接入 prettier 插件，或在根目录新增 .prettierrc，并通过 npm script 驱动自动修复。

性能考量 ​

  • 构建产物体积
    • Vite 构建已关闭 sourcemap，避免源码泄露与体积膨胀。
    • release.yml 在打包 zip 后再次校验不包含 .map 文件。
  • 内容脚本注入
    • 审计报告指出 fix-build.js 向每个 iframe 注入约 1.93 MB 脚本（含 pdf.worker），建议优化注入策略与按需加载。
  • 流式渲染与 DOM 操作
    • 审计报告指出流式渲染每约 30 ms 全量重解析 + 整段 DOM 替换，存在性能瓶颈。
  • Service Worker 保活
    • 周期性定时器阻止空闲回收，建议使用 chrome.alarms 替代 setInterval。
  • 存储写放大
    • 工具统计与审计日志“读全量-改-整写回”，应改为增量写入或批处理。

故障排查指南 ​

  • ESLint 失败
    • 检查 eslint.config.js 的 ignores 是否误排了需要扫描的路径。
    • 确认 agent/node_modules 与 agent/dist 被正确忽略，避免第三方代码干扰。
  • 单元测试失败
    • 确认 vitest.config.js 的 include 路径是否正确，setupFiles 是否注入必要 mock。
    • 若涉及 DOM，确保使用 jsdom 环境或文件头注释切换环境。
  • E2E 测试失败
    • 检查 playwright.config.js 的 headless、retries、actionTimeout 设置是否符合 CI 环境。
    • 若网络请求不稳定，考虑增加重试或 Mock。
  • 构建失败
    • 检查 vite.config.js 的 sourcemap 是否被意外开启。
    • 确认 dist/manifest.json 是否存在，release.yml 会校验该文件。
  • 发布失败
    • 检查 GITEE_TOKEN 是否配置，权限是否勾选 projects。
    • 若 Gitee 附件上传失败，查看网络稳定性并重跑流水线。
  • 安装器验证失败
    • Windows：检查 install.ps1 的 param 块与 $env:AGENT_VERSION 回退逻辑。
    • Unix：确认 curl|bash 管道执行语义与版本一致性。
