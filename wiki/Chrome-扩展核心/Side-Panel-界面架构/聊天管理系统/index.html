引言 ​

本文件面向“聊天管理系统”的完整技术文档，覆盖会话管理、消息处理管道、流式响应、上下文压缩、多面板支持、历史存储与搜索、断点续传等关键能力。本次更新重点增强了消息处理管道：新增产物声明解析与合并机制，支持 AI 通过 [[artifact:路径|说明]] 标记声明动态生成的文件产物，并与静态分析结果合并；同时引入聊天内文件路径可点击功能，提升用户体验。系统采用双进程架构：Chrome 扩展端（Manifest V3）负责侧边栏 UI、会话状态与渲染；独立本地 Agent 提供 ReAct 执行循环、工具调用、长期记忆与 RAG 能力。两端通过本地 HTTP/WebSocket 通信契约协作，Agent 源码修改后需重启进程才生效。

项目结构 ​

聊天管理相关代码主要分布在以下模块：

  • 侧边栏聊天编排：chat-manager.js、chat-streaming.js、session-manager.js、session-manager-ui.js、auto-compaction.js
  • 新增产物管理：artifacts-manager.js（含声明解析、合并逻辑）、markdown-render.js（含路径提取、链接转换）
  • 共享上下文计算：context-usage.js
  • 后台流式控制器：stream-controller.js
  • 子代理调度：agent-dispatcher.js
  • 持久化层：session-store.js、db.js
  • 任务恢复：chat-resume.js

核心组件 ​

  • 聊天管理器：负责加载/保存聊天历史、构建知识库上下文、发送消息、协调流式输出、错误提示与国际化文案。
  • 会话管理：对外暴露创建、切换、删除、重命名、排序、归档、导入、复制会话等 API，底层由 IndexedDB 实现。
  • 流式输出：按会话隔离地创建/更新流式 DOM，维护滚动行为、思考指示器、工具卡片与最终结果合并。
  • 产物管理器：新增产物声明解析（parseDeclaredArtifactsFromText）、声明与静态产物合并（mergeDeclaredArtifacts）、一站式构建（buildArtifactsForMessage），支持 [[artifact:路径|说明]] 标记格式。
  • Markdown 渲染器：新增标记剥离（stripArtifactMarkers）、路径候选提取（extractPathCandidates）、文件路径链接转换（applyFilePathLinks）、点击委托绑定（bindFileLinkDelegate）。
  • 自动压缩：在发送前根据阈值与待压缩条数决定是否静默压缩，失败退避不阻断用户发送。
  • 上下文使用：统一计算占用、选择历史、注入摘要，保证预览与发送口径一致。
  • SSE 流控制器：解析 OpenAI 兼容 SSE，节流 chunk，提取 usage/tool_calls/reasoning_content，空闲超时保护。
  • 子代理调度：派生子 Agent，限制嵌套深度，隔离 sessionId，裁剪返回长度。
  • 存储层：IndexedDB 主存储 + chrome.storage.local 后备，支持迁移、归档、书签、定时任务、ReAct checkpoint。
  • 任务恢复：检测遗弃 checkpoint，展示继续执行入口，复用 callApi 流式基础设施完成恢复。

架构总览 ​

聊天管理的端到端流程如下：用户在侧边栏输入消息 → 聊天管理器组装上下文（含知识库检索、技能/MCP/文件/网页引用）→ 选择历史并注入压缩摘要 → 新增：AI 通过系统提示词中的产物声明指引生成 [[artifact:路径|说明]] 标记 → 后台通过 SSE 流式返回内容、工具调用与用量 → 前端解析声明标记，与静态分析产物合并 → 增量渲染、工具卡片与思考过程 → 文件路径自动转换为可点击链接 → 完成后持久化会话与消息，必要时触发自动压缩或归档。

详细组件分析 ​

会话管理机制：创建、切换、保存与恢复 ​

  • 创建会话：生成唯一 ID，写入 IndexedDB，设置活跃会话，初始化默认标题与时间戳。
  • 切换会话：并发保存当前会话与读取目标会话，更新 activeSessionId、messageHistory、模型/温度/工具配置，必要时从 Agent 配置覆盖全局参数。
  • 保存会话：将 state 中的模型、工具、Agent、温度、topP、上下文压缩记录与消息历史序列化到 IndexedDB，自动推导标题。
  • 恢复会话：启动时 loadSessions，若存在活跃会话则恢复其 messageHistory、上下文压缩记录、模型与工具开关；首次打开自动创建默认会话。

消息处理管道：从用户输入到 LLM 响应 ​

  • 输入预处理：提取文本内容、剥离图片、附加选中/引用上下文、技能与 MCP 上下文、RAG 知识库检索结果。
  • 上下文选择：基于 isolateChat、maxMemoryMessages、compaction、historyBudget 选择携带历史，并对被裁消息生成规则摘要。
  • 压缩注入：若启用上下文压缩且摘要有效，将摘要拼入 system prompt，确保不被 trim 丢弃。
  • 产物声明注入：系统提示词中包含产物声明指引（仅在启用工具时注入），引导 AI 在最终回答末尾声明动态生成的文件产物。
  • 发送与流式接收：后台 SSE 流控制器解析 content/tool_calls/reasoning_content/usage，前端流式输出增量渲染。

产物声明解析与合并机制 ​

  • 声明标记格式：[[artifact:路径|可选说明]]，路径必填、说明可省，全角/半角竖线只认半角 |。
  • 变量过滤：含 $VAR、${VAR}、%TEMP% 等变量引用的路径一律丢弃，沿用既有约定。
  • 去重策略：规范化路径后去重，相对路径与绝对路径尾段匹配视为同一文件。
  • 合并逻辑：静态分析产物优先，声明项补充说明信息，source 字段标识来源（'static' | 'declared'）。
  • 一站式构建：buildArtifactsForMessage 组合静态分析、声明解析、合并去重三个步骤。

聊天内文件路径可点击功能 ​

  • 路径候选提取：extractPathCandidates 从可见文本中提取疑似文件路径 token，排除 URL、纯目录、代码块内路径。
  • 可信路径验证：已知的产物路径直接可信，其他路径通过 CHECK_FILES_EXIST 批量校验。
  • 安全边界：仅当工作目录根已知且路径在根内时才发起校验，目录外路径 fail-closed 不转链接。
  • 链接渲染：将有效路径包裹为 .chat-file-link span，带 data-path 属性与 title 提示。
  • 点击委托：bindFileLinkDelegate 一次性绑定 document 级点击事件，调用 locateFileInWorkspace 定位文件。

性能与容量控制 ​

  • 流式节流：streamChunkDelay 控制 chunk 发送频率，避免频繁 DOM 更新。
  • 空闲超时：readSSEStream 空闲 120s 无数据即中断，防止连接卡死。
  • 上下文预算：HISTORY_BUDGET_RATIO=0.7，SAFETY_MARGIN=2000，OUTPUT_BUDGET 预留输出空间，避免超限。
  • 自动压缩退避：连续失败达到 maxFailures 后不再自动尝试，手动成功后重置。
  • 子代理返回裁剪：MAX_RESULT_TOKENS=2000，避免长文本阻塞 UI。
  • 产物声明解析优化：声明标记在 Markdown 渲染前剥离，避免重复解析；路径候选提取使用正则预编译，减少重复计算。

故障排查指南 ​

  • 流式无输出：检查 STREAM_IDLE_TIMEOUT_MS 是否触发，确认 fetchWithTimeout 与 outerWatchdog 已清理；查看 StreamController.finish 是否被调用。
  • 工具卡片异常：确认 normalizeToolCalls 已补齐 id，避免稀疏数组空洞导致 TypeError。
  • 会话切换后状态错乱：检查 switchToSession 中并发 saveCurrentSession 与 idb.getSession 的顺序，确保 state 赋值在 Promise.all 之后。
  • 归档/恢复异常：archiveCurrentSession 最多保留 20 个归档，restoreArchivedSession 会创建新活跃会话并从归档移除。
  • 检查点不可用：getAllReactCheckpoints 合并 storage.local 与 IDB，cleanupExpiredReactCheckpoints 清理过期项；若 store 缺失，withStore 会重试重建连接。
  • 产物声明解析异常：检查 [[artifact:路径|说明]] 语法是否正确，确认变量引用路径已被过滤；验证 mergeDeclaredArtifacts 的去重逻辑是否符合预期。
  • 文件路径链接异常：确认 applyFilePathLinks 的安全边界判断（目录外路径 fail-closed），检查 CHECK_FILES_EXIST 响应格式，验证 locateFileInWorkspace 调用链。

结论 ​

聊天管理系统以“聊天管理器”为核心编排层，结合“会话管理”“流式输出”“上下文压缩”“SSE 流控制器”“子代理调度”“存储层”“任务恢复”等模块，形成高内聚、低耦合的可扩展架构。本次更新显著增强了消息处理管道：通过产物声明解析与合并机制，系统能够识别 AI 声明的动态生成文件产物，并与静态分析结果无缝整合；通过文件路径可点击功能，提升了用户与产物的交互体验。系统在 MV3 Service Worker 生命周期约束下，通过消息传递与会话隔离保障稳定性；在容量与性能方面，通过预算控制、节流与退避策略提升用户体验；在可靠性方面，通过双写检查点与空闲超时增强容错能力。
