引言 ​

本文件面向“输入交互系统”，聚焦侧边栏输入框及其周边能力：文本输入、富文本支持、智能补全、菜单面板系统、交互门控机制、提示词管理、输入历史、键盘快捷键、无障碍与移动端适配，以及输入验证与安全过滤。该系统由 Chrome 扩展端（Manifest V3）与独立本地 Agent 组成，用户输入在侧边栏完成，经后台进程调度后调用 Agent 的文件读写、命令执行、长期记忆与 RAG 等能力。

项目结构 ​

输入交互系统主要位于 side_panel 模块，并与 background、content、agent 三处协同：

  • side_panel：负责 UI 输入、提示词选择、菜单面板、交互门控、历史记录等。
  • background：负责工具确认、会话状态、消息路由与保活。
  • content：负责页面级表单与富文本输入模拟。
  • agent：负责命令安全分级与执行策略。

核心组件 ​

  • 输入框与划词浮层：提供基础文本输入、选中上下文注入、浮动快捷菜单。
  • 提示词管理器：提示词模板库、搜索合并视图、变量替换与上下文注入、发送链路。
  • “+”二级菜单面板：分类数据加载、搜索过滤、多选/单选、动态管理入口。
  • 交互门控：确认/澄清弹窗单模态排队、呈现回执、超时计时起点控制。
  • 输入历史：去重、容量限制、持久化。
  • 页面输入工具：键盘事件模拟、富文本编辑器写入、结果反馈。
  • 命令安全：Agent 端命令替换特征检测与白名单纠偏。

详细组件分析 ​

输入框与划词浮层 ​

  • 功能要点
    • 基础文本输入与自动高度调整。
    • 基于选中文本的浮动菜单，展示已启用“在菜单中显示”的提示词项。
    • 点击浮层项后，将选中内容作为上下文注入，再发送提示词。
  • 关键流程
    • 计算浮层位置，避免溢出视口。
    • 过滤出 enabledInMenu=true 的提示词，渲染为可点击项。
    • 点击后隐藏浮层、压缩上下文、追加气泡、记录历史并发送。

提示词管理系统 ​

  • 功能要点
    • 提示词模板库：编码+内容，拖拽排序，管理按钮。
    • 下拉选择器：Tab 模式（提示词/技能/MCP）与合并搜索模式。
    • 变量替换与上下文注入：技能、MCP、知识库、网页、文件、引用/选中内容。
    • 发送链路：半自动压缩、消息构建、历史保存、输入历史追加。
  • 关键实现
    • showPromptSelector/hidePromptSelector 控制下拉可见性。
    • renderMergedList 聚合搜索，统一导航与选择行为。
    • insertPromptToInputByCode 支持 skipTriggerStrip，用于菜单面板 Ctrl+点击场景。
    • sendPromptByCode 组装上下文、构建 userContent、调用 callApi。

菜单面板系统（“+”二级面板） ​

  • 功能要点
    • 分类：提示词、技能、MCP、网页、知识库、助手、代理、工作目录、截图动作。
    • 搜索过滤：按类别字段进行本地即时过滤；截图类隐藏搜索框。
    • 管理入口：不同类别对应不同管理动作（提示词管理、设置页、新建/编辑、工作目录面板等）。
    • 选择行为：普通点击与 Ctrl/Cmd+点击语义区分；多选类别保持展开。
  • 关键实现
    • openCategoryPanel/closeCategoryPanel 控制面板生命周期与数据加载。
    • fetchCategoryData 根据类别拉取数据；workspace 仅加载根一层。
    • filterDataset/renderList 处理搜索与渲染；handleItemClick 分发选择动作。

交互门控机制（意图识别、预筛选、安全检查） ​

  • 用户意图识别
    • 通过提示词/技能/MCP/知识库/网页/工作目录等上下文组合表达意图。
    • 合并搜索模式下，提示词、技能、MCP 统一检索，便于快速定位目标。
  • 工具预筛选
    • 调用主力模型前使用轻量 API 预筛选工具集合，减少后续开销。
  • 安全检查
    • Agent 端对命令替换特征进行白名单纠偏，避免误报导致绝对禁止。
    • 敏感操作需用户确认，确认倒计时仅在交互真正呈现后启动。

输入历史记录 ​

  • 功能要点
    • 去重：相同文本只保留最新一条。
    • 容量限制：最多 20 条，超出移除最旧条目。
    • 持久化：保存到 chrome.storage.local。
  • 使用场景
    • 提示词发送后、划词问答发送后，将提示词正文加入历史，便于快速复用。

页面输入与富文本支持 ​

  • 功能要点
    • 键盘事件模拟：focus → keydown → keypress → input → keyup → blur，兼容 React/Vue 受控组件。
    • 富文本编辑器：contenteditable 元素通过 execCommand 或 dispatch InputEvent 写入。
    • 结果反馈：成功时返回包含变化提示的消息。
  • 测试覆盖
    • checkbox 拒绝文本输入、value 为空报错、contenteditable 走富文本路径。

    • chrome.runtime.sendMessage 用于跨进程通信。
    • chrome.storage.local 用于持久化输入历史。
    • Agent 端 security.js 提供命令安全策略。

故障排查指南 ​

  • 确认弹窗无法拒绝
    • 现象：未弹出确认即被判拒。
    • 原因：确认与澄清弹窗同层级且澄清遮挡确认，导致用户不可见。
    • 解决：使用交互门控排队，仅在真正呈现后上报 INTERACTION_DISPLAYED，后台据此启动超时。
  • 命令被误报为危险
    • 现象：只读/打印类命令被绝对禁止。
    • 原因：命令替换特征黑名单过于严格。
    • 解决：Agent 端采用白名单纠偏，仅对可疑子段送检，避免整串一票否决。
  • 表单输入无效
    • 现象：React/Vue 受控组件 value 不变。
    • 原因：直接赋值未触发 onChange。
    • 解决：使用键盘事件模拟完整事件链，或富文本路径写入。

结论 ​

输入交互系统以侧边栏为核心，围绕提示词管理、二级菜单面板、交互门控、输入历史与页面输入工具形成闭环。通过 Token 预算驱动压缩、上下文注入与 Agent 安全策略，系统在易用性与安全性之间取得平衡。建议在实际扩展中遵循现有接口契约，优先复用提示词与菜单面板能力，并在新增输入组件时对齐快捷键、无障碍与移动端适配规范。
