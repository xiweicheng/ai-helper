引言 ​

本文件面向"工具调度与执行系统"，覆盖扩展端（Chrome MV3 background）与 Agent 端（Node.js 本地代理）之间的工具发现、注册、预筛选、路由、执行、权限控制、互斥锁、并行优化、生命周期管理、错误处理与审计日志。文档以版本 2.3.1 为基准，强调两端通信契约、SW 生命周期约束、Agent 进程重启后接口生效等运行时前提。

最新更新：增强了工具预筛选系统的 JSON 信封错误处理能力，防止 AI 模型返回的畸形内部协议数据泄露到用户界面。

项目结构 ​

系统由两部分组成：

  • 扩展端 background：负责 ReAct 循环、工具定义聚合、MCP/RAG 动态注册、工具预筛选、执行路由、确认与澄清交互、定时任务编排。
  • Agent 端 server：提供 HTTP + WebSocket 服务，承载命令执行、文件操作、搜索、RAG、MCP 工具注册与调用、Skill 注册与执行、安全沙箱与审计。

核心组件 ​

  • 工具定义与执行器：集中维护 RAW_TOOLS、BUILTIN_TOOLS、TOOL_EXECUTION_MAP、PARALLELIZABLE_TOOLS、CONFIRMATION_REQUIRED_TOOLS，并实现 MCP/RAG 工具的动态注入与清理。
  • 工具预筛选：在工具数量超过阈值时，通过一次轻量 LLM 调用判断是否需要工具及具体工具集合，支持直接回答模式。新增：增强的 JSON 信封错误处理和内部协议数据防护。
  • ReAct 推理循环：统一协调消息流、工具调用、子任务规划、并行执行、超时与中断、完成度校验与反思。
  • 定时任务调度：基于 chrome.alarms 的 cron/间隔/一次性任务，复用会话、选择模型与工具集、网页上下文注入。
  • Agent 服务端：HTTP 路由、CORS 白名单、认证鉴权、命令执行、文件上传、状态与健康检查。
  • 命令执行器：跨平台 shell 选择、输出缓冲限制、WebSocket 流式输出、超时预算与延长策略、进程组终止。
  • MCP/Skill 注册表：启动连接 MCP Server、扁平化工具列表、按服务启用状态过滤；Skill 扫描、加载、启用状态持久化。
  • 安全模块：路径规范化、硬阻止目录、白名单前缀匹配、符号链接 realpath 校验、工作目录放行。
  • 审计与统计：内存权威态、防抖落盘、关键审计即时刷、工具使用统计聚合。

详细组件分析 ​

工具定义与注册机制 ​

  • 内置工具：常量文件中聚合浏览器、标签页、存储、媒体、AI、Agent、记忆、调试等工具，派生 BUILTIN_TOOLS、分类映射、执行位置映射、可并行集合、需确认集合。
  • MCP 工具：扩展端通过 loadMcpTools 拉取 Agent 端已连接 MCP Server 的工具列表，压缩 schema，去重注入 RAW_TOOLS/BUILTIN_TOOLS，重建 BG_HANDLERS，并暴露 mcpToolIds 与 mcpToolMetaMap 用于服务级开关与强制下发。
  • RAG 工具：知识库检索与导入工具在 tool-executor 中动态注册，包含停用库提示、参数校验、禁用库消息生成。
  • 生命周期：loadMcpTools/unloadMcpTools 使用互斥锁防止并发；rebuildBgHandlers 同步更新 PARALLELIZABLE_TOOLS 与 CONFIRMATION_REQUIRED_TOOLS。

参数验证与执行路由 ​

  • 参数解析：工具参数在 react-loop 侧进行防御性解析（string/object），tool-helpers 提供 tryParseToolArgs。
  • 路由分发：根据 TOOL_EXECUTION_MAP 决定 background 或 agent 执行；background 工具走 BG_HANDLERS，agent 工具经 local-agent-client 转发。
  • 确认与澄清：requiresConfirmation 工具进入确认流程；plan_task 触发子任务规划，必要时暂停本轮其他工具调用。
  • 网络访问控制：内网地址访问受 networkAccessEnabled 与 allowedNetworkHosts 控制，拒绝未授权主机。

工具预筛选算法与 JSON 信封容错处理 ​

  • 触发条件：当工具总数超过 PRESELECT_MIN_TOOL_COUNT（默认 10）时启用。
  • 输入：messages、model、tools、apiParams、callCount、mustKeepToolIds。
  • 过程：
    • 提取最后一条 user 消息作为问题，截取最近 4 条 user/assistant 历史。
    • 构建系统提示词，列出工具名、前 3 个参数名与描述。
    • 调用 LLM 返回 JSON {type:"answer"/"tools", data:...}。
    • 新增：JSON 信封解析与容错处理：
      • 优先尝试标准 JSON.parse 解析新格式
      • 解析失败时尝试 recoverAnswerEnvelopeData 容错恢复 answer 信封
      • 检测 looksLikePreselectEnvelope 识别畸形内部协议信封
      • 对畸形信封进行安全防护，不向用户暴露内部协议数据
    • 若 type=answer，直接返回答案；若 tools 为空则回退全部工具。
    • 大小写不敏感匹配工具名，追加原型工具（proto_）与强制保留工具（/ 指定 MCP 服务）。
  • 异常处理：API 失败、JSON 解析失败均回退全部工具，记录 executionLog。

更新 新增了三层 JSON 信封错误处理机制：

并行执行优化与互斥锁 ​

  • 并行工具集合：PARALLELIZABLE_TOOLS 由 RAW_TOOLS 自动派生，MCP 工具默认 parallelizable=true。
  • 互斥锁：MCP/RAG 工具加载使用 Promise 互斥锁，防止 load/unload 并发；rebuildBgHandlers 确保集合一致性。
  • 并发控制：ReAct 循环对 plan_task 的子任务支持 sequential/parallel/dependency 策略，配合 loop-detector 检测重复无效操作、振荡、无进展滚动等。

工具生命周期管理 ​

  • 启动阶段：
    • 扩展端：constants 聚合内置工具；tool-executor 初始化 MCP/RAG 动态注册。
    • Agent 端：server 启动 HTTP/WS，初始化 MCP/Skill 注册表，检测 RAG 可用性。
  • 运行阶段：
    • MCP 工具按需拉取，按服务器启用状态过滤；RAG 工具随知识库启用状态变化。
    • Skill 注册表扫描文件系统与内置技能，恢复启用状态。
  • 关闭阶段：
    • MCP 注册表断开所有连接；Skill 注册表停止周期任务；Activity Store 尽力刷盘。

错误处理与审计日志 ​

  • 错误处理：
    • 预筛选 API 失败回退全部工具；MCP 拉取失败记录警告；命令执行超时/退出码错误上报。
    • 新增：畸形 JSON 信封防护：检测到 {type,data} 格式的畸形信封时，不会将内部协议数据透传给用户界面，而是记录警告并回退到全量工具模式。
    • ReAct 循环检测无限循环、重复无效操作、振荡、无进展滚动，暂停任务并提示补充指导。
  • 审计日志：
    • appendAuditLog 追加敏感操作审计，关键操作即时落盘，普通操作防抖合并。
    • recordToolStats 累加工具调用次数、成功次数、总时长、最近使用时间。

性能与并发 ​

  • 预筛选阈值固定为 10，避免小工具集不必要的 LLM 调用。
  • MCP/RAG 工具加载使用互斥锁，防止并发导致集合不一致。
  • 命令执行采用流式输出与输出缓冲上限（5MB），防止内存无限增长。
  • 超时策略：Agent 端 decideTimeoutAction 根据期内输出决定是否延长，最多延长 5 次，总预算封顶 600s。
  • Activity Store 防抖合并落盘，关键审计即时刷，减少 storage.local 频繁写开销。
  • 新增：JSON 信封解析的性能考虑：容错恢复函数使用正则表达式进行边界定位，避免复杂的字符串处理影响性能。

故障排查指南 ​

  • 定时任务不执行：
    • 检查 chrome.alarms 是否重建（rehydrateAlarms），任务是否 enabled，cron/interval 是否合法。
    • 参考 src/background/scheduler.js#L70-L124。
  • 工具预筛选失效：
    • 检查工具数量是否超过阈值，LLM API 是否可用，JSON 解析是否成功。
    • 新增：检查畸形 JSON 信封：如果看到"预筛选返回的 JSON 格式非法且无法恢复"错误，说明 AI 模型返回了不符合预期的内部协议数据，系统已自动防护并回退到全量工具模式。
    • 参考 src/background/tool-preselector.js#L273-L432。
  • MCP 工具未加载：
    • 检查全局 MCP 开关、Agent 连通性、服务器启用状态、schema 压缩是否截断过多参数。
    • 参考 src/background/tool-executor.js#L551-L651、agent/src/mcp/registry.js#L26-L108。
  • 命令执行超时：
    • 检查 decideTimeoutAction 策略、输出是否在期内产生、是否达到最大延长次数。
    • 参考 agent/src/executor.js#L165-L186。
  • 审计日志丢失：
    • 检查是否关键审计（cookie_write/page_data_clear/file_delete/command_exec 拒绝/取消），否则可能因防抖延迟可见。
    • 参考 src/background/activity-store.js#L46-L123。

结论 ​

本系统通过扩展端与 Agent 端的清晰分工，实现了工具定义的集中管理、动态发现与注册、语义预筛选、安全路由与执行、并行优化与互斥保护、完整生命周期管理与审计追踪。最新版本增强了 JSON 信封的错误处理能力，有效防止了 AI 模型返回的内部协议数据泄露到用户界面，提升了系统的安全性和健壮性。建议在开发新工具时遵循现有分类、执行位置、确认标记与 schema 压缩规范，并在 Agent 端实现安全校验与流式输出，以确保系统稳定性与可观测性。

附录：工具开发与最佳实践 ​

  • 工具定义：
    • 在 tools/ 目录下新增工具文件，导出工具数组，并在 constants.js 中聚合。
    • 明确 category、execution、parallelizable、requiresConfirmation、confirmationActions。
  • 参数验证：
    • 在工具 handler 中进行参数必填校验，返回结构化错误信息。
    • 使用 i18n 文案，避免硬编码中文。
  • 安全校验：
    • Agent 端工具涉及文件/命令时，必须调用 security.checkPath/checkCommand。
    • 内网访问需通过 decideNetworkAccess 白名单校验。
  • 并发与超时：
    • 可并行工具标记 parallelizable=true，避免阻塞主循环。
    • 长耗时工具应实现流式输出与超时控制，遵循 decideTimeoutAction 策略。
  • 审计与统计：
    • 敏感操作调用 appendAuditLog，关键操作即时落盘。
    • 所有工具执行调用 recordToolStats 记录使用统计。
  • 测试建议：
    • 扩展端使用 vitest 单测，Agent 端使用 node --test 限定 test/unit 目录。
    • 修改后统一执行 npm run build:silent 验证构建。
  • 新增：JSON 信封处理最佳实践：
    • 确保 AI 模型返回符合预期的 {type,data} 格式信封。
    • 如果出现畸形信封，系统会自动防护并记录警告，无需手动干预。
    • 在调试时关注 executionLog 中的 reasonMalformedEnvelope 错误信息。
