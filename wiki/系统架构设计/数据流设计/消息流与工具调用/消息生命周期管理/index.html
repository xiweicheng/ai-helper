引言 ​

本文围绕“从用户输入到最终响应”的完整消息生命周期，系统性梳理扩展端（Chrome 侧边栏/Service Worker）与本地 Agent 之间的协作机制。重点覆盖：消息创建、路由分发、ReAct 推理循环、状态跟踪、持久化、会话上下文压缩、去重与缓存、优先级调度、队列管理、消息格式与版本兼容、统计与调试、以及安全与隐私保护。

项目结构 ​

本项目采用双进程架构：

  • Chrome 扩展端（Manifest V3 Service Worker + Side Panel）：负责 UI、消息编排、流式渲染、会话与 Token 预算、任务恢复、与 Agent 通信。
  • 独立本地 Agent（Node.js）：提供文件读写、命令执行、长期记忆与 RAG、MCP 工具注册等能力。

核心组件 ​

  • 消息入口与路由：Side Panel 发起 CALL_API，Background 接收并进入 ReAct 循环；支持 RESUME_REACT 恢复中断任务。
  • ReAct 推理循环：工具选择、调用、结果聚合、反思评估、循环检测、超时控制、子任务拆分与并行策略。
  • 流式输出：SSE 流式分片、思考过程可视化、工具卡片、滚动与交互控制。
  • 会话与持久化：会话 CRUD、归档、分叉、滚动位置、上下文压缩记录、生成态标记。
  • Token 预算与上下文压缩：模型上下文窗口推断、消息预算分配、历史裁剪、引用内容压缩、自动压缩决策。
  • Agent 客户端：配对认证、HTTP/WebSocket 封装、可达性缓存、多代理切换、敏感操作分级。

详细组件分析 ​

消息创建与路由分发 ​

  • Side Panel 在发送前进行上下文组装：系统提示词、工具定义、历史消息选择、知识库检索注入、引用/选中内容压缩。
  • Background 接收后进入 reactLoop，维护 activeReactLoops 以检测 SW 重启；通过 keepalive port 定向下发确认弹窗与状态更新。
  • 支持 RESUME_REACT：从 IndexedDB 恢复 checkpoint，清理不完整 tool_calls/tool 配对，注入恢复提示，继续执行。

状态跟踪与持久化存储 ​

  • Checkpoint：按 sessionId 保存 currentMessages、iteration、taskState、subtaskPlan、subtaskProgress、notesState 等，失败时自动续跑。
  • 会话存储：会话列表、活跃会话、消息历史、上下文压缩记录、滚动位置、生成态标记；删除会话时同步清理 checkpoint 与收藏。
  • 恢复流程：页面加载或用户点击“继续执行”，复用 callApi 基础设施，传入 resumeFromCheckpoint=true，走相同流式渲染路径。

会话状态管理与上下文压缩 ​

  • 会话级上下文压缩记录（activeCompaction）包含摘要、压缩范围、节省 token、模型、时间戳与 revision。
  • 自动压缩：基于使用率阈值（默认 85%）、最小待处理消息数、是否正在生成、是否启用隔离聊天等条件触发。
  • 压缩时机：发送前尝试自动压缩；手动压缩可撤销（若未发送新消息）。
  • 压缩效果：将旧轮次替换为结构化摘要，保留关键信息，降低后续请求上下文占用。

消息去重、重复请求检测与缓存 ​

  • 工具结果缓存：单次 ReAct 循环内缓存工具结果，TTL 60s，上限 30 条，避免重复工具调用。
  • 确认弹窗去重：Side Panel 对可见/排队中的确认项做同请求去重，防止 port 与广播重复投递导致吞掉后续请求。
  • 关联键唯一：后台为每次确认生成唯一关联键，即使模型复用 tool_call.id 也能区分不同命令。
  • MCP 工具查询缓存：Background 缓存 MCP 工具列表，减少网络请求。

优先级调度、队列管理与资源分配 ​

  • 子任务拆分与策略：plan_task 可将复杂任务拆分为多个子任务，支持顺序/并行/依赖策略；同一轮中 plan_task 后其他工具调用被跳过。
  • 循环检测：多模式检测器识别重复无效操作、枚举循环、振荡、无进展滚动、预算耗尽等，达到阈值暂停任务并提示补充指导。
  • 超时控制：ReAct 循环总超时、工具执行超时、流式空闲超时；子任务继承父任务剩余时间预算。
  • 资源分配：执行日志内存窗口限制（1000 条），仅保留终态条目，避免长任务内存失控。

依赖关系分析 ​

  • Background 依赖 Shared Token Counter 进行预算与裁剪；依赖 Stream Controller 管理 SSE 空闲超时；依赖 Local Agent Client 访问 Agent HTTP/WebSocket。

  • Agent 客户端维护可达性缓存，已知不可达时快速失败，避免阻塞等待超时。

性能与内存优化 ​

  • Token 估算校准：基于实际 prompt_tokens 与估算值对比，EWMA 平滑因子动态调整，提升估算准确性。
  • 图片 Token 估算：按分辨率 tile 公式计算，避免 Base64 字符串高估约 20 倍。
  • 历史裁剪优化：一次性预计算每条消息贡献值，增量扣减，替代 O(n²) 全量重估。
  • 执行日志内存窗口：仅保留最近 1000 条终态条目，释放进行中条目之外的旧数据，防止 SW 内存泄漏。
  • 流式滚动优化：requestAnimationFrame 补滚，避免内容高度变化导致的底部遮挡。

故障诊断与监控 ​

  • SW 保活与自动续跑：keepalive port 维持 SW 存活；SW 重启检测并通过闹钟唤醒后扫描 checkpoint 自动续跑，耗尽次数后通知人工介入。
  • 面板断开延迟复核：端口断开后延迟判断，避免误判“仍在执行”；结合 activeReactLoops 与 isCancelled 综合判定。
  • 流式空闲超时：SSE 空闲超时自动中断，提示网络或服务提供商不稳定。
  • 调试信息：checkpoint 列表诊断、IndexedDB 自检、日志截断保留 subtask_plan 条目，便于历史视图还原计划。

安全与隐私 ​

  • Agent 配对与认证：所有需认证请求携带 Bearer Token；配对码认证成功后存储加密 token，支持多代理切换。
  • 敏感操作确认：工具执行前弹出确认对话框，5 分钟超时默认拒绝；支持“当前任务放行”批量授权，但会清理以避免跨任务泄露。
  • 文件沙箱与命令分级：Agent 端安全模块对文件操作与命令执行进行分级管控；黑名单拦截、灰名单确认。
  • 数据脱敏：消息过滤移除 internal 字段，清洗非法 Unicode；图片 content 剥离 Base64，仅保留必要元数据。

结论 ​

本方案通过 Side Panel 与 Background 的紧密协作，结合 Agent 端的强大能力，实现了从用户输入到最终响应的完整消息生命周期管理。系统在状态跟踪、持久化、上下文压缩、去重与缓存、优先级调度、流式渲染等方面提供了完善的实现，同时兼顾性能优化与安全隐私保护。未来可进一步扩展监控指标采集、自动化故障自愈与更细粒度的权限控制。
