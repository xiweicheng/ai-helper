引言 ​

本文件面向扩展端（Chrome 扩展，Manifest V3）与 Agent 端（独立 Node.js 进程）之间的通信契约。当前稳定版本为 2.3.1，两端版本号保持同步。扩展端通过本地 HTTP REST API 和 WebSocket 双通道调用 Agent 的文件系统、命令执行、长期记忆、RAG、Skill 与 MCP 工具能力；Agent 源码修改后必须重启进程，新接口才生效。

项目结构与通信边界 ​

  • 扩展端：src/background/local-agent-client.js 封装所有 HTTP/WebSocket 请求，负责配对、Token 管理、可达性缓存、超时控制、MCP/Skill/RAG 客户端封装。
  • Agent 端：agent/src/server.js 提供 HTTP Router 与 WebSocket Server，统一鉴权、安全校验、日志、国际化、MCP 注册表、Skill 注册表、RAG 路由转发。
  • 安全层：agent/src/security.js 提供路径白名单、硬阻止目录、命令黑白名单与分级管控。
  • 认证层：agent/src/auth.js 实现配对码轮换、一次性配对、Token 验证与活跃窗口。
  • 执行层：agent/src/executor.js 负责命令子进程、超时策略、WebSocket 广播与完成回放。
  • MCP 层：agent/src/mcp/client.js 与 agent/src/mcp/registry.js 管理多传输 MCP Client 实例、工具发现与调用。

核心组件与职责 ​

  • 扩展端客户端：维护已配对代理列表、活跃代理 ID、可达性缓存；统一发送带 Bearer Token 的请求；封装文件、命令、MCP、Skill、RAG、审计日志、回收站等 API。
  • Agent 服务端：解析请求、按路径分发到文件系统、命令、MCP、Skill、RAG、Memory、配置管理等子系统；统一 JSON 响应格式；支持 CORS 仅放行 Chrome 扩展来源。
  • 认证模块：生成 6 位配对码，支持失败锁定与成功后立即轮换；持久化 extensionId → token 映射；verifyToken 更新 lastAuthTime。
  • 安全模块：路径规范化、硬阻止目录、realpath 防符号链接绕过、allowedPaths 前缀校验；命令分级 deny/confirm/allow。
  • 执行模块：spawn shell 子进程，stdout/stderr 流式广播，超时受管模式与旧语义兼容，完成结果回放给延迟连接的 WebSocket 客户端。
  • MCP 模块：支持 stdio、SSE、Streamable HTTP、WebSocket 四种传输；自动 listTools；合并多服务器工具并注入扩展端工具列表。

架构总览 ​

扩展端通过 local-agent-client.js 发起请求；Agent 端由 server.js 统一鉴权与安全校验后分发给具体业务模块。命令执行使用 HTTP 返回 execId 与 wsUrl，随后通过 WebSocket 实时推送 stdout/stderr/exit/error。MCP 工具在 Agent 端自动发现，扩展端按需拉取并动态注册为 AI 工具。

详细协议规范 ​

通用响应结构 ​

所有 HTTP 响应统一为 JSON，包含以下字段：

  • success: boolean，表示业务是否成功。
  • error: string，失败时的用户可读错误信息（国际化）。
  • httpStatus: number，扩展端附加的 HTTP 状态码，用于区分“Agent 离线”与“资源不存在”。
  • 其他业务字段：如 version、platform、execId、content、tools、servers 等。

示例（健康检查）：

  • 请求：GET /api/status
  • 响应：{ success: true, version: "2.3.1", running: true, platform: "...", ... }

示例（需认证的状态详情）：

  • 请求：GET /api/status/detail，Header：Authorization: Bearer <token>
  • 响应：{ success: true, pairCodeTTL, workdir, allowedPaths, commandTimeout, fileMaxSize, uploadMaxSize, resourceUsage, ... }

文件操作 API ​

  • /api/fs/read：读取文件，返回 content、size、path。
  • /api/fs/write：写入文件，支持 utf-8 与 base64。
  • /api/fs/list：列出目录条目。
  • /api/fs/stat：获取文件详细信息。
  • /api/fs/delete：移至回收站。
  • /api/fs/download：单文件或目录打包 zip，返回 base64。
  • /api/fs/download-stream：二进制流下载，避免 base64 膨胀。
  • /api/files/upload：multipart/form-data 上传。
  • /api/fs/upload-stream：raw binary 流式上传。

路径安全：所有路径先经 checkPath，命中硬阻止或不在 allowedPaths 则返回 403。

命令执行与 WebSocket 流式输出 ​

命令执行采用 HTTP + WebSocket 双通道：

  • HTTP 返回 execId 与 wsUrl。
  • WebSocket URL 为 ws://{host}:{port}/ws/exec/{execId}，认证通过 Authorization Header 或 query ?token=。
  • 服务端每 30 秒 ping 检测半开连接，两拍无 pong 则 terminate。
  • 执行器广播 stdout/stderr/exit/error，支持完成回放。

性能、连接管理与重连策略 ​

  • 请求超时：agentRequest 默认 60s，agentGet 默认 30s；文件上传 60s；下载 120s；RAG 搜索 180s；RAG 导入 600s。
  • 可达性缓存：按 agentId 缓存 null/true/false，已知不可达直接返回错误，避免阻塞等待超时。
  • WebSocket 心跳：服务端每 30 秒 ping，无 pong 则 terminate；客户端空闲超时由调用方统一管理，避免双重超时冲突。
  • 命令超时：支持受管模式（timeoutMs 协商）与旧语义（commandTimeout），期内有输出可延长，静默即杀。
  • 优雅关闭：shutdown 终止进程、关闭 MCP、断开 WebSocket、销毁活跃 socket，10s 强制退出。

错误处理与状态码约定 ​

  • 400：请求参数无效、JSON 解析失败、文件大小超限、路径缺失。
  • 401：缺少 Authorization Header。
  • 403：Token 无效、路径被拒绝、命令 deny、CORS 来源不被允许。
  • 404：API 路径不存在、文件/目录不存在。
  • 409：操作进行中、目标已存在。
  • 429：操作过于频繁（冷却期）。
  • 500：内部异常、RAG 路由加载失败、下载失败。
  • 503：RAG 依赖不可用。

扩展端附加 httpStatus 字段，便于区分“Agent 离线/网络错误”与“业务 404”。

故障排查清单 ​

  • 无法连接 Agent：检查 /api/status 是否可达，确认扩展来源是否为 chrome-extension://。
  • 认证失败：确认 /api/pair 成功后 token 已保存，后续请求携带 Authorization: Bearer <token>。
  • 文件操作 403：检查路径是否在 allowedPaths 内，是否命中硬阻止目录。
  • 命令执行被拒绝：查看 checkCommand 返回 level，deny 不可绕过，confirm 可 force。
  • WebSocket 断连：检查服务端心跳是否正常，客户端是否长时间无输出导致超时。
  • MCP 工具未显示：确认 MCP Server 已连接且 enabled，扩展端已调用 /api/mcp/tools。
  • RAG 不可用：调用 /api/rag/detect 探测依赖，必要时安装依赖并重启 Agent。
