简介 ​

本文面向 Agent 端的本地 HTTP/WebSocket 服务，基于 Node.js 原生 http 模块和 ws 库实现。该服务是 Chrome 扩展与本机能力之间的桥梁：扩展通过本地端口调用 Agent 的文件读写、命令执行、长期记忆、RAG、MCP 工具、技能系统等功能；Agent 负责安全校验、路径沙箱、命令分级、进程管理、流式输出、配置持久化以及优雅关闭。

关键约束：

  • 双进程架构：Chrome 扩展端（Manifest V3）与独立本地 Agent 进程（Node.js）。
  • 修改 Agent 源码后必须重启进程，新接口才生效。
  • 默认监听 127.0.0.1:18910，仅本机可访问；若绑定到 0.0.0.0，远程请求仍需认证。
  • 所有业务接口统一返回 { success, ... } JSON 结构，错误信息使用 i18n 文案。

项目结构 ​

Agent 的 HTTP/WebSocket 入口位于 agent/src/server.js，它同时承担以下职责：

  • 启动 Node.js HTTP 服务器并注册路由。
  • 解析请求体、处理 CORS、国际化语言切换。
  • 执行认证、配对、工作目录切换、文件操作、命令执行、Skill/MCP/RAG/Memory 路由分发。
  • 创建 WebSocket 升级处理器，用于命令执行结果流式推送。
  • 管理进程生命周期、优雅关闭、信号处理和全局异常捕获。

详细组件分析 ​

HTTP 路由与中间件管道 ​

HTTP 服务器在 startServer 中创建，并通过 handleRequest 实现统一的请求处理流程：

  1. 初始化 i18n，将当前请求语言同步到 config、auth、security、executor、memory、rag、skill、mcp 等模块。
  2. 处理 CORS 预检请求，仅放行 chrome-extension:// 来源。
  3. 解析 URL，每次请求重新加载配置，确保 workdir 切换后立即生效。
  4. 先处理无需认证的接口：/api/pair、/api/status、/api/shutdown。
  5. 再处理需认证的接口：/api/heartbeat、/api/agent/restart、/api/agent/update、文件接口、命令接口、Skill、MCP、RAG、Memory。
  6. 未匹配的路径返回 404。

认证与配对机制 ​

认证模块维护以下状态：

  • 当前配对码：定时刷新，插件在线时停止刷新，离线超时后恢复刷新。
  • 最近认证时间：用于判断扩展是否仍在线。
  • 配对失败计数：连续失败达到阈值后临时锁定，并立即轮换配对码。
  • 配对记录：存储扩展 ID 与 token，落盘前对 token 加密。

路径与命令安全模型 ​

安全模块提供两层保护：

  1. 路径沙箱：通过 checkPath 校验目标路径是否在 allowedPaths 或 workdir 内，防止符号链接绕过，拦截硬阻止目录。
  2. 命令分级：通过 checkCommand 对命令进行黑名单（deny）、灰名单（confirm）、允许（allow）分类，支持链式命令拆分、解释器内联载荷、命令替换检测。

命令执行与 WebSocket 流式输出 ​

命令执行器负责：

  • 选择合适 shell（cmd/powershell/bash/zsh/fish/sh）。
  • 创建子进程，隔离环境变量，限制输出缓冲区上限。
  • 支持同步等待模式和异步 WebSocket 流式输出。
  • 管理超时策略：旧模式到期直接杀，受管模式根据输出情况决定是否延长。
  • 多客户端广播：同一 execId 可被多个 WebSocket 客户端订阅。
  • 进程终止：Windows 用 taskkill，Unix 用进程组 SIGTERM/SIGKILL。

WebSocket 握手与连接管理 ​

WebSocket 升级由 server.on('upgrade') 处理，仅允许 /ws/exec/{execId} 路径：

  1. 解析 URL，提取 execId。
  2. 同步语言到 executor、security、config 模块。
  3. 认证：优先使用 Authorization: Bearer，回退到 ?token= query。
  4. 验证失败直接返回 403。
  5. 验证通过后，将 WebSocket 客户端加入进程的 wsClients 集合。
  6. 启动心跳：每 30 秒 ping，未 pong 则 terminate。
  7. 客户端断开时移除连接，并在无客户端且非受管模式下取消超时。

配置选项与服务发现 ​

配置模块提供默认值与持久化：

  • 默认端口：18910
  • 默认 host：127.0.0.1
  • workdir：用户工作目录
  • allowedPaths：允许访问的目录列表
  • pairCodeTTL：配对码过期时间
  • commandTimeout：命令默认超时
  • fileMaxSize：文件读取大小限制
  • memoryEmbedding：长期记忆语义召回配置

健康检查接口 /api/status 返回版本、运行状态、平台信息、搜索工具可用性、RAG 可用性。

反向代理与 SSL/TLS 支持 ​

当前实现直接使用 Node.js 原生 http 模块，未内置 SSL/TLS 支持。推荐部署方式：

  • 使用 Nginx、Apache、Caddy 等反向代理提供 HTTPS。
  • 反向代理转发到 127.0.0.1:18910。
  • 注意 CORS 策略：仅放行 chrome-extension:// 来源，普通网页无法跨域读取响应。
  • 若暴露到公网，务必通过防火墙或反向代理限制来源 IP。

服务健康检查、优雅关闭与资源清理 ​

健康检查：

  • /api/status：无认证，返回基础平台信息。
  • /api/status/detail：需认证，返回内存、CPU、运行进程、RAG 状态等详细信息。
  • /api/heartbeat：需认证，刷新 lastAuthTime。

优雅关闭：

  • 监听 SIGINT、SIGTERM。
  • 停止配对码轮换、回收站清理、RAG 安装。
  • 终止所有运行中的命令进程。
  • 关闭 MCP 连接。
  • 强制断开所有 WebSocket 客户端。
  • 销毁活跃 HTTP socket。
  • 10 秒超时兜底，防止 server.close() 挂起。

资源清理：

  • PID 文件删除。
  • 全局 uncaughtException、unhandledRejection 捕获，记录日志但不退出进程。

性能与并发特性 ​

  • 请求体大小限制：JSON body 最大 200MB，multipart/form-data 同样限制。
  • 流式上传：/api/fs/upload-stream 使用 createWriteStream，避免 base64 膨胀。
  • 流式下载：/api/fs/download-stream 使用 createReadStream，分块 64KB 写出，避免 OOM。
  • ZIP 打包：使用 archiver，压缩级别 9，临时文件写入 tmpdir，完成后删除。
  • 命令输出缓冲：stdout/stderr 最大 5MB，超限标记 truncated 并广播提示。
  • 超时策略：受管模式支持最多 5 次延长，总预算封顶 600 秒。
  • 配置缓存：内存缓存 + mtime 检测，写入加锁防并发覆盖。
  • WebSocket 心跳：30 秒 ping，检测半开连接。
  • 进程树终止：Windows 用 taskkill /T，Unix 用负 PID 进程组信号。

错误码与响应约定 ​

所有接口统一返回 JSON 结构：

  • 成功：{ success: true, ... }
  • 失败：{ success: false, error: "错误文案" }

常见 HTTP 状态码：

  • 200：成功
  • 400：参数错误、JSON 解析失败、文件大小超限
  • 401：缺少 Authorization 或 Bearer Token
  • 403：Token 无效、路径不在白名单、命令被拒绝
  • 404：未知 API 路径
  • 409：操作进行中、目标已存在
  • 429：操作过于频繁
  • 500：内部错误、RAG 路由加载失败
  • 503：RAG 依赖不可用

错误文案来自 i18n，键名如 error.bodyTooLarge、error.invalidToken、security.pathNotInAllowedDir 等。

故障排查指南 ​

现象可能原因排查建议
端口占用已有 Agent 进程检查 .ai-helper-agent/agent.pid，或使用 /api/shutdown 停止
认证失败Token 无效或过期重新配对，检查 pairings.json
路径被拒绝不在 allowedPaths 或 workdir检查 config.json 的 allowedPaths 和 workdir
命令被拒绝命中黑名单或灰名单查看 security.js 的 BLACKLIST_PATTERNS 和 GRAYLIST_PATTERNS
WebSocket 断连浏览器空闲、网络闪断、心跳未 pong检查前端心跳逻辑，确认 /ws/exec/{execId} 连接存活
命令无输出子进程静默失败、输出缓冲截断查看 stderr 和 truncated 提示
RAG 不可用依赖未安装或 Node 版本不兼容调用 /api/rag/install 和 /api/rag/detect
优雅关闭卡住仍有活跃 socket 或子进程检查 activeSockets 和 runningProcesses

结论 ​

Agent 的 HTTP/WebSocket 服务器以 Node.js 原生模块为基础，实现了完整的安全控制、文件操作、命令执行、长期记忆、RAG、MCP 和 Skill 管理能力。其设计强调：

  • 安全优先：路径白名单、硬阻止目录、命令黑白名单、配对码轮换、Token 认证。
  • 可扩展：模块化路由、按需加载 RAG、MCP、Skill。
  • 健壮性：优雅关闭、全局异常捕获、进程树终止、心跳检测。
  • 可观测：审计日志、平台信息、资源使用统计。

对于生产部署，建议通过反向代理提供 HTTPS，严格限制来源 IP，并配合防火墙和监控告警。对于开发者，应遵循 i18n 文案、统一响应格式和安全校验流程，避免绕过 checkPath 和 checkCommand。
