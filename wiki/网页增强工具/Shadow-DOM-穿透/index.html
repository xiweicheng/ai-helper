引言 ​

Shadow DOM 是 Web Components 的核心隔离机制之一。它把组件的内部结构、样式和事件处理封装在一个独立的文档片段中，宿主页面无法直接通过常规 document.querySelector 访问其内部节点。对浏览器扩展、自动化脚本、网页分析工具和智能体交互系统而言，这意味着必须实现“穿透”能力：递归进入 shadowRoot，同时兼容同源 iframe，并在权限受限或跨域场景下安全降级。

本仓库在扩展端 Content Script 层实现了完整的 Shadow DOM 穿透工具集，并在此基础上提供元素查询、文本提取、HTML 快照、选择范围获取、可见性判断、滚动收集以及基于 ref 的元素操作等上层能力。这些能力被多个工具模块复用，支撑了“精准操作任意前端框架页面”的目标。

穿透算法详解 ​

递归遍历 Shadow Root ​

deepQuerySelector 和 deepQuerySelectorAll 是穿透能力的核心。它们的工作方式是：

  1. 如果当前根节点支持 querySelectorAll，则遍历所有子元素。
  2. 对每个有 shadowRoot 的元素，递归进入 Shadow Root 继续搜索。
  3. 对 IFRAME 或 FRAME 元素，尝试读取 contentDocument 或 contentWindow.document，并递归进入同源文档。
  4. 在 Shadow DOM 和 iframe 优先搜索后，再在当前根节点上执行一次选择器匹配。
  5. 最大递归深度默认是 5，防止无限嵌套导致性能问题。
flowchart TD
Start(["开始"]) --> CheckDepth["检查当前深度是否超过最大深度"]
CheckDepth --> |超过| ReturnNull["返回空结果"]
CheckDepth --> |未超过| QueryAll["遍历当前根的所有元素"]
QueryAll --> HasShadow{"元素是否有 shadowRoot"}
HasShadow --> |是| RecurseShadow["递归进入 shadowRoot 搜索"]
RecurseShadow --> FoundShadow{"Shadow 中找到目标"}
FoundShadow --> |是| ReturnFound["返回找到的元素"]
FoundShadow --> |否| NextEl["继续下一个元素"]
HasShadow --> |否| IsIframe{"是否为 IFRAME 或 FRAME"}
IsIframe --> |是| TryIframe["尝试读取 contentDocument"]
TryIframe --> CanAccess{"能否访问文档"}
CanAccess --> |能| RecurseIframe["递归进入 iframe 文档"]
CanAccess --> |不能| SkipIframe["跳过跨域 iframe"]
IsIframe --> |否| NextEl
NextEl --> Continue["继续遍历"]
Continue --> AfterTraversal["遍历完成后在当前根执行选择器"]
AfterTraversal --> HasResult{"当前根找到结果"}
HasResult --> |是| ReturnCurrent["返回当前根结果"]
HasResult --> |否| End(["结束"])

样式隔离处理 ​

Shadow DOM 的样式隔离意味着宿主页面的 CSS 通常不会直接影响组件内部样式，反之亦然。本项目的穿透能力并不直接修改 Shadow DOM 内部样式，而是通过以下方式间接适配样式隔离：

  • 使用 innerText、textContent、innerHTML、outerHTML 读取文本和 HTML。
  • 使用 getBoundingClientRect、checkVisibility、getComputedStyle 判断可见性和布局。
  • 使用 getRootNode 判断元素是否位于 Shadow Root 内。
  • 生成包含 Shadow Host 路径的选择器时，使用自定义前缀标记 Shadow DOM 层级。

这种方式避免了直接注入样式破坏组件内部样式隔离，同时保证外部工具能正确识别元素位置和可见性。

事件冒泡机制 ​

Shadow DOM 的事件模型允许某些事件冒泡到宿主文档，但事件目标仍保持在 Shadow Tree 内部。本项目在以下场景中考虑了事件冒泡：

  • 点击、悬停、键盘输入等操作都会显式派发 bubbles: true 的事件，以便 React、Vue、Angular 等框架的合成事件系统能够捕获。
  • 选择变化监听器通过 attachSelectionListeners 递归挂载到 Shadow Root，确保用户在选择 Shadow DOM 内部文本时也能触发工具栏更新。
  • 表单填充时使用原生 setter 设置值，并派发 input、change 事件，绕过受控组件的状态隔离。

跨域 iframe 与安全边界 ​

Shadow DOM 本身不是跨域问题，但项目中同时处理了 iframe 和 Shadow DOM。对于 iframe：

  • 如果 contentDocument 或 contentWindow.document 可访问，说明是同域或扩展权限允许访问，工具会继续递归遍历。
  • 如果访问抛出异常，代码会捕获并跳过该 iframe，避免中断整个遍历过程。
  • 这种设计符合浏览器的同源策略：跨域文档不可直接读写，只能作为黑盒存在。

对于 Shadow DOM：

  • 只要当前 Content Script 能访问宿主元素，就能读取其 shadowRoot。
  • 如果宿主元素本身不可访问，则无法进入 Shadow Tree。
  • 工具通过 try-catch 包裹可能失败的 DOM 访问，保证局部失败不影响整体遍历。

CheckIframe --> |否| CheckShadow{"是否遇到 shadowRoot"}

AccessOK --> |是| EnterIframe["递归进入 iframe 文档"]
AccessOK --> |否| SkipIframe["记录跨域限制并跳过"]

Web Components 内部内容访问示例 ​

本节给出在实际使用中如何操作组件内部元素、读取组件状态和触发组件方法。为避免泄露具体实现细节，这里以“步骤 + 对应源码位置”的方式说明。

示例一：点击 Shadow DOM 内部的按钮 ​

适用场景：页面外层有一个普通按钮，但真正可用的按钮在某个 Web Component 的 Shadow Root 中。

推荐步骤：

  1. 使用 deepQuerySelector 传入目标选择器。
  2. 如果返回元素为空，说明选择器无法穿透 Shadow DOM。
  3. 调整选择器或使用 query_elements 生成的 ref。
  4. 调用 clickElement 或 interactByRef 执行点击。

示例二：读取 Shadow DOM 内部文本 ​

适用场景：需要判断组件是否显示“订单已确认”之类的状态文本。

推荐步骤：

  1. 使用 deepGetText 获取包含 Shadow DOM 和同源 iframe 的合并文本。
  2. 在业务逻辑中判断目标字符串是否存在。
  3. 如果需要更精确的结构信息，使用 deepGetHtml 获取带注释标记的 HTML。

示例三：填充 Shadow DOM 内部的表单 ​

适用场景：React 受控组件、富文本编辑器、自定义下拉框。

推荐步骤：

  1. 优先使用 query_elements 返回的 ref，避免手写脆弱选择器。
  2. 如果是标准 input/textarea，使用 setNativeValue 设置值并派发 input、change。
  3. 如果是 contenteditable 或富文本编辑器，使用 fillContentEditable。
  4. 如果是自定义下拉，使用 selectDropdown 或先点击触发器再匹配选项。

性能、缓存与内存泄漏防护 ​

遍历优化 ​

  • 最大递归深度默认限制为 5，避免深层嵌套导致栈溢出或长时间遍历。
  • deepQuerySelector 在 Shadow DOM 中优先返回第一个匹配项，减少不必要遍历。
  • deepQuerySelectorAll 使用 Set 去重，避免同一元素被多次加入结果。
  • deepGetText 和 deepGetHtml 使用 visited Set 防止循环引用。

内存泄漏防护 ​

  • attachSelectionListeners 返回已添加监听器的集合，配合 removeSelectionListeners 统一移除。

  • Shadow DOM 选择变化监听器递归挂载，但通过 listeners.has(root) 防止重复挂载。

与现代前端框架的集成实践 ​

React ​

  • React 使用合成事件系统，因此直接调用 element.click() 有时不足以触发受控组件状态更新。
  • 本项目在表单填充和键盘输入中显式派发 input、change、keydown、keyup 等事件，并尽量使用 InputEvent 携带 inputType。
  • 对于受控组件，优先使用 setNativeValue 设置原生值，再派发事件，绕过 React 内部状态隔离。

推荐实践：

  • 优先使用 query_elements 返回的 ref，避免手写选择器。
  • 输入类操作使用 fillForm 或 keyboardInput。
  • 点击类操作使用 clickElement 或 clickByText。

故障排查指南 ​

常见问题一：选择器找不到元素 ​

现象：deepQuerySelector 返回 null。

可能原因：

  • 元素在 Shadow DOM 内部，但选择器没有覆盖 Shadow Host。
  • 元素尚未渲染完成。
  • 元素被隐藏或不在可视区域。
  • 元素在跨域 iframe 中。

排查建议：

  1. 使用 hasShadowDom 判断页面是否包含 Shadow DOM。
  2. 使用 deepGetHtml 查看 Shadow DOM 和 iframe 的 HTML 结构。
  3. 使用 query_elements 获取结构化快照，确认元素是否被识别为可交互元素。
  4. 对 iframe，检查是否同源。

常见问题二：点击无效或状态未更新 ​

现象：点击成功，但 React/Vue/Angular 组件状态未更新。

可能原因：

  • 只调用了 click()，没有派发框架依赖的事件。
  • 使用了 jQuery 或旧式赋值方式，绕过了框架状态。
  • 目标元素是 contenteditable 或富文本编辑器。

排查建议：

  1. 使用 clickElement 或 interactByRef。
  2. 对输入类操作使用 fillForm 或 keyboardInput。
  3. 对富文本编辑器使用 fillContentEditable。

常见问题三：选择区域工具栏不响应 Shadow DOM 选择 ​

现象：用户在 Shadow DOM 内部选中文本，但工具栏没有更新。

可能原因：

  • 选择变化监听器未挂载到 Shadow Root。
  • 监听器被提前移除。
  • 当前文档不是 Shadow Root。

排查建议：

  1. 使用 attachSelectionListeners 递归挂载监听器。
  2. 使用 removeSelectionListeners 清理监听器。
  3. 使用 deepGetSelection 获取 Shadow DOM 内的选择内容。

常见问题四：跨域 iframe 无法读取内容 ​

现象：遍历到 iframe 后停止或报错。

可能原因：

  • iframe 跨域，浏览器阻止访问 contentDocument。
  • 扩展权限未配置或页面策略禁止嵌入。

排查建议：

  1. 接受跨域 iframe 不可访问的限制。
  2. 只对同源 iframe 进行深度遍历。
  3. 如需跨域访问，应通过后端代理或官方 API，而不是绕过浏览器安全策略。

结论 ​

本仓库的 Shadow DOM 穿透能力以 shadow-dom-utils.js 为核心，向上支撑了元素查询、文本提取、HTML 快照、选择区域、可见性判断、滚动收集和 ref 驱动的元素操作。其设计重点包括：

  • 递归遍历 Shadow Root 和同源 iframe。
  • 对跨域和权限受限场景做安全降级。
  • 通过事件派发和原生值设置兼容现代前端框架。
  • 使用 WeakMap、Set、懒生成 selector 等方式控制性能和内存。
  • 将 Shadow DOM 能力抽象为可复用的工具模块，避免各功能模块重复实现。

对于使用者而言，最稳妥的实践是：优先使用 query_elements 返回的 ref，其次使用 deepQuerySelector 和 deepQuerySelectorAll，最后才手写选择器；对受控组件优先使用 fillForm、keyboardInput、clickElement 等高层工具，而不是直接操作 DOM。这样既能穿透 Shadow DOM，又能保持与 React、Vue、Angular 等框架的良好兼容性。
