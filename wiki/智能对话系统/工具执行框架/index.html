引言 ​

本文件面向“工具执行框架”的开发者与维护者，系统性说明：

  • 工具定义与注册机制（内置工具、MCP 动态注入、RAG 知识库工具）。
  • 参数校验与安全过滤（Schema 校验、类型检查、命令白名单）。
  • 并行执行策略（PARALLELIZABLE_TOOLS、子任务并发池、资源上限）。
  • 超时控制（TOOL_TIMEOUT_MS、Agent 端预算延长策略、交互式工具特殊处理、用户中断）。
  • 错误处理与审计（异常捕获、重试、审计日志与统计）。
  • 新工具开发、执行策略配置与性能优化实践。
  • 调试方法与常见问题排查。

本项目为双进程架构：Chrome 扩展端（Manifest V3）+ 独立本地代理端 Agent（Node.js）。两端版本号保持同步，当前以 2.3.1 为准；修改 Agent 源码后需重启进程，接口才会生效。

项目结构 ​

工具执行框架横跨扩展端 background 与 Agent 端两个运行时：

  • 扩展端负责工具定义聚合、动态注册、调度、并发控制、超时与交互、审计记录。
  • Agent 端负责命令执行、MCP 工具发现与调用、Skill 加载与执行、RAG 能力探测。

核心组件 ​

  • 工具定义与聚合：通过常量模块聚合 8 组内置工具，派生 BUILTIN_TOOLS、TOOL_EXECUTION_MAP、PARALLELIZABLE_TOOLS、CONFIRMATION_REQUIRED_TOOLS 等映射。
  • 工具执行器：统一入口，负责 MCP/RAG 动态注册、工具选择、参数解析、执行分发、审计与统计。
  • ReAct 循环：负责多轮推理、工具分组并行、plan_task 子任务调度、工具级超时与用户取消。
  • Agent 命令执行器：跨平台 shell 选择、安全环境变量、流式输出、超时延长策略、进程树终止。
  • MCP 注册表：管理 MCP Server 连接、工具发现、工具调用转发。
  • Skill 系统：Workflow Skill JSON/YAML 加载与校验、Agent Skill SKILL.md 扫描、DAG 拓扑执行与并行。

详细组件分析 ​

工具定义与注册机制 ​

  • 内置工具聚合：constants.js 将 8 个工具组合并为 RAW_TOOLS，并派生 BUILTIN_TOOLS、TOOL_EXECUTION_MAP、PARALLELIZABLE_TOOLS、CONFIRMATION_REQUIRED_TOOLS、BUILTIN_TOOLS_UI 等。
  • 动态注册：
    • MCP 工具：loadMcpTools 从 Agent 拉取工具列表，压缩 schema，注入 RAW_TOOLS/BUILTIN_TOOLS/TOOL_HANDLERS，重建 BG_HANDLERS，并持久化 mcpTools 供 UI 显示。
    • RAG 工具：loadRagTools 检测 Agent 是否支持 RAG，若启用则注入 knowledge_search/ingest/list 三个工具，并同步 ragTools 到 storage。
  • 去重与清理：使用 Set 维护已注册 ID，提供 unloadMcpToolsInternal/unloadRagToolsInternal 清理函数，并通过互斥锁防止并发加载/卸载。

参数验证机制 ​

  • 工具定义层：每个工具的 function.parameters 必须为 object，id 与 function.name 一致，execution 取值合法，由单元测试覆盖。
  • MCP Schema 压缩：compressMcpSchema 移除冗余字段、限制 properties 嵌套深度、截断 description、限制参数数量，避免撑爆上下文。
  • Skill 参数校验：executor.js 兼容 JSON Schema 风格 parameters，校验 required 字段，进行 number/boolean/string 类型转换。
  • 命令安全：Skill 中 agent_exec 走 checkCommand 分级（deny/confirm/allow），灰名单命令在 Workflow 中直接拒绝；路径操作走 checkPath 白名单。

并行执行策略 ​

  • 工具级并行：PARALLELIZABLE_TOOLS 集合标记可并行工具；rebuildBgHandlers 根据 RAW_TOOLS 重建该集合。
  • ReAct 循环并行：同组工具 Promise.all 并行执行；单组内非并行或仅 1 个则顺序执行。
  • 子任务并行：strategy=parallel 时使用 dispatchSubtasksParallel 并发池，maxParallel 限制并发数，tracked promise finally 自移除，避免竞态。
  • 资源管理：activeExecutions 限制最大活跃 Skill 执行数，定期清理过期记录；命令执行输出缓冲区上限 5MB，防止内存无限增长。

超时控制机制 ​

  • 扩展端工具级超时：executeToolWithTimeout 对除 clarify_question 外的工具设置超时，支持 TOOL_TIMEOUT_MS 自定义覆盖，但受全局 toolTimeout 上限约束；同时支持 AbortController 用户中断。
  • 交互式工具特殊处理：clarify_question 外层暂停整体循环超时，内部有独立澄清超时计时，面板呈现后才启动倒计时，未呈现期间轮询 Side Panel 存活性。
  • Agent 端命令超时：executor.js 支持受管模式（显式 timeoutMs），基于 decideTimeoutAction 策略函数裁决延长或终止；无输出视为挂起即杀，最长延长次数 MAX_TIMEOUT_EXTENSIONS，总预算封顶 TOTAL_BUDGET_CAP_MS。
  • 进程终止：Windows 使用 taskkill /T /PID，Unix 使用 SIGTERM 到进程组，5 秒后升级为 SIGKILL。

错误处理策略 ​

  • 异常捕获：工具执行、Skill 步骤、命令执行均包裹 try/catch，返回结构化 success/error 对象；Skill 执行部分失败返回 partial 结果。
  • 重试机制：Agent 连通性检测与部分网络调用具备超时与缓存；Skill 执行引擎对步骤失败按策略 continue/skip/stop 处理。
  • 审计日志：appendAuditLog 与 recordToolStats 采用内存权威态 + 防抖落盘，关键审计即时刷；Cookie/文件/命令等敏感操作均有审计记录。

依赖关系分析 ​

  • Skill loader.js 与 executor.js 共同构成 Skill 生命周期：加载→校验→执行→状态查询。

性能与并发 ​

  • 工具预筛选：当工具总数超过 PRESELECT_MIN_TOOL_COUNT 时启用预筛选，减少模型 token 消耗。
  • 并行工具组：同组工具 Promise.all 并行执行，降低端到端延迟。
  • 子任务并发池：dispatchSubtasksParallel 限制 maxParallel，tracked promise finally 自移除，修复旧 indexOf(completed) 竞态导致上限失效的问题。
  • 输出缓冲限制：命令 stdout/stderr 累计上限 5MB，超限时广播 truncated 消息并停止追加。
  • 活跃执行清理：Skill activeExecutions 最多保留 MAX_ACTIVE_EXECUTIONS，定时清理已完成/错误记录。

超时控制 ​

  • 扩展端：
    • TOOL_TIMEOUT_MS 可为单个工具设置更短超时，最终 effectiveTimeout=min(自定义, 全局 toolTimeout)。
    • clarify_question 工具不设置外层超时，仅内部独立计时；Side Panel 呈现后才启动倒计时。
    • 用户可通过 abortCurrentTool 触发 AbortController，立即 reject 当前等待工具。
  • Agent 端：
    • 受管模式下，decideTimeoutAction 根据期内是否有输出决定延长或 kill；extensions 达到 MAX_TIMEOUT_EXTENSIONS 或触及 TOTAL_BUDGET_CAP_MS 即终止。
    • 断开 WS 客户端时，仅在 managed=false 或 entry.detached=true 时才取消定时器，避免 SW 空闲被回收导致误解除超时。

调试与故障排除 ​

  • 工具定义问题：
    • 检查 id 唯一性、function.name 与 id 一致、execution 取值合法、parameters.type=object。
    • 参考测试用例断言。
  • MCP 工具不可见：
    • 确认 mcpEnabled 全局开关；检查 Agent 是否支持 MCP；查看 mcpTools 存储是否更新；确认目标服务未被禁用。
  • RAG 工具不可用：
    • 确认 ragEnabled 与 Agent /api/status ragAvailable；检查 collection 是否被禁用。
  • 命令执行卡死：
    • 检查 Shell 选择是否正确（Git Bash/PowerShell/cmd）；观察 stdout_truncated 消息；确认超时策略是否延长；必要时 detach 进程。
  • 用户取消无效：
    • 检查 AbortController 是否绑定；确认 sessionId 正确；查看 abortCurrentTool 是否调用成功。
  • 审计日志缺失：
    • 检查 appendAuditLog/recordToolStats 调用点；确认 flush 调度是否触发；SW onSuspend 兜底刷盘。

结论 ​

工具执行框架通过统一的定义与注册机制，将内置工具、MCP 动态工具与 RAG 知识库工具整合到同一执行管线；借助 Schema 压缩与参数校验保障安全性与稳定性；通过工具级与 Agent 端双层超时控制、用户中断支持与可扩展的重试/回滚策略，确保长时间任务的健壮性；并行执行与资源上限控制提升吞吐与响应速度；完善的审计与统计为排障与优化提供依据。开发新工具时，建议遵循现有工具定义规范，合理设置 parallelizable/requiresConfirmation，并在必要时接入 Agent 能力与审计记录。
