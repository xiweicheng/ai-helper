引言 ​

本文件面向“智能对话系统”的 ReAct 推理循环、工具执行框架、上下文管理、完成度校验等核心能力，提供从架构到实现细节的系统化说明。系统采用双进程架构：Chrome 扩展端（Manifest V3）负责 UI、消息路由与 ReAct 主循环；独立本地 Agent 端提供文件读写、命令执行、长期记忆与 RAG 能力。两端通过本地 HTTP/WebSocket 通信，Agent 源码修改后需重启进程才生效。

项目结构 ​

围绕本次文档目标，关键代码集中在 background 层与 shared 工具库：

  • ReAct 主循环与状态恢复：background/react-loop.js
  • 工具定义、动态注册与执行调度：background/tool-executor.js
  • 多模式循环检测器：background/loop-detector.js
  • 完成度校验编排：background/completion-verifier.js
  • Token 估算与上下文预算：shared/token-counter.js
  • 批量上下文摘要：background/context-summarizer.js
  • 流式输出控制器：background/stream-controller.js
  • 手动压缩摘要：background/context-compactor.js
  • 工具参数解析与结果规范化：background/tool-helpers.js

核心组件 ​

  • ReAct 推理循环：封装 SW 保活、超时控制、API 调用、工具执行、日志与 checkpoint 持久化、子任务计划锚点与便签回注、上下文压力评估与裁剪、反思注入。
  • 工具执行框架：统一获取可用工具、动态注册 MCP/RAG 工具、参数解析与结果规范化、并行执行策略、敏感操作确认、网络与安全门控。
  • 循环检测器：六模式检测（重复、ref 枚举、ABAB 振荡、失败作用域、导航重置、无进展滚动），软提醒与硬停结合，按 tab 隔离状态。
  • 完成度校验：客观断言取证（DOM/命令）、开放任务 critic 评审、四闸门回炉控制、缺项纠正指令生成。
  • 上下文管理：Token 估算校准、批量结构化摘要、权重兜底裁剪、图片剥离与引用压缩。
  • 流式输出：SSE 解析、节流发送、usage 提取、tool_calls 检测与 ID 规范化。

详细组件分析 ​

ReAct 推理循环 ​

  • 思考-行动-观察循环：每轮构造 messages/tools 调用 LLM；若返回 tool_calls，则进入工具执行阶段；否则视为文本回复并推进。
  • 工具调用协调：支持并行执行（PARALLELIZABLE_TOOLS）、敏感操作确认（CONFIRMATION_REQUIRED_TOOLS）、超时控制（runWithTimeout）、执行日志增量发送与内存窗口裁剪。
  • 循环检测：每轮末将工具调用记录喂入 loopDetector；根据 kind 决定注入提醒或抛出硬停错误。
  • 上下文管理：每次 API 前评估上下文压力，触发批量摘要或权重裁剪；保留 system 与 assistant(tool_calls)+tool 配对；历史图片剥离；Token 预算动态计算。
  • 完成度校验：在子任务成功时即时取证并标注 completionNote/verification；Phase B 支持基于四闸门的回炉重跑。
  • 恢复机制：checkpoint 持久化 IndexedDB，支持中断恢复、清理不完整消息对、注入恢复提示。

工具执行框架 ​

  • 工具定义与注册：BUILTIN_TOOLS、RAW_TOOLS、TOOL_HANDLERS、TOOL_EXECUTION_MAP；动态加载 MCP/RAG 工具，重建 BG_HANDLERS 与并行/确认集合。
  • 参数验证与结果规范化：tryParseToolArgs 两阶段修复 JSON；normalizeToolResult 统一 {success, content, tool_call_id}。
  • 并行执行策略：依据 PARALLELIZABLE_TOOLS 并发执行；执行日志增量发送，避免 64MiB 限制。
  • 超时控制：runWithTimeout 包装 Promise.race；工具级超时与整体循环超时分离。
  • 安全与确认：敏感工具弹出确认对话框，支持“当前任务放行”；agent_exec 灰名单命令走相同确认通道。
  • 会话强制下发 MCP 服务：绕过关闭/排除列表，保证预筛选不丢弃。

循环检测算法 ​

  • 六模式：重复（窗口制）、ref 枚举（query_elements）、ABAB 振荡、失败作用域（白名单工具）、导航重置（back/forward/reload/wait_navigation）、无进展滚动（scroll_to）。
  • 状态桶：按 tabId 隔离，维护 window、ababTail、repeatCounts、refEnum、failureScopes、scroll、warned/flowWarned、healthyStreak。
  • 输出：kind=none/nudge/stop；nudge 合并为一条 user 提醒注入；stop 抛错并带 loopStop reason。

完成度验证器 ​

  • 断言归一化：normalizeDoneCriteria 过滤非法/不受支持的 check。
  • 异步取证：createContentEvidenceCollector（DOM）、createCommandEvidenceCollector（命令/文件）、createRoutingEvidenceCollector（路由 DOM/命令）。
  • 判定内核：classifyVerdict 输出 SATISFIED/UNMET_RETRYABLE/UNMET_PERMANENT/INDETERMINATE。
  • 回炉控制：四闸门（可重试∧有进展∧有预算∧未超次）+ 严格真子集进度判定；directive 仅点名可取证且未通过的缺项。
  • 注解写入：annotateOneSubtaskCompletion 在子任务 onDone 即时写回 verification/completionNote；Phase B 支持 rerun 回调驱动再跑一轮。

上下文管理与 Token 优化 ​

  • Token 估算与校准：estimateMessagesTokens 支持多模态内容；EWMA 校准因子更新 getCalibratedTokens。
  • 上下文预算：getMessageBudget 与 assessContextPressure；按 80% 阈值触发批量摘要，仍超标则权重裁剪。
  • 批量摘要：summarizeRoundsBatch 一次 LLM 压缩多轮旧对话，注入结构化摘要（任务目标/已完成/关键事实/未决问题）。
  • 手动压缩：generateCompactionSummary 用户显式触发，快速失败明确报错。
  • 图片处理：stripImagesFromContent 剥离历史图片；sanitizeImageUrlsForApi 仅传 url 字段。

性能与优化 ​

  • Token 估算校准：EWMA 平滑实际 prompt_tokens，减少估算偏差导致的过度裁剪或超限。
  • 批量摘要替代串行摘要：一次 LLM 调用压缩多轮旧对话，降低调用次数与延迟。
  • 权重裁剪 O(n)：贡献预估算一次，增量扣减，避免 O(n²)。
  • 执行日志内存窗口：EXECUTION_LOG_MEMORY_LIMIT 限制日志规模，防止 SW 内存失控。
  • 流式空闲超时：STREAM_IDLE_TIMEOUT_MS 保护长连接卡死。
  • 大工具结果卸载：offloadLargeToolResult 将全文写入 workspace，对话内仅保留预览与路径，按需回读。

故障排查指南 ​

  • API 400 上下文超限自愈：检测到 context/token/too long 特征时，按 CONTEXT_HEAL_RATIOS 逐档裁剪并重试本轮，至多 CONTEXT_HEAL_MAX_ATTEMPTS 次。
  • 流式空闲超时：readSSEStream 抛出 StreamIdleTimeout，区分 AbortError 与空闲超时，分别给出用户可见文案。
  • 工具参数解析失败：tryParseToolArgs 两阶段修复（位置引导修复、尾随逗号、未加引号字符串、嵌套对象、自动补全括号/引号、数组混入 KV 对）。
  • 工具结果格式异常：normalizeToolResult 兜底填充 content 与 tool_call_id，失败返回标准错误对象。
  • 侧边栏确认弹窗无法送达：默认拒绝 fail-closed，撤销陈旧弹窗，避免串扰与悬挂。

结论 ​

本系统以 ReAct 主循环为核心，串联工具执行、循环检测、完成度校验与上下文管理，形成稳健的智能对话闭环。通过 Token 校准、批量摘要与权重裁剪保障上下文稳定；通过多模式循环检测与四闸门回炉控制抑制无效振荡；通过流式控制器与执行日志增量发送提升用户体验与可观测性。
