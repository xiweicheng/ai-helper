# 工作目录动态切换

## Context（背景与目标）

当前工作目录（workdir）由代理端配置文件 `~/.ai-helper-agent/config.json` 决定，启动时快照，运行期无法更改；用户只能在配置文件里手改后重启代理。用户希望在工作目录管理面板里**随时动态切换**当前活跃代理的工作目录，且：

- 默认从「允许访问目录列表」(allowedPaths) 中点选；
- 也支持手动输入一个超出列表的绝对路径；
- 切换后，后端配置、系统提示词注入的工作目录、插件端各处 workdir 缓存都要同步；
- 不破坏现有功能（文件拖拽、面包屑导航、虚拟滚动、上传/下载/删除/搜索、代理切换刷新）。

工作目录数据流现状（已核实）：
- 代理端 `agent/src/config.js` 存 `workdir` + `allowedPaths`，有 `saveConfig` / `updateConfigField`（带写锁）。
- 代理端 `agent/src/server.js` 的 `/api/status/detail` 返回两者；所有 fs 操作经 `agent/src/security.js` 的 `checkPath()` 校验，路径必须落在 `allowedPaths` 前缀内，否则 403。
- 插件端 workdir 有 **3 处缓存**：`state.agentPlatform.workdir`（喂 system prompt）、`state.agentWorkdirs` Map（代理下拉显示）、`_workspaceRoot`（workspace-manager.js 模块级，喂文件面板）。
- system prompt 在 `src/side_panel/utils.js:234 getSystemPrompt()` 每次构建时读 `state.agentPlatform.workdir`，注入到「命令执行环境」的「工作目录」字段（L246）——**只要更新 state.agentPlatform.workdir，下次发消息自动用新值，无需改 prompt 构建**。

## 关键风险（必须先处理）

**server.js 的 `config` 是启动快照**：`startServer()` 内 `const config = loadConfig()`（L349）被 `handleRequest` 闭包捕获后永不刷新。L620/621（status/detail）、L646/655/661（上传默认目标）、L1382（exec cwd）都读这个快照。若不修复，切换 workdir 后 status/detail 仍返回旧值 → 前端 `getWorkspaceRoot` 拿旧值 → 整个切换失效。而 `security.js` 的 `checkPath` 每次 `loadConfig()`（mtime 缓存自动刷新），会用到新值 → 出现「前端显示旧 root、后端校验新 root」的不一致。

**修复**：在 `handleRequest` 函数体顶部（url 解析之后、进入接口之前）加一行遮蔽声明 `const config = loadConfig();`。此 `config` 遮蔽外层闭包变量，上述引用点全部自动拿最新值。`loadConfig()` 有 mtime 缓存，无磁盘变化时仅一次 `statSync`，开销可忽略。外层 L349 的 config 仍保留给 L350（port/host）和 L355（启动日志）。

## 实现方案

### 1. 代理端：新增 `POST /api/config/workdir` 接口

文件：`agent/src/server.js`

1. **补 import**（L13）：`import { loadConfig, saveConfig } from './config.js';`（`mkdir`/`join`/`resolve`/`homedir` 已 import）。
2. **handleRequest 顶部加遮蔽**（L376 函数体内，url 解析 L398 之后）：`const config = loadConfig();`
3. **新增接口**：插入到 `parseBody` 之后、`/api/fs/search_files`（L760）之前（与其他 POST JSON 接口同区）。逻辑：
   - 取 `body.workdir`，校验非空字符串；
   - 展开 `~` → `homedir()`；必须是绝对路径（Unix `/` 或 Windows 盘符），否则 400；
   - `resolve()` 规范化；禁止设为 `~/.ai-helper-agent` 本身（防敏感目录暴露），403；
   - `await mkdir(resolvedWorkdir, { recursive: true })`——**目录不存在自动创建**（创建失败如权限不足才报错）；
   - `loadConfig()` 取最新 → 复制 → 设 `workdir = resolvedWorkdir`；若 `allowedPaths` 不含该路径则追加（**只增不减**，旧路径保留）；
   - `await saveConfig(updatedConfig)`（内部写锁防并发）；
   - `logSystem('workdir_switched', ...)`；返回 `{ success, workdir, allowedPaths, message }`。
   - 复用 L437 `verifyToken` 认证（接口在认证块之后）。

设计决策：目录不存在→自动 mkdir -p（手动输入新路径时体验最好）；新 workdir 必须加入 allowedPaths（否则 checkPath 拒绝访问）；旧 allowedPaths 保留（切回旧目录仍可访问、不丢配置）；不允许通过此接口删 allowedPaths。

### 2. 插件端 workspace-manager.js：新增两个函数

文件：`src/side_panel/workspace-manager.js`

1. `getAgentStatusDetail()`（插在 L172 `getWorkspaceRoot` 之后）：fetch `/api/status/detail`，返回完整 data（含 workdir、allowedPaths），供弹窗展示 allowedPaths 复用。
2. `switchWorkspace(newWorkdir)`（插在 L180 `resetWorkspaceRoot` 之后）：调内部 `agentRequest('/api/config/workdir', { workdir })`；成功后 `resetWorkspaceRoot()` 清缓存；返回 `{ success, workdir?, allowedPaths?, error? }`。

具名 export，无需改 export 列表。

### 3. 插件端 workspace-panel.js：UI 改动

文件：`src/side_panel/workspace-panel.js`

1. **import 补充**（L2-12）：加 `getAgentStatusDetail, switchWorkspace`。
2. **title-row 加切换按钮**（L65-73）：在 `<span id="workspaceAgentName">` 之后、`<button id="workspacePanelClose">` 之前，插入 `<button class="workspace-panel-switch-btn" id="workspaceSwitchBtn" title="切换工作目录">` + 文件夹切换图标 SVG。按钮 CSS 用 `margin-left:auto` 推到右侧（close 原有 `margin-left:auto` 在 flex 中剩余空间已被切换按钮吸收，自然紧贴其右），不破坏现有右靠布局。
3. **bindEvents 绑定**（L205 之后）：`workspaceSwitchBtn` click → `showSwitchWorkdirDialog()`。
4. **新增 `showSwitchWorkdirDialog()`**（插在 L3617 `showInputDialog` 之后）：
   - 调 `getAgentStatusDetail()` 拿 `workdir` + `allowedPaths`；
   - 仿 `showInputDialog`（L3579）的 `modal-overlay show` + `modal-container` 模式构建弹窗（仅按钮关闭，禁止点遮罩关闭——符合 no-native-dialogs 规则）；
   - 弹窗内容：标题「切换工作目录」+ 当前 workdir 显示 + 「从允许的目录中选择」列表（每项 📁 + 路径，当前项高亮带「当前」徽标，非当前项点击即切换）+ 「或输入绝对路径」输入框（placeholder `/Users/you/path 或 ~/path`）+ 取消/切换按钮；
   - 列表项点击 → `doSwitch(path)`；切换按钮/输入框 Enter → `doSwitch(input.value)`；Esc/取消 → resolve(false)；
   - 若输入路径不在 allowedPaths 内，先 `await window.showCustomConfirm(message, title)`（index.js L16 已定义，签名 `(message, title)` 返回 Promise<boolean>）二次确认。
5. **新增 `performSwitchWorkdir(newWorkdir)`**（紧接上文）：切换成功后的完整刷新流程（复用 `handleStorageChange` L3031 的清理模式）：
   - `switchWorkspace(newWorkdir)` → 失败 toast 报错返回；
   - 清面板本地状态：`workspaceRoot=null; currentPath=null; pathHistory=[]; selectedPaths.clear(); searchQuery=''; searchResults=[]; isSearchMode=false; dirCache.clear();`（`resetWorkspaceRoot` 已在 switchWorkspace 内调）；
   - 同步 `state.agentPlatform = { ...state.agentPlatform, workdir: result.workdir }`（system prompt 下次构建自动用新值）；
   - 同步 `state.agentWorkdirs.set(activeAgentId, result.workdir)` + 调 `window.updateAgentItemWorkdir(activeAgentId, result.workdir)` 刷新下拉项；
   - 面板若展开则 `navigateToRoot()` 重新导航；toast 成功提示。

### 4. 插件端 side_panel/index.js：暴露下拉刷新函数

文件：`src/side_panel/index.js`

在 `updateAgentItemWorkdir`（L969）定义之后，或初始化阶段（L16 `window.showCustomConfirm` 附近）加：`window.updateAgentItemWorkdir = updateAgentItemWorkdir;`（供 workspace-panel.js 切换后调用，刷新代理下拉项的 workdir 显示）。无需改 `updateAgentDropdown` 整表重渲（避免闪烁）。

### 5. CSS：切换按钮 + 弹窗列表样式

文件：`src/side_panel/styles.css`

在 modal 样式区（L4250 附近）新增：`.workspace-panel-switch-btn`（22×22 透明按钮，margin-left:auto，hover 变蓝）、`.switch-workdir-dialog` 系列列表项样式（current 高亮、hover、徽标、空态）。弹窗主体尽量复用现有 `.modal-overlay/.modal-container/.modal-title/.modal-input`，降低样式风险。

## 端到端验证步骤

1. `npm run build:silent`（失败则按报错修复 import/语法）。
2. **场景 A 列表选**：点切换按钮 → 弹窗列 allowedPaths → 点非当前项 → 弹窗关闭、面板导航到新 root、面包屑新路径、toast 成功。
3. **场景 B 手动输入已存在路径**（如 `/tmp`，不在列表）→ 自定义确认框 → 切换成功、`/tmp` 加入 allowedPaths、面板导航到 `/tmp`。
4. **场景 C 手动输入不存在路径**（如 `/tmp/ai-helper-test-xxx`）→ 确认 → 后端自动 mkdir、切换成功、面板导航到空目录。
5. **场景 D 输入当前 workdir** → toast「该目录已是当前工作目录」，不切换。
6. **场景 E 输入相对路径** → 后端 400「必须是绝对路径」，toast 报错。
7. **后端同步**：`cat ~/.ai-helper-agent/config.json` 确认 workdir 和 allowedPaths 更新（旧 allowedPaths 保留）；`GET /api/status/detail` 返回新值；面板上传文件落新 workdir；聊天框 `pwd` 输出新 workdir。
8. **system prompt**：切换后发「当前工作目录是什么」，确认回复中工作目录是新值。
9. **不破坏**：切换 workdir 后再切代理，面板自动 reset 导航到该代理 root；搜索/上传/下载/删除/新建/重命名/拖拽全部正常；代理下拉项 workdir 显示已更新。
