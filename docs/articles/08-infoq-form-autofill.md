## 摘要

让大模型"聊得好"已经不算新闻，让它"干得了活"才是当下 Agent 领域真正的分水岭。我们用一段 67 秒的演示视频记录了一个完整案例：把一份含 3 条商品数据的 Excel 交给浏览器插件 AI Helper，附上一句"按要求只录入前两条"，插件自己打开表单页、逐行读取数据、逐字段填写、走完四步向导、核对确认弹窗并提交，最后与源数据分屏对照验收——全程零手动操作。本文以这段视频为线索，逐段拆解画面背后正在发生的事情：ReAct 推理循环、工具预选、三级反思、Shadow DOM 与 React 受控组件穿透，以及把流程沉淀为 Skill 的工程实践。文末还有一个彩蛋：这段演示视频本身，也是用脚本"生成"出来的。

## 一、为什么是"批量填表"

后台运营同学大概都经历过这样的下午：商品上架季，几十条商品数据躺在 Excel 里，而后台表单一次只能录一条——名称、SKU、分类、价格、库存、上架状态、标签、保修期、商品描述、备注……复制、粘贴、切换下拉、勾选复选框，一条三分钟，三十条就是一个半小时，还得祈祷别把价格粘错行。

这类任务对人是纯粹的重复劳动，对 AI Agent 却是一份含金量很高的考卷，因为它同时考察四件事：

1. **指令理解与约束执行**——"共 3 条，只录前 2 条"，多录一条就是错；
2. **跨页面操作**——数据在 Excel 里，动作在另一个网页的表单里；
3. **真实 DOM 的复杂度**——现代前端框架的受控组件、Shadow DOM， naive 的 `element.value = x` 赋值根本不会触发框架状态更新；
4. **结果自证**——填完不算完，得能核对"录进去的"和"源数据"是否一致。

演示视频选的正是这个场景。下面按视频时间轴逐段拆解。

## 二、演示逐段拆解

### 0:00–0:08 数据源与"隐藏约束"

视频先给 Excel 特写：3 条商品（无线蓝牙降噪耳机、纯棉圆领印花 T 恤、有机混合坚果礼盒），高亮扫过前两行，第三行以灰色带过——字幕写明"共 3 条，本次演示录入前 2 条"。这不是剪辑效果，而是任务指令的一部分：**用户只要求录入前两条**。Agent 是否守得住这个约束，是整段演示的第一个看点。

### 0:08–0:58 录屏主体：从启动到提交

录屏以 1.6 倍速播放，顶部字幕把过程切成五个阶段：

1. **启动插件，解析目标表单页**。侧边栏里一句自然语言指令下单后，插件自动跳转到目标表单页（一个四步向导：基本信息 → 价格库存 → 详情 → 确认），并先"看懂"页面结构：哪些是输入框、哪些是下拉、哪些是受控组件。
2. **逐行读取 Excel，自动填入字段**。第一条商品的名称、SKU、分类、售价、库存、上架状态、标签逐个落位。注意画面里字段值是由插件以"模拟真实输入"的方式写入的——对 React 受控组件，直接改 `value` 不会生效，必须走原生 setter 加派发 input/change 事件，才能让框架"认为"是用户输入的。
3. **按步骤推进**。填完基本信息点"下一步"，进入价格库存、详情步骤，继续填，直到向导走完。每一步之间都有等待与校验，而不是盲目连点。
4. **确认弹窗自动核对，一键提交**。最后一步的确认弹窗里，Agent 会把即将提交的字段值与源数据再核对一遍，确认无误才点击提交。
5. **结果校验**。页面回到记录列表，两条商品在列，状态"已上架/预售"与源数据一致。

第二条商品重复同样的流程。全程侧边栏里能看到 ReAct 循环的实时日志：每一轮"思考 → 选工具 → 执行 → 反思"都摊开给用户看，Token 消耗同步计数。

### 0:58–1:07 结果分屏对照

结尾定格在执行结果汇总页，左侧绿框标注"提交成功"，右侧与 Excel 源数据分屏对照：前两条标记 Done，第三条标记 Skipped——**指令说只录两条，就恰好停在两条**。旁白收尾："前两条数据准确提交完成，与 Excel 源数据完全一致。"

## 三、画面背后的技术底座

### 3.1 ReAct 推理循环 + 工具预选

AI Helper 的执行内核是一个配置化的 ReAct 循环：每轮先由轻量模型做一次**工具预选**——把 40 多个内置工具定义全塞给主力模型，Token 会爆炸且注意力被稀释；先用一次廉价调用缩到 5–10 个与当前任务真正相关的工具，再交给主模型决策"思考 → 调用工具 → 观察结果"。填表任务里被选中的就是页面交互族工具：点击、输入、选择、等待元素、读取表格等。

### 3.2 三级反思：不把 LLM 的原始输出直接甩给你

每轮工具执行后做工具级反思（这一步真的成功了吗？元素真的存在吗？）；子任务边界做子任务反思；最终答案再做后置反思，按 7 个维度评分，未达标自动修订或重跑。填表这种"错一个字段就是错"的任务，靠的就是这层质量兜底——确认弹窗里的"自动核对"，本质也是反思链路的一环。

### 3.3 页面操作层：穿透真实前端

Content Script 侧的操作层处理三类硬骨头：Shadow DOM 内的元素寻址、同源 iframe 跨帧操作、以及 React/Vue 受控组件的值写入（原生 value setter + 事件派发）。演示里的四步向导表单大量使用受控输入与动态渲染，插件的"等待元素可见再操作"策略保证了步骤切换时不会点空。

### 3.4 Skill：把流程沉淀成技能

"读 Excel → 打开表单 → 逐行填写 → 核对提交"这套流程，在 AI Helper 里可以沉淀为一个 Skill（技能），下次换一份 Excel 只需一句话触发，无需重复描述步骤。工具能力还可以通过 MCP 协议动态扩展——今天填商品表单，明天接上数据库工具就能做数据核对。

## 四、花絮：这段演示视频也是"生成"的

演示视频本身没有用任何剪辑软件：画面由 ffmpeg 滤镜管线分五段合成（渐变片头、Excel 特写逐行高亮、1.6 倍速录屏叠加步骤字幕与闪烁高亮、成功定格分屏、收尾画面），旁白由 macOS 系统语音合成，BGM 与音效是用 numpy 现场合成的和弦垫与提示音，混音时旁白出现处 BGM 自动闪避；中/英两个版本由同一套脚本参数化产出，构建脚本已开源在仓库 `demo/form-autofill/video-build/` 下，附完整构建指引。用自动化演示自动化，算是这个项目的一点小执念。

## 五、上手与开源

AI Helper 基于 MIT 协议开源（GitHub: xiweicheng/ai-helper），已上架 Microsoft Edge 扩展商店；Chrome/Chromium 用户可通过开发者模式加载构建产物使用。填入任意 OpenAI 兼容端点的 API Key 即可开始对话，需要本地文件读写/命令执行时再可选安装本地代理服务。演示视频中英双语版、Demo 表单页与 Excel 数据源均在仓库与文档站公开，欢迎复现、挑刺、提 PR。

## 结语

"能不能聊"早已不是大模型应用的差距所在，"能不能把一件琐碎但严格的事完整做对"才是。批量填表这样的小场景，恰恰是检验 Agent 指令约束、页面操作、质量反思全链路的试金石。我们希望这段 67 秒的视频和它背后的开源实现，能为你自己的"动手型 AI"提供一个可拆解、可复用的样本。
