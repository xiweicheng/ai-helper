# 三级反思系统：让 AI 给自己的回答打分

> 本文来自 AI Helper 项目的真实工程实践。AI Helper 是一个开源的 Chrome 智能助手扩展，采用 ReAct（Reasoning + Acting）推理循环架构，内置 44 个工具，支持多轮工具调用和复杂任务拆解。

## 问题：AI 会犯错

ReAct 架构让 AI 能够"思考-行动-观察"循环往复地完成任务。但现实很骨感：

- 工具调用会失败——页面结构变了、元素选择器过时了、网络超时了
- AI 会做出错误判断——选了不合适的工具、参数填错了
- 中间结果可能是空的或异常的

如果只是机械地执行 ReAct 循环、输出最终结果，质量完全靠运气。AI Helper 的解法是：**让 AI 在执行过程中和执行结束后，对自己的行为进行反思**。

这就是三级反思系统。

## Level 1：工具级反思

每次工具调用完成后，系统会评估这个工具的结果是否"有用"。不是每次都反思——只在特定条件下触发。

### 触发条件

```js
export function shouldTriggerToolReflection(toolResultStr, failCountInIteration, reflectionConfig) {
  const tc = reflectionConfig.toolReflection;

  // 连续失败触发
  if (tc.triggerOnConsecutiveFails && failCountInIteration >= tc.triggerOnConsecutiveFails)
    return true;

  // 错误结果触发
  if (tc.triggerOnError && (toolResultStr.includes('"success":false') || 
      toolResultStr.includes('error') || toolResultStr.includes('失败')))
    return true;

  // 空结果触发
  if (tc.triggerOnEmpty && (!toolResultStr || toolResultStr.trim() === '' || 
      toolResultStr === '{}'))
    return true;

  // 结果过大触发（超过阈值字符数）
  if (tc.triggerOnOversized && toolResultStr.length > tc.oversizeThreshold)
    return true;

  return false;
}
```

四个触发条件，覆盖了工具调用最常见的异常场景。其中"结果过大"的触发很巧妙——一个工具返回 50000 字符的结果，要么是提取错了（把整个页面 HTML 拉回来了），要么需要进一步处理，都值得反思一下。

### 反思怎么做

触发后，系统调用一次轻量 API，让模型快速评估工具结果是否有用：

```js
const prompt = `The tool "${toolName}" was called with parameters ${JSON.stringify(toolCallParams)}.
Tool returned result (truncated): ${toolResultStr.substring(0, 2000)}
Please quickly assess whether this tool result is helpful.
Output: {"useful": true, "reasoning": "brief reason", "suggestion": null}`;
```

模型返回 `useful: false` 时，会附带改进建议。这个建议会被注入到下一轮 ReAct 循环中，引导 AI 调整策略。

### 每轮限流

工具反思有频率限制——`maxPerIteration`（默认 2 次/轮）。防止反思本身陷入死循环：工具失败 → 反思 → 还失败 → 再反思……

### 优先级排序

当同一轮有多个工具需要反思时，`getToolReflectionPriority` 会按优先级排序处理：

- 错误结果：+10 优先级
- 连续失败：+5 × 失败次数
- 重要工具（表单填充、数据修改等）：+3
- 空结果：+2

优先处理最严重的问题，避免在次要问题上浪费 API 调用。

## Level 2：子任务反思

当 AI Helper 执行复杂任务时，会将任务拆解成子任务（通过 `plan_task` 工具）。每个标记为 `complex` 的子任务执行完后，会进行一轮质量评估。

```js
export async function reflectOnSubtask(messages, result, executionLog, model, config, 
                                        subtaskReflectConfig, ...) {
  const dimensions = subtaskReflectConfig.dimensions || ['completeness', 'relevance'];
  // 评估维度可配置
  const prompt = `Evaluate the execution result of subtask: ${subtaskName}
  // ... 按 dimensions 逐维度打分
  Output: {"overallScore": 8, "dimensions": {...}, "issues": [...], "refinedAnswer": null}`;
}
```

子任务反思聚焦于两个核心维度：**完整性**（任务是否充分完成）和**相关性**（结果是否切中任务目标）。如果模型认为结果有问题，可以输出 `refinedAnswer` 进行修订。

## Level 3：后置反思

这是最重量级的反思——在 ReAct 循环产出最终答案后，对整个回答做一次全面质量评估。

### 评估维度

后置反思的 Prompt 让模型从多个维度给最终答案打分：

```
## Evaluation Dimensions (each scored 1-10)
1. completeness: 是否完整回答了用户问题？
2. accuracy: 信息是否准确可靠？
3. relevance: 是否紧扣用户需求？
4. toolUsage: 工具选择是否合理？参数是否正确？
5. efficiency: 是否有不必要的步骤或重复操作？
```

模型输出一个 `overallScore`（总分）和各维度分数，同时附带发现的问题和改进建议。

### 三档决策

```js
if (parsed.overallScore >= postConfig.qualityThreshold) {  // 默认 ≥7
  decision = 'passed';        // 通过，使用原答案（或模型主动修订版）
} else if (parsed.overallScore >= postConfig.refineThreshold) {  // 默认 ≥5
  decision = 'revised';       // 修订，使用模型提供的 refinedAnswer
} else {  // <5
  if (parsed.refinedAnswer) {
    decision = 'revised';     // 低分但有修订版，使用修订答案
  } else {
    decision = 'needs_improvement';  // 建议重新执行整个任务
  }
}
```

- **≥7 分**：通过。如果模型主动提供了更好的答案版本，也会采用。
- **5-7 分**：修订。使用模型生成的修订版答案。
- **<5 分**：需要改进。如果有修订版就用修订版；没有的话，建议重新执行任务。

### 多轮修订

后置反思支持多轮修订循环（`maxRounds` 可配置，上限 10 轮）。第一轮没通过就用修订答案再做一轮评估，直到通过或用完轮数。

## 配置：让用户决定

反思系统默认整体关闭，但后置反思默认开启。用户可以自己决定：

- **质量优先**：开启全部三级反思，接受额外的 API 调用和延迟。
- **速度优先**：只保留后置反思，甚至全部关闭。
- **按需调节**：工具反思的触发阈值、每轮最大次数、后置反思的质量阈值和修订阈值都可配置。

## 代价

反思不是免费的。每一级反思都需要一次额外的 API 调用：

- 工具级反思：每次触发约消耗 512 tokens 输出
- 子任务反思：每次约 1024 tokens
- 后置反思：每次约 4096 tokens，多轮修订则成倍增加

所以整个反思体系的设计哲学是：**让用户自己决定要不要开**。简单任务不需要反思，复杂任务才需要。质量优先还是速度优先，这是一个 trade-off，交给用户判断。

## 总结

三级反思系统让 AI 具备了"自我纠错"能力。工具级反思在执行过程中捕捉异常，子任务反思保证每个复杂步骤的质量，后置反思对最终答案做全面评估。即使中间步骤出错，AI 也有机会自己发现并修正，而不是把错误一路带到最终输出。
