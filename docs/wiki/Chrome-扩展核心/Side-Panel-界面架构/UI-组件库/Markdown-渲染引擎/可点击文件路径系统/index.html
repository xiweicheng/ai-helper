引言 ​

本文件聚焦“可点击文件路径系统”，即 AI Helper 在侧边栏中把 Agent 生成的工作目录文件、命令输出产物和对话消息中的文件路径，统一转化为可点击、可定位、可预览的交互能力。该系统横跨两条主线：

  • 任务产物线：从 Agent 执行日志中提取写文件操作，生成“文件产物”面板，支持定位到工作目录、预览、下载等。
  • 输入选择线：通过 $ 选择器在工作目录中检索文件/目录，并作为“基于文件的问答”附件加入输入区。
  • 消息链接线：将聊天消息中的有效文件路径渲染为可点击链接，点击后跳转到工作目录面板并高亮对应条目。

该项目采用双进程架构：Chrome 扩展端（Manifest V3，版本 2.3.1）与独立本地代理端 Agent（Node.js，npm 包名 ai-helper-agent，版本 2.3.1）。两端版本号保持同步；Agent 源码修改后必须重启进程，新接口才生效。

项目结构 ​

围绕“可点击文件路径系统”，相关代码主要分布在 side_panel 子模块：

  • artifacts-manager.js：任务文件产物管理，负责从 executionLog 提取写文件操作，提供产物列表、定位、预览、下载等。
  • file-at-selector.js：输入框 $ 选择器，用于检索工作目录文件/目录并添加到“文件问答”。
  • workspace-panel.js：工作目录文件管理器 UI，承载浏览、搜索、预览、编辑、导出、定位等能力。
  • chat-manager.js：消息渲染入口之一，负责把产物按钮挂载到消息右侧，并把有效文件路径转换为可点击链接。
  • utils.js：通用工具，包含 i18n 文案注入、提示、时间格式化等。
  • manifest.json 与 scripts/fix-build.js：构建期处理 MV3 Service Worker、side panel HTML 脚本注入及运行时 side_panel.default_path 剥离，保证 side panel 可被 background 动态控制。

核心组件 ​

  • 产物管理器（artifacts-manager.js）
    • 从 Agent 执行日志中提取写文件操作，包括 echo/cat/tee/cp/mkdir/touch 等常见模式，以及 Bash 花括号展开、heredoc 内联脚本、find/ls 输出兜底解析。
    • 提供产物列表、排序、定位到工作目录、预览、下载、复制文件名/路径等操作。
  • 工作目录面板（workspace-panel.js）
    • 展示当前工作目录内容，支持搜索、多选、上传、删除、重命名、移动、预览、编辑、导出（Word/PDF/图片/Markdown）、在浏览器打开等。
    • 暴露 locateFileInWorkspace、previewArtifactFile、resolveWorkspaceAbsolutePath 等函数供产物管理器调用。
  • 输入 $ 选择器（file-at-selector.js）
    • 输入 $ 时触发，远端递归搜索名称匹配的文件/目录，前端按前缀匹配、最近修改时间、目录优先、字典序排序，最多显示 50 条。
    • 选中后将文件元数据附加到“文件问答”，并自动调整输入框高度。
  • 消息渲染（chat-manager.js）
    • 当消息存在 agent_file 产物时，挂载“文件产物”按钮，并异步校验产物有效性。
    • 将消息中的有效文件路径转换为可点击链接，点击后进入工作目录面板定位。
  • 通用工具（utils.js）
    • 提供 Toast、输入框高度自适应、下拉框定位、HTML 转义、时间格式化等基础能力。

架构总览 ​

“可点击文件路径系统”的运行流程如下：

  1. Agent 执行命令或脚本，产生工作目录文件。
  2. 扩展侧从执行日志中提取产物，并在消息右侧显示“文件产物”按钮。
  3. 用户点击产物按钮，打开产物列表，可对单个文件进行定位、预览、下载。
  4. 用户在输入框输入 $，触发工作目录文件选择器，选择文件后加入“文件问答”。
  5. 聊天消息中的有效文件路径会被渲染为可点击链接，点击后跳转到工作目录面板并高亮对应条目。

详细组件分析 ​

产物管理器（artifacts-manager.js） ​

产物管理器是“可点击文件路径系统”的核心，承担以下职责：

  • 规范化路径、提取文件名/扩展名、HTML 转义。
  • 解析 Bash 花括号扩展，如 mkdir -p dir/{a,b}、touch {x,y}.txt。
  • 从 agent_exec 命令字符串中提取写入目标，包括重定向、cat > file、cp、tee、mkdir、touch 等。
  • 解析 heredoc 内联脚本，识别 Python/shell 等解释器，静态分析脚本内部创建的文件路径。
  • 从 find/ls 输出中兜底解析路径，区分目录与文件，过滤非路径 token。
  • 提供产物列表渲染、排序、定位、预览、下载、复制文件名/路径等功能。

输入 $ 选择器（file-at-selector.js） ​

$ 选择器用于在工作目录中快速检索文件/目录，并将其作为“文件问答”附件加入输入区：

  • 输入 $ 时触发，若有关键词则远端递归搜索，否则展示根目录内容。
  • 搜索结果按前缀匹配、最近修改时间、目录优先、字典序排序，最多显示 50 条。
  • 选中文件后，移除输入框中的 $... 文本，焦点回到输入框，并将文件元数据附加到“文件问答”。

性能与可靠性 ​

  • 产物解析优化：
    • 使用 Bash 花括号展开与 heredoc 静态分析，减少误判。
    • 对 find/ls 输出进行黑名单过滤与启发式分类，避免权限位/用户名/时间等非路径 token 被误识别。
  • 输入选择器优化：
    • 远端搜索防抖 200ms，避免频繁请求。
    • 前端排序后截断至 50 条，提升可读性与性能。
  • 工作目录面板优化：
    • 大文件预览降级为“在浏览器中打开”，避免内存压力。
    • 预览期 window 监听使用 AbortSignal 管理生命周期，避免常驻监听泄漏。
  • 构建期优化：
    • 剥离 side_panel.default_path，避免运行时覆盖 background 的 setOptions 控制，确保 side panel 行为一致。

故障排查指南 ​

  • 产物未显示：
    • 检查 Agent 是否已连接，工作目录是否已设置。
    • 确认执行日志中存在 agent_file 产物，且路径有效。
  • 文件定位失败：
    • 检查工作目录是否包含该文件，或文件是否已被删除。
    • 确认 resolveWorkspaceAbsolutePath 返回的路径是否正确。
  • $ 选择器无结果：
    • 检查远端搜索是否成功，关键词是否过短或过长。
    • 确认工作目录权限是否足够，能否列出目录内容。
  • 消息链接不可点击：
    • 检查 applyFilePathLinks 是否被调用，路径是否符合工作目录规范。
    • 确认 workspace-panel.js 的 locateFileInWorkspace 方法是否正常。

结论 ​

“可点击文件路径系统”通过产物管理器、工作目录面板、$ 选择器和消息渲染四个核心组件，实现了从 Agent 执行日志到用户交互的完整闭环。它不仅提升了用户对生成文件的可见性和可操作性，还通过 $ 选择器增强了“基于文件的问答”体验。系统在性能与可靠性方面做了多项优化，包括防抖、截断、预览降级、构建期脚本注入等，确保在不同场景下都能稳定运行。未来可考虑进一步增强路径解析的鲁棒性，例如支持更多 shell 语法和动态变量替换，同时优化大文件预览的性能表现。
