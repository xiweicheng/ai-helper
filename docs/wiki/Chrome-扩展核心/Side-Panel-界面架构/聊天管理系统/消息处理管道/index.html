引言 ​

本文面向“从用户输入到 LLM 响应”的完整消息处理管道，覆盖以下关键主题：

  • 消息类型系统：用户消息、系统消息、工具调用消息与结果消息的结构与流转。
  • 意图识别与工具预筛选：如何根据上下文选择候选工具集合。
  • 工具执行协调：参数校验、并行执行、超时控制、错误重试与确认门控。
  • 消息路由：本地工具、远程 Agent 请求与浏览器 API 调用的分发策略。
  • 状态管理：待发送、执行中、完成、失败等状态转换规则。
  • 审计日志：执行时间追踪、Token 统计与调试信息收集。
  • 压缩与优化：上下文截断、重复消息去重与缓存机制。

本项目的双进程架构为 Chrome 扩展端（Manifest V3）+ 独立本地代理端 Agent；扩展端通过 HTTP/WebSocket 调用 Agent 的文件读写、命令执行、长期记忆与 RAG 能力。Agent 源码修改后必须重启进程新接口才生效。

项目结构 ​

围绕消息处理管道的核心代码集中在 background 层：

  • index.js：Service Worker 入口、侧边栏与面板生命周期、保活端口、自动续跑与 checkpoint 恢复。
  • react-loop.js：ReAct 推理循环、API 调用、流式响应、循环检测、子任务编排与检查点持久化。
  • tool-executor.js：工具定义、动态注册（MCP/RAG）、工具执行、网络访问安全门控、审计记录。
  • agent-dispatcher.js：子 Agent 调度，派生会话隔离、深度限制与结果截断。
  • local-agent-client.js：与 Agent 的 HTTP/WebSocket 通信封装、认证、超时与可达性缓存。
  • stream-controller.js：SSE 流式读取与空闲超时控制。
  • token-recorder.js：Token 用量统计。
  • activity-store.js：活动存储与审计日志写入。
  • shared/tools.js：默认 ReAct 配置与模型常量。

核心组件 ​

  • Background 入口（index.js）
    • 负责 SW 保活、侧边栏可见性、自动续跑闹钟、checkpoint 清理与恢复。
    • 维护 keepalive 端口，用于定向消息与面板实例身份上报。
  • ReAct 推理循环（react-loop.js）
    • 对外入口 reactLoop 包装心跳与自动续跑；内部实现 reactLoopImpl 驱动多轮对话、工具调用、流式响应、循环检测、子任务计划与进度。
    • 负责消息清洗、上下文预算、Token 估算与截断、检查点持久化与恢复。
  • 工具执行器（tool-executor.js）
    • 统一工具定义与执行映射；支持 MCP/RAG 工具动态注册；内置网络访问白名单与安全提示。
    • 提供 executeTool、fetchWithRetry、审计记录 recordToolStats、appendAuditLog 等能力。
  • 本地 Agent 客户端（local-agent-client.js）
    • 封装 /api/* 与 WebSocket 通信；认证、超时、可达性缓存、MCP/RAG 相关接口。
  • 子 Agent 调度器（agent-dispatcher.js）
    • 基于 sessionId 派生子会话，限制嵌套深度，构建系统提示词并调用 ReAct 或直连非流式 API。
  • 流控制器（stream-controller.js）
    • SSE 流读取、空闲超时、流式中断与结束信号。
  • Token 记录器（token-recorder.js）
    • 统计每次 API 调用的输入/输出 Token 用量。
  • 活动存储（activity-store.js）
    • 追加审计日志、记录工具执行统计，供前端展示与诊断。

详细组件分析 ​

消息类型系统与数据流 ​

  • 用户消息（role=user）
    • 由侧边栏/面板构造，携带用户输入与可选附件（如截图、URL）。
    • 在 ReAct 循环中作为当前消息序列的一部分发送给 LLM。
  • 系统消息（role=system）
    • 包含全局提示、技能注入、子 Agent 系统提示词等。
    • 由 react-loop 与 agent-dispatcher 构建，影响模型行为与工具使用策略。
  • 工具调用消息（assistant.tool_calls）
    • LLM 返回的工具调用列表，包含工具名与参数（可能为字符串或对象）。
    • react-loop 解析参数、进行参数校验与确认门控，再交由 tool-executor 执行。
  • 工具结果消息（role=tool）
    • 工具执行结果回写至消息序列，供下一轮 LLM 决策。
    • 同时写入活动存储与审计日志，附带执行时间与状态。

意图识别与工具预筛选 ​

  • 工具预筛选（tool-preselector.js）
    • 根据当前上下文与用户输入，从全量工具集中筛选候选工具，减少 LLM 的干扰项。
    • 支持会话级强制下发的 MCP 工具补回（mergeForcedMcpTools），确保用户显式指定的工具不被丢弃。
  • 意图识别
    • 由 LLM 自身判断是否需要工具调用；若需要，则生成 assistant.tool_calls。
    • react-loop 对 tool_calls 进行解析与校验，必要时触发用户确认。

工具调用协调机制 ​

  • 参数验证
    • react-loop 解析 tool_call.arguments（字符串或对象），tool-executor 对必填字段进行校验，缺失时返回结构化错误。
  • 并行执行
    • 标记为 parallelizable 的工具可并行执行；react-loop 在子任务层面支持 sequential/parallel/dependency 策略。
  • 超时控制
    • 工具执行超时（TOOL_TIMEOUT_MS）、ReAct 循环总超时（loopTimeout）、流式空闲超时（STREAM_IDLE_TIMEOUT_MS）。
  • 错误重试
    • fetchWithRetry 对网络请求进行重试；工具执行失败时记录审计日志并向上抛出异常。
  • 确认门控
    • 敏感工具（如 manage_tab、agent_exec）需用户确认；未确认或超时则 fail-closed。

消息路由逻辑 ​

  • 本地工具调用
    • 由 tool-executor 直接执行，如浏览器 API、内存查询、RAG 检索等。
  • 远程 Agent 请求
    • 通过 local-agent-client 调用 /api/* 接口，支持文件读写、命令执行、MCP 工具调用。
  • 浏览器 API 调用
    • 通过 chrome.* API 直接操作标签页、书签、历史记录等。

消息状态管理 ​

  • 状态定义
    • processing：执行中
    • success：成功
    • error：失败
    • cancelled：取消
  • 状态转换规则
    • 工具执行开始时标记为 processing；完成后转为 success 或 error；用户取消或超时转为 cancelled。
    • 子任务计划（subtask_plan）豁免裁剪，确保历史视图可展示未执行的子任务。
  • 检查点与恢复
    • react-loop 定期保存 checkpoint（含 currentMessages、executionLog、subtaskPlan 等）；SW 重启后可自动续跑。

性能与优化 ​

  • 上下文截断
    • 使用 truncateByTokens、trimMessagesByBudget 控制消息长度，避免超出模型窗口。
  • 重复消息去重
    • 工具结果缓存（toolResultCache）在同一轮对话内避免重复执行相同工具。
  • 缓存机制
    • MCP 工具描述压缩（compressDescription、compressProperties、compressMcpSchema）减少上下文占用。
    • Agent 可达性缓存（_agentReachability）避免频繁健康检查。
  • 流式优化
    • stream-controller 支持空闲超时与增量推送，降低长连接资源占用。

故障排查指南 ​

  • SW 静默重启
    • 通过 keepalive 端口检测 SW 重启，恢复 checkpoint 并通知面板。
  • 工具执行超时
    • 检查 TOOL_TIMEOUT_MS 与 fetchWithRetry 配置，查看审计日志中的执行时间。
  • 确认对话框未弹出
    • 检查 keepalive 端口是否建立，面板是否可见，确认超时是否触发。
  • Agent 不可达
    • 检查 _agentReachability 状态，确认配对与令牌配置，查看 health check 日志。

结论 ​

本消息处理管道以 ReAct 推理循环为核心，结合工具预筛选、参数校验、并行执行、超时控制与确认门控，实现了从用户输入到 LLM 响应的完整闭环。通过本地工具、远程 Agent 与浏览器 API 的多路路由，以及审计日志与 Token 统计，系统在功能性与可观测性之间取得平衡。上下文截断、缓存与流式优化进一步提升了性能与稳定性。
