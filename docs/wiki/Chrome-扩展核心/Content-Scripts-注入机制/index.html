注入时机与作用域 ​

  • 加载时机：run_at: document_idle，表示 DOM 已构建完成，但图片等资源可能仍在加载。
  • 作用域：每个 frame 独立执行，all_frames: true 使子帧也拥有独立上下文。
  • 全局变量隔离：Content Script 不能直接访问页面 JS 变量；如需访问，必须通过消息通道或注入函数。
  • 跨 frame 限制：同源 iframe 可被读取，跨源 iframe 会触发权限异常并被捕获跳过。

核心组件总览 ​

Content Script 的核心职责是：

  • 提供统一的消息路由表，将后台或侧边栏请求分发到具体工具函数。
  • 封装页面读取、交互、提取、高级工具四类能力。
  • 新增：管理选择工具栏的顶层层显示和遮挡检测。
  • 维护元素引用注册表（ref），避免模型编写脆弱 CSS selector。
  • 支持 Shadow DOM 与 iframe 的深度查询与文本/HTML 聚合。
  • 提供样式注入、二维码生成、完成度校验等高级功能。

详细组件分析 ​

消息路由表与异步处理 ​

  • HANDLERS 是一个普通对象，键为消息类型，值为处理器函数。JavaScript 对象属性查找近似 O(1)，适合高频消息分发。
  • ASYNC_HANDLERS 是一个 Set，标记需要保持消息通道开放的异步工具。
  • TOP_FRAME_ONLY_TYPES 限制某些工具只在顶层 frame 响应，避免 iframe 抢先应答导致取证或 ref 解析混乱。

选择工具栏顶层层管理与遮挡检测 ​

新增 选择工具栏现已采用 Popover API 进入浏览器的 top layer，解决了传统 z-index 层级冲突问题，特别是在飞书等同文档应用中。

顶层层管理机制 ​

  • Popover API 集成：工具栏、溢出下拉菜单、结果面板和 Token 弹窗都使用 popover="manual" 属性，通过 showPopover() 和 hidePopover() 方法控制显示状态。
  • 回退机制：在不支持 Popover API 的环境中，自动回退到传统的 body 挂载 + 内联 display 方式。
  • 状态同步：使用 isFloatOpen() 函数确保 popover 状态与内联 display 状态保持一致。

遮挡检测与交互防护 ​

  • 智能遮挡检测：使用 elementFromPoint 在浮层关键位置进行命中测试，检测是否有宿主页面的高层级元素遮挡。
  • 临时遮挡处理：发现外来遮挡元素时，将其临时隐藏并记录原始 display 状态，在所有浮层关闭后自动恢复。
  • 自身元素豁免：通过 data-aih 标记识别扩展自身的浮层元素，避免误伤。
  • 交互窗口期保护：在用户与工具栏交互期间（mousedown→mouseup），防止宿主页面清选区导致的工具栏意外隐藏。

元素引用注册表与 ref 解析 ​

  • elementRegistry 是 Map<ref, {element, selector, tag, role, name}>，用于稳定引用元素。
  • elementRefMap 是 WeakMap<Element, ref>，跨快照复用编号，元素 GC 后编号退役。
  • resolveByRef 提供统一解析逻辑：注册表命中 → isConnected 检查 → selector 兜底重查 → 失败时返回结构化建议。

性能优化与内存管理 ​

  • 防抖节流：autoWaitAfterAction 使用最小等待和稳定计数，避免频繁轮询。
  • 批量操作：fillForm 批量填充表单字段，返回每个字段的处理结果。

安全考虑 ​

  • XSS 防护：sanitizeInjectedCss 过滤危险 CSS 构造，防止脚本执行和数据外泄。

故障排查指南 ​

  • Content Script 未注入：检查 manifest.json 的 content_scripts 配置，确认 matches 和 run_at。
  • 消息无响应：检查 HANDLERS 中是否有对应处理器，确认 ASYNC_HANDLERS 是否正确标记。
  • ref 解析失败：调用 query_elements 重新获取快照，检查 elementRegistry 是否过期。
  • Shadow DOM 无法访问：确认目标元素是否在 Shadow DOM 内，使用 deepQuerySelector 而非原生 querySelector。
  • 样式注入无效：检查 sanitizeInjectedCss 是否过滤了关键 CSS，确认 injectMode 是否合法。
  • 新增：工具栏显示问题，检查 Popover API 支持情况和遮挡检测逻辑。
  • 新增：z-index 冲突问题，确认工具栏是否正确使用 top layer 机制。

结论 ​

Content Script 注入机制通过 Manifest 配置、消息路由表、工具模块化和 Shadow DOM 穿透技术，实现了安全、高效、可扩展的页面交互能力。新增的选择工具栏顶层层管理机制进一步增强了在现代网页环境中的兼容性和用户体验。其设计强调：

  • 清晰的模块职责分离。
  • 稳定的元素引用机制。
  • 安全的样式注入和内容过滤。
  • 新增：先进的浮层层级管理和遮挡检测。
  • 高性能的异步处理和内存管理。
  • 完善的错误处理和故障恢复。

这些特性使得 Content Script 能够应对复杂的现代网页结构，同时保证安全性和性能，特别是在飞书等高复杂度宿主应用中表现出色。
