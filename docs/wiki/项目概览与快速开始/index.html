引言 ​

AI Helper 是一个让大语言模型真正操作网页的开源浏览器扩展。它不只是聊天，还能点击、填写表单、拖拽、上传文件、执行终端命令，并通过 MCP 协议动态扩展工具；可选本地 Agent 服务进一步提供文件读写、命令执行、长期记忆与知识库检索能力。

项目的核心价值可以概括为：

  • 可操作的 AI 助手：从“读网页”升级到“亲手操作网页”。
  • 双进程架构：Chrome 扩展端负责用户界面、页面交互与任务编排；独立 Node.js Agent 服务负责本地文件系统、命令执行、RAG 知识库和外部工具集成。
  • 可控且可扩展：内置 40+ 工具、Skill 技能系统、MCP 协议、多智能体协作、定时任务、审计日志与回收站等生产级能力。
  • 数据本地优先：知识库索引和本地文件操作运行在用户本机，便于隐私控制和离线场景。

当前文档以版本 2.3.1 为准，对应扩展端 package.json、Agent 包 ai-helper-agent、Manifest 版本号以及构建产物中的版本信息保持一致。

项目结构 ​

仓库采用“扩展端 + Agent 子工程”的组织方式：

  • 根目录是 Chrome 扩展工程，包含 Manifest V3 配置、Vite 构建脚本、背景脚本、内容脚本、侧边栏、选项页、共享模块和测试。
  • agent/ 是独立的 Node.js 代理服务工程，暴露 HTTP/WebSocket API，并提供 MCP、Skill、RAG、命令执行、文件管理、安全策略和日志子系统。
  • docs/ 存放产品文档、架构图、商店素材、文章和演示资源。
  • scripts/ 包含构建、打包、主题审计、图标生成等工程脚本。
  • test/ 是扩展端的单元测试与端到端测试；Agent 端测试位于 agent/test/。

Chrome 扩展端 ​

扩展端基于 Manifest V3，核心职责包括：

  • 定义扩展权限、内容脚本、Service Worker、选项页和侧边栏。
  • 管理用户会话、消息流、工具调用、截图、调试器、调度器和通知。
  • 通过 local-agent-client.js 封装与 Agent 的 HTTP/WebSocket 通信。
  • 提供内置 Agent 模板和多 Agent 调度能力。

本地 Agent 服务 ​

Agent 服务是扩展端能力的延伸，核心职责包括：

  • 启动 HTTP 服务器并路由 /api/* 请求。
  • 实现配对认证、健康检查、心跳、重启、更新和关闭。
  • 提供文件读写、目录列表、搜索、ZIP 打包、流式上传。
  • 执行系统命令，支持异步、等待、停止、分离模式。
  • 注册 MCP 工具、Skill 技能、RAG 知识库。
  • 输出结构化日志，支持审计与安全事件记录。

子代理调度与内置 Agent ​

扩展端支持主 Agent 派生子 Agent，用于分工完成复杂任务。调度器会：

  • 限制嵌套深度，防止 ReAct 循环无限递归。
  • 加载内置或自定义 Agent 定义。
  • 根据 Agent 的工具集合和技能提示词构建系统提示。
  • 使用派生 sessionId 隔离子 Agent 的信令与日志。
  • 对返回结果进行 token 预算截断。

性能与运行时约束 ​

  • Service Worker 生命周期：Chrome MV3 的 Service Worker 可能被空闲终止，需要保活机制；background 与 side panel 的消息传递是常见故障点。
  • Agent 进程重启：Agent 源码修改后必须重启进程，新接口才生效；服务端提供 /api/agent/restart 和 /api/agent/update 接口。
  • 请求超时：扩展端对 HTTP 请求设置默认超时，WebSocket 连接空闲超时由调用方统一管理，避免双重超时冲突。
  • Token 预算管理：扩展端按 Token 数而非消息数截断上下文，避免拆分 tool_calls 与 tool 消息。
  • 文件大小限制：Agent 对 JSON body、流式上传、文件读取分别设置大小上限，防止内存爆炸。

安装指南与系统要求 ​

官方安装渠道以 GitHub Releases 自动构建产物为主：

  • 从 Chrome Web Store 或 Microsoft Edge Add-ons 商店安装。
  • Chromium 用户可从 GitHub Releases 下载 ai-helper-*.zip，解压后在开发者模式下加载已解压扩展程序。
  • 开发者可从源码构建，但推荐普通用户直接使用官方构建产物。

系统要求：

  • Chrome / Edge / Chromium 114+，因为需要使用 Side Panel API。
  • 若启用本地 Agent 能力，需要 Node.js 环境安装 ai-helper-agent。

快速开始 ​

推荐的新手流程如下：

  1. 安装扩展：从应用商店或 GitHub Releases 安装。
  2. 打开侧边栏：使用快捷键或扩展图标打开侧边栏。
  3. 配置大模型厂商：在选项页添加 OpenAI 兼容端点和密钥，保存多个厂商配置。
  4. 可选：启动本地 Agent：一键安装代理端或使用命令行启动，将配对码填入选项页 → Agent。

扩展端与 Agent 端通信机制 ​

扩展端通过 local-agent-client.js 封装与 Agent 的通信，核心契约包括：

类别端点或行为用途
配对与会话/api/pair、/api/status、/api/status/detail配对认证、健康检查、平台信息

版本同步策略 ​

项目采用“扩展端与 Agent 端版本号保持同步”的策略：

  • 扩展端版本定义在根 package.json 和 manifest.json 中。
  • Agent 端版本定义在 agent/package.json 中。
  • 构建产物中的版本信息来自 src/config/version.json。
  • CI 通过 .github/workflows/release.yml 构建扩展 zip 并发布到 GitHub Releases。

建议维护者：

  • 升级版本时同步更新扩展端与 Agent 端版本号。
  • 发布前确认 npm run build:silent 能成功构建。
  • 用户安装时应优先选择与扩展版本匹配的 Agent 版本。

结论 ​

AI Helper 的核心价值在于把“聊天型 AI”升级为“可操作、可编排、可审计”的浏览器智能助手。其双进程架构清晰分离了浏览器上下文和本地系统能力，既降低了扩展端的权限风险，又保留了强大的本地执行能力。对于初学者，可以从网页信息提取和表单自动化入手；对于有经验的开发者，可以深入 MCP、Skill、RAG、多 Agent 协作和 Agent 安全策略。

在使用时，请始终注意：

  • 优先通过官方渠道安装扩展和 Agent。
  • 保持扩展端与 Agent 端版本一致。
  • 理解 Service Worker 生命周期和 Agent 进程重启约束。
  • 使用内置的安全策略、回收站和审计日志保护本地数据。
