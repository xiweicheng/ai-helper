引言 ​

本文件面向“信息提取工具”的技术文档，聚焦网页内容读取、结构化数据解析、表单与链接收集、元数据与结构化数据抽取、Shadow DOM 穿透以及搜索高亮等能力。该工具以 Chrome 扩展 Content Script 为核心运行环境，通过统一的 message 路由暴露给 background 侧工具调用，最终形成可扩展的信息提取管线。

项目结构 ​

信息提取相关代码主要位于 content 层：

  • page-extract.js：元数据、链接、表单、图片、Markdown/JSON 转换、iframe 内容、页面搜索。
  • shadow-dom-utils.js：Shadow DOM 与 iframe 的深度查询、文本/HTML 获取、选择范围处理。
  • page-tools.js：纯文本/富文本获取、表格提取、剪贴板、悬停、文本高亮等基础工具。
  • index.js：Content Script 入口，统一消息路由，将上层工具映射到具体实现。
  • browser-tools.js：background 侧对外暴露的工具定义（如 page_content、extract_data、search_in_page、iframe_content）。

核心组件 ​

  • 纯文本与富文本获取
    • 纯文本：基于 Shadow DOM 穿透的 deepGetText，支持 iframe 同源内容合并。
    • 富文本：基于 deepGetHtml 获取完整 HTML，可剥离样式；选区富文本通过 Range 克隆节点生成。
  • 表格数据解析
    • 单表提取：extractTable 支持 JSON/Markdown 输出，可选是否包含表头行。
    • 多表结构化：pageToJson 批量提取多个 table、ul/ol 列表、JSON-LD、article、Microdata。
  • 链接与表单
    • 链接：extractLinks 支持内/外链过滤、可选图片链接纳入。
    • 表单：extractForms 识别 input/textarea/select，记录 name/id/type/placeholder/required/selector。
  • 元数据与结构化数据
    • 元数据：extractMetadata 提取 title/description/keywords/author、Open Graph、Twitter Card、canonical、JSON-LD、Microdata。
  • Shadow DOM 穿透
    • 深度查询、文本/HTML 获取、选择范围、视口坐标计算、监听器管理。
  • 页面搜索与高亮
    • searchInPage 支持 plain/regex 模式、大小写敏感、上下文片段、结果高亮。

架构总览 ​

信息提取在 MV3 双进程架构中的调用路径如下：

  • Background 工具定义 extract_data、page_content、search_in_page、iframe_content 等。
  • Background 通过 chrome.runtime 向 Content Script 发送消息。
  • Content Script 的 index.js 根据 message.type 分发到对应处理器。
  • 处理器调用 page-extract.js 或 page-tools.js 的具体函数。
  • 底层依赖 shadow-dom-utils.js 完成跨 Shadow DOM/iframe 的访问。

详细组件分析 ​

纯文本与富文本获取 ​

  • 纯文本
    • 通过 getPageText 调用 deepGetText，自动合并 Shadow DOM 与同源 iframe 文本，并截取最大长度。
    • 可选择包含标题和链接摘要，便于快速概览。
  • 富文本
    • getFullHtml 基于 deepGetHtml 获取完整 HTML，可按需移除 style 属性以减少体积。
    • getSelectedContent 支持 text/html 两种格式，html 模式下通过 Range.cloneContents 保留富文本结构。

表格数据解析 ​

  • 单表提取 extractTable
    • 支持 selector 定位表格，遍历 tr/td/th 提取单元格文本。
    • 支持 includeHeaders 控制是否包含首行作为表头。
    • 输出格式：json（含 data、rowCount、columnCount）或 markdown（标准表格语法）。
  • 多表结构化 pageToJson
    • 批量扫描 root 下的 table、ul/ol、JSON-LD、article、Microdata。
    • 对每个 table 提取 headers 与 rows，限制 maxItems 避免过大结果。
    • 对 Microdata 去重（按 itemType + 前缀文本签名），避免重复条目。

Shadow DOM 穿透技术 ​

  • 深度查询
    • deepQuerySelector/deepQuerySelectorAll 优先遍历 shadowRoot 与 iframe，再回退到当前 root 的 query。
    • 支持 maxDepth 防止无限递归，visited 集合防止循环引用。
  • 文本/HTML 获取
    • deepGetText 合并 body.innerText 与 shadow tree textContent，拼接 iframe 内容。
    • deepGetHtml 合并 documentElement.outerHTML 与 shadow innerHTML，插入注释标记区分来源。
  • 选择范围与视口坐标
    • deepGetSelection 递归查找有焦点 frame 的选择范围。
    • getElementViewportPosition/getRangeViewportPosition 累加 iframe 偏移，确保坐标正确。
  • 监听器管理
    • attachSelectionListeners/removeSelectionListeners 为各 Shadow Root 注册 selectionchange。

页面搜索与高亮 ​

  • searchInPage
    • plain 模式：使用 window.find 辅助定位，TreeWalker 遍历文本节点匹配正则。
    • regex 模式：直接对 body.innerText 执行正则匹配，支持大小写敏感。
    • 支持 contextLength 提供命中前后上下文，maxResults 限制结果数量。
    • highlight=true 时，通过 Range 包裹命中文本节点，避免替换 innerHTML 导致事件丢失。

性能与优化建议 ​

  • 控制结果规模
    • 使用 maxItems/maxResults/maxLength 限制返回体量，避免大页面导致内存与传输压力。
  • 减少 DOM 遍历开销
    • 优先使用具体 selector 缩小范围，避免全页遍历。
    • 对 Shadow DOM/iframe 设置合理 maxDepth，避免深层树遍历。
  • 避免重复工作
    • 使用 seenUrls/seenJsonLd/seenMicrodata 去重，减少冗余解析。
  • 安全与稳定性
    • 对跨域 iframe 捕获异常并跳过，保证主流程稳定。
    • 高亮采用 Range 包裹文本节点，不替换 innerHTML，避免事件丢失与布局抖动。
  • 输出格式选择
    • 表格输出优先 JSON 用于程序处理，Markdown 用于人类阅读；按需选择。

故障排查指南 ​

  • 未找到目标元素
    • 检查 selector 是否正确，必要时使用 generateUniqueSelector 生成稳定选择器。
    • 确认是否在顶层 frame 调用需要 TOP_FRAME_ONLY_TYPES 的工具。
  • 跨域 iframe 不可访问
    • getIframeContent 会返回 accessible=false，这是预期行为；仅同源 iframe 可读取内容。
  • 搜索无结果
    • 确认 query/pattern 非空，plain/regex 模式差异；注意大小写敏感选项。
  • 高亮无效
    • 确保 highlight=true 且存在匹配；Range 高亮不会破坏事件监听。
  • 表单字段缺失
    • 确认字段为 input/textarea/select；动态生成的字段需在渲染后再次提取。
