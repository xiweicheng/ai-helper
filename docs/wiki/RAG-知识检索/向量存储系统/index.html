引言 ​

本技术文档聚焦 RAG 向量存储子系统，重点解释 Vectra 存储适配器的实现原理、嵌入模型集成方式、向量维度管理、批量插入优化、内存控制、存储引擎选择策略，以及索引重建、查询优化和运维维护要点。该系统采用双进程架构：Chrome 扩展端通过本地 HTTP/WebSocket 调用 Agent 端的 RAG 能力；Agent 端负责向量索引、检索、文档解析与嵌入生成。

项目结构 ​

RAG 相关代码集中在 agent/src/rag 下，按职责分层组织：

  • store：向量存储适配器（当前基于 vectra@0.15.0）
  • embedding：嵌入后端抽象与具体实现（本地 transformers.js、OpenAI 兼容 API）
  • document：文档加载、解析与分块
  • manager：知识库生命周期、导入、重建、注册表管理
  • searcher：检索器（向量 + 关键词增强、阈值过滤、旁路探测）
  • config：路径、默认配置、批大小等常量
  • detect：RAG 可选依赖运行时检测

核心组件 ​

  • VectraStore：封装 vectra LocalIndex，提供幂等建库、事务批量 upsert、向量检索、按文档删除、全量枚举与重建能力。
  • EmbeddingProvider：统一嵌入接口，区分查询侧与文档侧语义，自动选择本地或远端后端。
  • LocalEmbedding：基于 @huggingface/transformers 的本地嵌入，支持模型缓存、q8 量化、token 计数。
  • OpenAICompatEmbedding：对接 OpenAI 兼容 /embeddings 接口，支持 dimensions 透传与自动降级重试。
  • RagManager：知识库注册表、导入、重建、进度、并发控制、安全校验与错误上报。
  • Searcher：向量检索 + 关键词命中增强、阈值过滤、旁路探测。
  • chunker：段落优先的分块算法，保留原文偏移以预留 BM25 混合检索。
  • detect：在独立子进程中探测 vectra 与 transformers 可用性，避免主进程模块缓存污染。

详细组件分析 ​

Vectra 存储适配器 ​

VectraStore 是对 vectra@0.15.0 的轻量封装，关键约束与设计如下：

  • 幂等建库：先判断 isIndexCreated，再 createIndex，避免重复创建抛错。
  • 事务批量写入：使用 beginUpdate/endUpdate 包裹逐条 upsertItem，减少落盘次数；异常时 cancelUpdate 回滚。
  • 元数据设计：每个分块记录 documentId、chunkIndex、totalChunks、text、startPos、endPos，便于按文档检索、删除与未来 BM25 混合检索。
  • 查询接口：queryItems 为位置参数签名 (vector, query, topK, filter?, isBm25?)；返回统一结构并兜底空值。
  • 文档级操作：listDocumentChunks 按 chunkIndex 排序；removeDocument 通过 listItemsByMetadata + deleteItems 两步完成。
  • 重建接口：recreate 直接删除旧索引并重建，供模型变更场景使用。

嵌入模型集成 ​

EmbeddingProvider 是统一入口，根据配置自动选择后端：

  • 模式判定：显式 mode 优先；否则有 apiKey 走 openai-compat，否则 local。
  • 模型与维度：本地默认 Xenova/bge-small-zh-v1.5（512 维），远端默认 text-embedding-3-small；dimensions=0 表示不指定，由平台决定。
  • 非对称检索：查询侧自动附加 BGE 中文查询前缀，文档侧不加前缀，保证链路一致性。
  • Token 计数：仅本地后端暴露 countTokens，用于发现超窗风险。

LocalEmbedding 关键点：

  • 模型下载走 hf-mirror 镜像，缓存到 MODELS_DIR，避免 node_modules 内缓存被重装清空。
  • pipeline 单例 + 加载锁，避免并发重复加载；dtype=q8 量化降低内存占用。
  • countTokens 使用 tokenizer.model_max_length 作为窗口上限，truncation=false 真实统计 token 数。

OpenAICompatEmbedding 关键点：

  • endpoint 必须包含版本段，只拼接 /embeddings，避免双重版本段。
  • 支持 dimensions 透传；若服务端不支持（如固定维度模型返回 400），自动降级重试不带 dimensions。
  • 对返回顺序不稳定服务进行 index 排序，确保输入输出对齐。

文档分块与索引重建 ​

chunker 采用“段落优先 + 字符窗口兜底 + 重叠”策略：

  • 自然断点优先级：\n\n、\n、句号、感叹号、问号、分号等。
  • 安全边界：默认 chunkSize=400，overlap=80，避免超过模型最大输入导致静默截断。
  • 返回结构包含 startPos/endPos，为未来 BM25 混合检索预留。

RagManager 的重建流程保证原子性与可恢复性：

  • 临时目录构建新索引，完成后原子 rename 换入。
  • 重建清单 REBUILD_MANIFEST 记录目标配置与计数，崩溃恢复时可补提交注册表。
  • 失败清理策略：finalDir 存在则删 tmpRoot；不存在则保留现场供恢复逻辑处理。

检索与关键词增强 ​

Searcher 在向量检索基础上增加关键词通道：

  • 查询侧使用 embedQuery，确保与导入侧同一模型与前缀。
  • 候选集扩大为 topK*2，合并关键词命中后统一阈值过滤。
  • 关键词匹配：英文/数字按词边界，中文取最长命中片段；高频词剔除；命中加分封顶。
  • 旁路探测：过滤为空时放宽阈值，区分“无数据”与“被过滤”。

存储引擎选择策略 ​

当前仅实现 VectraStore 适配器，并通过 store/index.js 暴露统一工厂 createVectorStore。未来可通过 RAGAdapter 接入其他后端（如 Qdrant）。选择策略：

  • 当前默认 Vectra（本地磁盘索引），适合单机部署与离线环境。
  • 远端嵌入模型（OpenAI 兼容）可与本地索引组合，形成“本地索引 + 远端向量生成”的混合架构。
  • 检测机制 detect.js 在独立子进程探测 vectra 与 transformers 可用性，避免主进程模块缓存污染。

性能与调优 ​

  • 批量插入优化：使用 VectraStore.upsertChunks 的事务 beginUpdate/endUpdate 包裹逐条 upsertItem，显著减少落盘开销。
  • 嵌入批大小：EMBED_BATCH_SIZE=10，兼容部分平台单次批量上限（如阿里云百炼 text-embedding-v3/v4）。
  • 内存控制：
    • 导入体积上限：文本 10MB、文件 50MB，避免大内容驻留内存。
    • 分块大小限制：chunkSize 上限 2000，默认 400，配合 overlap=80 平衡召回与内存。
    • 本地模型 q8 量化，降低内存占用。
  • 查询优化：
    • 候选集扩大为 topK*2，关键词增强后再统一阈值过滤。
    • 关键词扫描上限 KEYWORD_SCAN_LIMIT=20000，防止大库卡顿。
    • 旁路探测区分“无数据”与“被过滤”，提升用户体验。
  • 索引重建：
    • 原子换入 + 重建清单，崩溃后可恢复。
    • 重建期间旧索引与旧配置保持可用，失败不影响线上。
  • 维度管理：
    • EmbeddingProvider.dimensions 与 Searcher 维度校验，避免模型/配置变更后产生无意义结果。
    • OpenAICompatEmbedding 自动降级 dimensions 参数，兼容固定维度模型。

故障排除指南 ​

常见问题与解决思路：

  • 内存溢出（OOM）：
    • 检查导入体积是否超过 INGEST_MAX_TEXT_BYTES/INGEST_MAX_FILE_BYTES。
    • 调整 chunkSize 与 overlap，避免过大分块。
    • 本地模型启用 q8 量化，减少内存占用。
  • 索引损坏或重建中断：
    • 查看 .rebuild_<collectionId> 与 rebuild_manifest.json，确认是否处于半完成状态。
    • 使用 recoverInterruptedRebuilds 自动收敛；必要时手动回滚 index_backup。
  • 数据同步失败：
    • 检查 collections.json 权限是否为 0o600，避免多进程并发写冲突。
    • 确认 _updateRegistry 互斥锁未阻塞，观察日志中是否有长时间等待。
  • 向量维度不匹配：
    • 切换模型或 dimensions 后需重建索引；Searcher 会抛出 embeddingDimensionMismatch。
  • 远端嵌入 API 失败：
    • 检查 endpoint 是否包含版本段，apiKey 是否正确。
    • 若服务端不支持 dimensions，自动降级重试；仍失败需检查服务端响应。
  • 依赖不可用：
    • 运行 detectRagAvailable 或 runRagProbe，查看 errorSummary。
    • 确保 Node 版本 >=22，vectra 与 @huggingface/transformers 已安装。
