引言 ​

本文件聚焦于 ReAct 推理循环的实现，围绕“思考-行动-观察”主循环、工具调用协调、循环检测、子任务管理、反思机制以及错误恢复展开。重点解析 reactLoopImpl 的核心流程，包括消息处理、工具执行调度、结果缓存、上下文压缩、检查点持久化与恢复；并说明 shouldReflect、buildReflectionPrompt、reflectOnResult 的反思策略；同时梳理 loop-detector 的多模式检测（重复操作、元素枚举、振荡、失败作用域、无进展滚动、预算控制）。文档还提供扩展新工具类型、自定义 ReAct 行为与优化推理性能的实践建议，以及常见问题的定位方法。

项目结构 ​

ReAct 推理循环位于扩展端 background 脚本中，由多个模块协作完成：

  • react-loop.js：ReAct 主循环、工具执行编排、子任务派发、上下文压缩、检查点、反思入口。
  • react-reflection.js：后置反思与子任务反思的 Prompt 构建、API 调用与结果解析。
  • loop-detector.js：多模式循环检测器（纯逻辑，browser-free）。
  • tool-executor.js：工具定义、动态注册（MCP/RAG）、执行分发与超时。
  • subagent-depth.js：统一的子代理/子任务嵌套深度计数器。
  • completion-verifier.js：完成度校验编排层（取证、评审、重跑指令构造）。

核心组件 ​

  • ReAct 主循环（reactLoopImpl）
    • 负责消息预处理、API 调用、工具执行、结果缓存、上下文压缩、检查点保存与恢复、反思触发。
  • 工具执行器（tool-executor）
    • 提供工具定义、动态注册（MCP/RAG）、参数解析、执行分发、超时与确认门控。
  • 循环检测器（loop-detector）
    • 六模式检测：重复、ref 枚举、ABAB 振荡、失败作用域、导航重置、无进展滚动，并提供软提醒与硬停。
  • 反思机制（react-reflection）
    • 后置反思 with 评估/修订解耦，子任务反思独立评分与可选修订。
  • 完成度校验（completion-verifier）
    • 客观断言取证、命令/文件类判据、DOM 类判据、重跑指令生成。
  • 嵌套深度（subagent-depth）
    • plan_task 与 dispatch_task 共享深度计数，防止递归爆炸。

详细组件分析 ​

reactLoopImpl：思考-行动-观察主循环 ​

  • 消息处理
    • 应用不可信内容安全合约、过滤内部字段、剥离历史图片、上下文压力评估与主动裁剪、任务锚点与便签瞬态回注。
  • API 调用
    • 流式与非流式统一封装，带外层超时 watchdog、重试回调、usage 统计与 token 校准。
  • 工具执行调度
    • 按 tool_calls 声明顺序分组并行（PARALLELIZABLE_TOOLS），plan_task 独占语义，clarify_question 暂停整体计时。
  • 结果缓存
    • 单次循环内 Map 缓存，TTL=60s，并行工具命中仍喂入检测器避免重复检测失效。
  • 执行日志与快照
    • 增量发送 EXECUTION_STATUS_UPDATE，内存窗口裁剪，checkpoint 节流保存。
  • 子任务管理
    • plan_task 拆解后 executeSubtasks，支持 sequential/parallel/dependency 策略，失败策略 stop/continue/skip，回滚已完成子任务。
  • 反思入口
    • 最终答案完成后根据 shouldReflect 决定是否进行后置反思。

工具调用协调机制 ​

  • 用户确认门控
    • 敏感工具/action 级确认，支持“当前任务放行”，会话级关联键防串扰，面板呈现回执后才开始倒计时。
  • 并行执行
    • 连续可并行工具合并为一组 Promise.all，非并行工具单独执行；plan_task 会中断同轮后续工具。
  • 结果缓存
    • 仅并行工具缓存，TTL=60s，命中时仍记录 loopRecords 以维持重复检测能力。
  • 工具观察提示
    • 失败/空结果/超大结果时追加规则提示，引导模型自我调整，零额外 LLM 调用。

循环检测算法（多模式） ​

  • 重复检测（窗口制）
    • 相同 toolName+args+result 在窗口内重复达到阈值即软提醒，超过停止阈值硬停。
  • ref 枚举循环
    • query_elements 专用：非法页、重读且结果不变、乱序跳页累计可疑计数，超阈硬停。
  • ABAB 振荡
    • 最近尾迹 A,B,A,B 交替判定，全交替硬停，部分交替软提醒。
  • 失败作用域
    • 白名单工具（interact_element/fill_form/select_dropdown/keyboard_input/file_upload）对同一目标连续失败达阈值硬停。
  • 无进展滚动
    • scroll_to(target=top/bottom/coordinates) 报告未移动多次硬停。
  • 预算控制
    • 全局提醒预算达到阈值硬停，避免多模式软提醒累积导致长时无进展。

子任务管理与执行 ​

  • 策略
    • sequential/parallel/dependency（拓扑排序），失败策略 stop/continue/skip，最大并发默认 3。
  • 防重放
    • 成功子任务即时记入进度 Map，恢复后跳过重放，写操作二次执行风险规避。
  • 回滚
    • stop 策略下逆序回滚已完成子任务，记录 rolledback/rollback_failed 日志。
  • 超时与预算
    • 子任务整体超时上限 15 分钟，受父任务剩余时间约束；computeSubtaskLoopTimeoutMs 保证最小 60s。
  • 完成度校验
    • Phase B：子任务成功当场取证（DOM/命令/文件），可配置 rerunEnabled 驱动重跑回路，严格真子集判定防振荡。

反思机制：shouldReflect / buildReflectionPrompt / reflectOnResult ​

  • shouldReflect
    • 子任务内部不触发；存在 plan_task、工具失败、或工具调用次数≥2 时触发。
  • buildReflectionPrompt
    • 提取用户问题、工具执行详情、计划信息，输出结构化 JSON 评分维度。
  • reflectOnResult
    • 评估/修订解耦：先轻量评估，低于质量阈值才发起修订调用；支持多轮，记录 reflectionLog，最终决策 passed/revised/needs_improvement。

错误恢复与检查点 ​

  • 检查点保存
    • 初始、plan_task 完成、tools_completed、final_answer、error/user_cancelled 等时机保存；节流 1500ms，子任务不保存。
  • 恢复流程
    • resumeReactLoopFromCheckpoint 读取 IndexedDB，清理不完整消息配对，注入恢复提示，重新调用 reactLoop，携带 checkpoint 状态（taskState/subtaskPlan/subtaskProgress/notesState）。
  • 异常处理
    • AbortError 传播取消语义；StreamIdleTimeout 本地化提示；HTTP 400 上下文超限自愈（最多 3 次，逐档更激进裁剪）。

性能与预算控制 ​

  • Token 预算与上下文压缩
    • 动态计算 reactTokenBudget（上下文窗口 - 实际 system prompt - 工具定义 - 输出预留 - 安全余量），阈值 80% 触发批量压缩，保留最近 2 轮原文，其余轮次一次 LLM 调用结构化摘要；仍超标则权重裁剪（反思 > 工具结果 > 普通消息）。
  • 工具结果截断与卸载
    • MAX_TOOL_RESULT_TOKENS=6000，优先卸载到 Agent workspace（保留完整可回读），失败则智能截断。
  • 流式空闲超时
    • StreamIdleTimeout 保护，前端显示“思考中”状态行就地更新为“重试中”。
  • 子任务并发与超时
    • dispatchSubtasksParallel 使用 Set 跟踪在途任务，size 恒等于真实并发数；computeSubtaskLoopTimeoutMs 限制子任务整体超时。

调试与故障排查 ​

  • 常见问题
    • 工具确认弹窗不出现：检查 keepalive port 是否存在、INTERACTION_DISPLAYED 回执是否送达、会话归属匹配。
    • 子任务卡住：检查子任务是否被 cancel、是否触发循环检测硬停、是否完成度校验 rerunEnabled 配置不当。
    • 上下文超限 400：查看 contextHealAttempts 自愈次数与 trimMessagesByBudget 裁剪比例。
    • MCP 工具未生效：确认 loadMcpTools 是否成功、服务器是否禁用、mcpToolIds 去重。
  • 诊断要点
    • 执行日志节点 status 是否为 processing/failed/cancelled，observation 是否被截断。
    • loop-detector 的 nudge/stop 原因与 params。
    • reflection 的 overallScore 与 decision（passed/revised/needs_improvement）。
    • checkpoint 是否落盘成功（read-back 验证）。

结论 ​

ReAct 推理循环通过 reactLoopImpl 将“思考-行动-观察”主循环与工具执行、循环检测、子任务管理、反思机制与错误恢复有机整合。其设计强调：

  • 安全性：敏感操作确认、不可信内容包装、内网访问门控。
  • 鲁棒性：检查点持久化与恢复、上下文超限自愈、流式空闲超时。
  • 可扩展性：MCP/RAG 工具动态注册、完成度校验编排、反思策略解耦。
  • 性能：Token 预算与批量压缩、工具结果卸载、并行子任务并发受限。
