引言 ​

本文件面向“上下文管理系统”的完整技术文档，聚焦以下目标：

  • 解释上下文压缩算法：truncateByTokens、truncateContentSmart、assessContextPressure。
  • 说明 Token 计数与优化机制：estimateMessagesTokens、getCalibratedTokens、trimMessagesByBudget。
  • 描述记忆存储机制：短期记忆（会话历史）、长期记忆（Agent 端）与 scratchpad 便签系统。
  • 解释会话状态管理：生命周期、持久化与恢复。
  • 说明上下文摘要生成：summarizeRoundsBatch 批量摘要与 extractAllRounds 轮次提取。
  • 提供可操作的优化建议、自定义策略思路与内存泄漏防护要点。

本项目为双进程架构：Chrome 扩展端（Manifest V3，src/）与独立本地代理端 Agent（Node.js）。扩展侧负责 UI、上下文估算、压缩触发与消息组装；Agent 侧负责长期记忆、RAG、工具执行与安全控制。两端通过本地 HTTP/WebSocket 通信。

项目结构 ​

上下文管理相关代码横跨共享层、后台服务层与侧边栏 UI 层：

  • 共享层 token-counter.js：Token 估算、截断、预算分配、压力评估、消息过滤与清洗。
  • 共享层 context-usage.js：发送路径的历史选择、压缩注入与占用计算。
  • 后台层 context-compactor.js：手动压缩摘要生成。
  • 后台层 context-summarizer.js：批量对话轮次摘要生成。
  • 后台层 react-loop.js：ReAct 主循环中的上下文压力检测、动态裁剪与摘要降级。
  • 侧边栏 context-indicator.js：上下文指示器、手动压缩流程与摘要查看。
  • 侧边栏 session-manager.js / session-manager-ui.js：会话创建、切换、保存、删除与 UI 交互。
  • 工具定义 agent-tools.js：take_note 便签工具定义，支撑 scratchpad。

详细组件分析 ​

Token 估算与截断 ​

  • estimateTokens：按中文/英文字符比例估算单段文本 token。
  • estimateMessagesTokens：支持字符串与 multipart content（含 image_url），避免 Base64 高估；附加 tool_calls/tool_call_id/reasoning_content 字段估算。
  • truncateByTokens：保留头部 70% + 尾部 30%，插入省略提示。
  • truncateContentSmart：智能类型识别（HTML/JSON/文本），分别采用 body 优先、顶层 key 摘要、固定头尾策略。
  • filterApiMessages：剥离内部字段、修复 assistant(tool_calls)+tool 配对、清理图片 URL 内部字段、清洗非法 Unicode。
  • sanitizeImageUrlsForApi：仅保留标准 url 字段，避免非标准字段进入请求体。
  • stripImagesFromContent：移除多模态 content 中的图片，仅保留文本。

预算分配与压力评估 ​

  • getContextWindow：优先级为自定义模型映射 > 全局覆盖 > 内置映射 > default。
  • getMessageBudget：contextWindow - SYSTEM_PROMPT_BUDGET - estimateToolsTokens(toolCount) - OUTPUT_BUDGET。
  • assessContextPressure：ratio < 0.7 safe；< 0.9 warning；否则 critical。

消息预算裁剪与规则摘要 ​

  • trimMessagesByBudget：从旧到新移除消息，保证 assistant(tool_calls)+tool 配对连丢；预估算逐条贡献并增量扣减，避免 O(n²)。
  • generateMessagesSummary：从被裁消息中提取最近 user 问题与使用的工具名，生成结构化摘要。

上下文使用计算与发送路径 ​

  • selectHistoryForSend：记忆层（isolateChat=false 不携带历史）→ 窗口层（maxMemoryMessages）→ 压缩层（upToMessageId 之后参与发送）→ 预算层（从后往前保留至 historyBudget）。
  • appendCompactionToSystemPrompt / applyCompactionInjection：将压缩摘要注入 system prompt，受 preserveSystem 保护。
  • computeContextUsage：与发送路径同源的计算口径，输出 usedTokens、contextWindow、ratio、level 与 breakdown。
  • assembleCompactionMaterial：点击“压缩上下文”时，按记忆设置窗口选出全部携带内容作为素材，不经发送预算裁剪。

手动压缩与批量摘要 ​

  • 手动压缩：context-indicator.runCompaction 收集素材 → 调 background COMPACT_CONTEXT_SUMMARY → 写入 state.activeCompaction → 持久化。
  • 批量摘要：context-summarizer.summarizeRoundsBatch 构建 transcript（priorSummary + rounds），对超长 transcript 做 truncateByTokens 封顶，调用 LLM 输出结构化摘要；失败返回 null，由上层降级到权重裁剪。
  • 轮次提取：extractAllRounds 扫描 assistant(tool_calls) 起始的完整轮次，包含其后所有 tool 消息。

记忆存储机制 ​

  • 短期记忆：浏览器侧 side panel 的 state.messageHistory 与 IndexedDB 会话数据（通过 session-manager.js 封装）。
  • 长期记忆：Agent 端 memory/global-memory.json，跨会话持久化；扩展侧通过工具调用与上下文压缩沉淀 summary 条目（tags 含 compaction + session:<id>）。
  • Scratchpad 便签：take_note 工具在 ReAct 循环中维护 notesState（FIFO 限制长度），并在每轮末尾以锚点消息形式注入 filteredMessages，使关键发现跨越压缩存活。

  • 生命周期：newSession → switchToSession → saveCurrentSession → deleteSession/archive/restore/duplicate。
  • 持久化：chrome.storage.local 用于 completedSessionIds；IndexedDB 用于会话数据（load/save/switch/delete/reorder/import/export）。
  • 恢复：restoreCompletedSessions 在 Side Panel 初始化时恢复完成标记；switchToSession 恢复 activeSessionId 与对应历史。

性能与内存优化 ​

  • 工具定义 token 缓存：rawToolTokens 在 ReAct 主循环外只算一次，getCalibratedTokens 仍逐轮应用（因校准因子随实际用量演进）。
  • trimMessagesByBudget 已优化为逐条贡献预估算 + 增量扣减，避免 O(n²)。
  • 图片 token 估算按分辨率 tile 公式，避免 Base64 字符串高估约 20 倍。
  • 实时校准 updateCalibration 使用 EWMA 平滑，样本不足时不生效，防止异常波动。
  • 长任务中 stripImagesFromContent 历史消息剥离，减少不必要传输。
  • 建议：
    • 合理设置 maxMemoryMessages，避免过长历史常驻内存。
    • 开启 persistSummaryToMemory，让压缩摘要沉淀为长期记忆，降低重复压缩成本。
    • 控制 take_note 数量（NOTES_MAX_STORED FIFO），避免便签无限增长。
    • 定期归档/删除会话，释放 IndexedDB 空间。

故障排查指南 ​

  • 压缩失败：
    • 检查 API 配置是否缺失（config_missing）。
    • 确认 isolateChat 是否为 true（memory_off）。
    • 确认正在生成回复时不可压缩（generating）。
  • 压缩点失效：
    • 当 upToMessageId 对应的消息被删除，本次发送会忽略压缩；可在详情弹窗中移除失效记录。
  • 上下文超限：
    • 观察 assessContextPressure 等级；critical 或超过 85% 会触发 trimMessagesByBudget。
    • 若批量摘要失败（summarizeRoundsBatch 返回 null），会回退到权重裁剪。
  • 工具调用配对错误：
    • filterApiMessages 会校验 assistant(tool_calls).id 与 tool.tool_call_id 严格匹配，不匹配会清除或剔除未匹配的 tool_calls。
  • 图片导致的高估：
    • 确保 stripImagesFromContent 在历史消息中正确剥离 Base64。
    • 使用 sanitizeImageUrlsForApi 清理非标准字段。

结论 ​

本系统的上下文管理围绕“精准估算 + 智能截断 + 预算控制 + 摘要降级”展开：

  • 通过 estimateMessagesTokens 与 getCalibratedTokens 提升估算准确度。
  • 通过 truncateByTokens/truncateContentSmart 实现可控的内容保留。
  • 通过 assessContextPressure 与 trimMessagesByBudget 实现主动防御。
  • 通过 summarizeRoundsBatch 与 extractAllRounds 实现高效批量摘要。
  • 通过 session-manager 与 IndexedDB 保障会话状态持久化与恢复。
  • 通过 scratchpad 便签与 ReAct 锚点注入，使关键信息在压缩中存活。

附录：实践示例与最佳实践 ​

  • 优化上下文使用：

    • 使用 compressQuotedContext 压缩引用内容，避免大段内容永久占据上下文。
  • 自定义压缩策略：
