引言 ​

本架构文档面向 AI Helper 2.3.1 的双进程系统：Chrome 扩展端（Manifest V3 Service Worker，位于 src/）与独立本地 Agent 服务（Node.js，入口为 agent/src/server.js）。两端版本号保持同步，通过 HTTP 与 WebSocket 通信契约协作。扩展端负责用户界面、浏览器能力、会话编排和 ReAct 执行循环；Agent 端提供文件系统、命令执行、MCP 工具、技能、长期记忆与 RAG 等本地能力。

关键约束包括：

  • MV3 Service Worker 可被 Chrome 空闲回收，必须通过 keepalive 长连接保活，并通过 checkpoint 实现自动续跑。
  • 扩展端与 Agent 端的认证基于配对码 + Bearer Token，所有需认证接口均要求 Authorization: Bearer <token>。
  • Agent 端修改源码后必须重启进程，新接口才生效。
  • 安全边界由扩展权限模型、CORS 白名单、路径沙箱、命令分级策略共同构成。

项目结构 ​

仓库采用“扩展端 + 独立 Agent 包”的双根结构：

  • 扩展端根目录包含 Manifest、Vite 构建配置、background、content、side_panel、options、shared、storage 等模块。
  • Agent 子目录是一个独立的 npm 包 ai-helper-agent，提供 CLI、HTTP/WebSocket 服务器、安全控制、MCP、Skill、RAG、Memory 等子系统。

核心组件 ​

  • Chrome 扩展端 Service Worker：作为扩展后台进程，承担消息路由、侧边栏生命周期、ReAct 循环调度、工具预筛选、Token 记录、自动续跑、通知与面板可见性判定。
  • 本地 Agent 客户端：封装与 Agent 的 HTTP/WebSocket 调用，管理多代理配对、可达性缓存、请求超时、语言头、Bearer Token 注入。
  • Agent 服务端：提供配对、健康检查、文件操作、命令执行、MCP、Skill、RAG、Memory 等 API，并实现 CORS、认证、限流、重启/更新流程。
  • 安全与认证模块：Agent 端维护配对码轮换、Token 校验、路径白名单、硬阻止目录、符号链接防护、命令分级与安全日志。
  • UI 主题与国际化：扩展端使用 CSS Token 体系支持亮/暗/跟随系统三态；i18n 覆盖扩展 _locales/ 与 Agent agent/src/locales。

架构总览 ​

AI Helper 的整体交互分为三层：

  1. 用户界面层：Side Panel 与 Content Script 负责用户输入、页面上下文、截图、书签、历史、知识库选择等。
  2. 扩展后台层：Service Worker 维护会话状态、ReAct 循环、工具执行、Agent 客户端、通知与面板保活。
  3. 本地 Agent 层：提供文件系统、命令执行、MCP、Skill、RAG、Memory 等能力，并对访问进行安全校验。

详细组件分析 ​

Chrome 扩展端 Service Worker 与保活机制 ​

Service Worker 是 MV3 扩展的核心后台进程，具有以下职责：

  • 初始化 i18n、定时任务、自动续跑、DB 自检、旧格式迁移。
  • 管理 Side Panel 打开/关闭、作用域模式、Tab 分组、快捷键切换。
  • 维护 keepalive 端口注册表，防止 SW 空闲被 Chrome 回收。
  • 检测 SW 重启并通知 Side Panel，携带 checkpoint 元数据供恢复。
  • 处理面板断开延迟复核，避免误报任务仍在执行。

Init --> Keepalive["注册 keepalive 端口监听"]

Agent 服务端与认证流程 ​

Agent 服务端提供 HTTP 路由与 WebSocket 支持，核心流程包括：

  • 配对接口 /api/pair：验证一次性配对码，返回 Bearer Token。
  • 健康检查 /api/status：无需认证，仅返回平台信息。
  • 认证拦截：除少数公开接口外，所有请求需携带 Authorization: Bearer <token>。
  • 心跳 /api/heartbeat：刷新最后认证时间，维持插件在线状态。
  • 重启/更新：受冷却时间与防重入保护，支持两阶段进程替换。

安全边界与沙箱隔离 ​

Agent 端的安全策略包括：

  • CORS 限制：仅允许 chrome-extension://<id> 来源跨域读取响应。
  • 路径沙箱：硬阻止 .ai-helper-agent 敏感文件/目录，工作目录放行，其他路径需命中 allowedPaths。
  • 符号链接防护：使用 realpath 解析真实路径后再做白名单与硬阻止检查。
  • 命令分级：命令执行需经过安全分级与用户确认，支持强制模式与超时控制。
  • 上传大小限制：JSON body 与 multipart 上传均有上限，防止内存耗尽。

性能与可扩展性 ​

  • Service Worker 保活：通过 keepalive 长连接防止空闲回收，结合闹钟与 checkpoint 实现自动续跑，避免长时间任务中断。
  • 请求超时与 AbortController：扩展端为每个会话创建 AbortController，支持用户取消与工具级终止等待。
  • Agent 端限流与防重入：重启/更新接口有冷却时间与操作进行中标志，防止 DoS 与并发写冲突。
  • 主题与国际化：CSS Token 体系支持亮/暗主题，i18n 覆盖扩展与 Agent 两端，避免硬编码色值与文案。
  • 可扩展点：MCP 工具注册、Skill 加载、RAG 索引、Memory 服务均可按需启用或禁用，不影响核心文件与命令执行。

故障排查指南 ​

常见故障与定位建议：

  • Side Panel 无法打开：检查 Service Worker 是否被回收，确认 keepalive 端口是否正常建立；查看 chrome.sidePanel.open() 是否在用户手势同步栈内调用。
  • Agent 未配对：确认 /api/pair 是否成功，检查配对码是否过期或被锁定；查看 agent/src/auth.js 中的失败计数与锁定逻辑。
  • 请求超时：检查 local-agent-client.js 中的超时设置与网络可达性；确认 Agent 服务是否运行在预期端口。
  • 路径访问被拒：检查 agent/src/security.js 的路径白名单与硬阻止目录；确认工作目录与 allowedPaths 配置。
  • SW 重启导致任务中断：查看 Side Panel 是否收到 SW_RESTARTED 消息，并根据 checkpoint 元数据决定是否继续执行。
