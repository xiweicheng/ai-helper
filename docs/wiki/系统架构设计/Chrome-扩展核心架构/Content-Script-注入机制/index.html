Content Script 生命周期与注入时机 ​

注入配置 ​

Manifest 中 Content Script 的关键配置如下：

  • matches: <all_urls>，表示对所有网页生效。
  • js: 先注入 libs/qrcode.min.js，再注入 libs/marked.min.js，最后注入 src/content/index.js。
  • css: 注入 styles/styles.css。
  • run_at: document_idle。
  • all_frames: true，允许在所有 frame 中注入。
  • match_about_blank: true，兼容空页面。
  • match_origin_as_fallback: true，同源回退匹配。

这意味着 Content Script 在文档空闲阶段注入，而不是更早的 document-start。该选择有利于：

  • 页面结构基本可用，减少因 DOM 未就绪导致的查询失败。
  • 降低对首屏渲染的阻塞风险。
  • 更适合以“读取页面 + 用户交互”为主的扩展场景。

但这也意味着：

  • 如果需要在极早期拦截网络或修改初始 DOM，应改用 document-start 并谨慎评估性能。
  • 当前实现依赖 document.body、chrome.runtime、window.top 等运行时对象存在。

运行期生命周期 ​

Content Script 启动后执行以下关键步骤：

  1. 导入各模块工具函数。
  2. 注册 i18n 翻译键。
  3. 初始化国际化。
  4. 打印调试日志，记录 URL、是否顶层 frame、是否存在 document.body。
  5. 注册全局快捷键：组合键打开扩展 action、全页截图、区域截图。
  6. 构建消息路由表 HANDLERS 和异步工具集合 ASYNC_HANDLERS。
  7. 定义仅顶层 frame 响应的类型集合 TOP_FRAME_ONLY_TYPES。
  8. 在扩展上下文有效时注册 chrome.runtime.onMessage。
  9. 注册全局错误和未处理 Promise 拒绝过滤器，屏蔽 Extension context invalidated。
  10. 等待 i18n 就绪后初始化选区工具栏。
  11. 提供区域截图选择函数，供消息路由调用。

消息路由表与异步处理模型 ​

路由表设计 ​

index.js 使用对象字面量作为消息路由表，键为消息类型，值为处理器函数。这种设计具备以下特点：

  • 查找复杂度接近 O(1)。
  • 新增工具只需添加键值对，无需遍历数组。
  • 分类清晰：页面读取、页面交互、表单输入、信息提取、媒体输出、异步工具、区域截图、页面度量。

路由表覆盖的主要类别包括：

  • 页面读取：获取页面文本、完整 HTML、查询交互元素、获取选中内容、子帧快照采集。
  • 页面交互：按 ref/text/selector 交互、填充表单、滚动到目标。
  • 表单输入：键盘输入、文件上传。
  • 信息提取：表格、元数据、链接、表单、图片、页面搜索、iframe 内容、滚动收集。
  • 媒体输出：存储管理、CSS 注入、完成度校验。
  • 异步工具：剪贴板、等待元素、下拉选择、二维码、区域截图。
  • 页面度量：页面宽高指标。

异步处理模型 ​

异步工具分为两类：

  1. 显式标记为异步的工具：COPY_TO_CLIPBOARD、PASTE_FROM_CLIPBOARD、WAIT_ELEMENT、SELECT_DROPDOWN、QRCODE、START_REGION_SELECTION，以及 INTERACT_ELEMENT、SCROLL_TO、KEYBOARD_INPUT 的某些分支。
  2. 返回 Promise 的处理器。

消息监听器统一处理同步和异步返回值：

  • 如果消息类型属于 ASYNC_HANDLERS，或者返回值是 Promise，则保持消息通道开放，并在 Promise resolve 后回复。
  • 否则直接同步回复。

错误传播机制 ​

错误传播遵循统一模式：

  • 工具函数通常返回 { success, data?, error?, message? } 结构。
  • 路由层不吞掉业务错误，而是将工具返回的错误原样传给调用方。
  • 对于扩展上下文失效，Content Script 通过全局 error 和 unhandledrejection 事件过滤，避免控制台刷屏。
  • 部分工具在 try-catch 中捕获异常，并转为结构化错误响应。

需要注意：

  • 异步工具的错误由 Promise reject 或工具内部返回 { success: false, error } 表达。
  • 路由层对 Promise 使用 Promise.resolve(result)，因此即使处理器返回 rejected Promise，也会被包装成 resolved Promise，最终通过 sendResponse 传递；若需要区分 reject 与业务错误，应在工具层明确返回结构化错误。

基础读取工具 ​

page-tools.js 提供轻量、稳定的页面读取能力：

  • getPageText：提取标题、URL、正文、词数、可选标题和链接。
  • getFullHtml：提取完整 HTML，支持去除内联样式和长度限制。
  • getSelectedContent：读取用户选区，支持 text/html 两种格式。
  • extractTable：解析表格为 JSON 或 Markdown。
  • copyToClipboard / pasteFromClipboard：剪贴板读写，带降级方案。
  • hoverElement：触发鼠标悬停，并自动检测导航或 DOM 变化。
  • highlightText：移除旧高亮、插入样式、遍历文本节点包裹高亮 span。

信息提取工具 ​

page-extract.js 负责结构化信息抽取：

  • extractMetadata：meta、Open Graph、Twitter Card、JSON-LD、Microdata。
  • extractLinks：链接列表，支持内外链过滤和图片链接。
  • extractForms：表单字段序列化，包含 input、textarea、select。
  • extractImages：图片列表，支持尺寸过滤、背景图、下载。
  • pageToMarkdown：HTML 转 Markdown。
  • pageToJson：结构化表格、列表、JSON-LD、文章、Microdata。
  • getIframeContent：同源 iframe 内容读取。
  • searchInPage：页面内搜索，支持 plain/regex、大小写、上下文、高亮。

交互查询与操作 ​

page-interaction.js 和 interaction-tools.js 共同构成页面自动化能力：

  • queryInteractiveElements：生成可交互元素树快照。
  • collectSnapshotOps：采集 overlay tree、body tree、frame info。
  • interactByRef：按 ref 点击、悬停、输入。
  • clickElement：点击元素并自动等待稳定。
  • fillForm：多字段表单填充，支持原生控件、contenteditable、checkbox/radio/select。
  • scrollToPosition：滚动到顶部、底部、坐标或元素。
  • waitForElement：等待元素出现、消失、可见、隐藏。
  • keyboardInput：模拟按键和文本输入。
  • fileUpload：通过 DataTransfer 设置文件。
  • clickByText：按文本查找并点击或悬停。
  • selectDropdown：原生 select 或自定义下拉选择。
  • manageStorage：localStorage/sessionStorage 的 get/set/remove/clear。

Shadow DOM 穿透与跨边界访问 ​

设计目标 ​

现代前端大量使用 Shadow DOM 和 iframe，普通 querySelector 无法穿透。shadow-dom-utils.js 提供统一穿透能力：

  • 递归遍历 shadowRoot。
  • 尝试访问同源 iframe 的 document。
  • 跨域 iframe 被安全跳过。
  • 提供选择器、全选、选区、文本、HTML、路径选择器、视口坐标、选择监听等工具。

选区工具栏实现 ​

选区工具栏是用户与 AI 能力之间的直接交互入口，核心行为包括：

  • 检测页面选区，包括 Shadow DOM 中的选区。
  • 在选区附近显示浮动工具栏。
  • 支持内置工具：AI 搜索、解释、翻译、总结、复制。
  • 支持更多工具溢出菜单、设置、临时禁用、站点禁用。
  • 支持“问问 AI”输入框模式。
  • 支持结果面板：流式渲染、复制、重新生成、推荐追问、Token 消耗明细。
  • 支持拖拽移动、锁定面板、关闭面板。
  • 支持 frameset 页面和 iframe 场景。

工具栏状态与变量 ​

工具栏维护多种状态：

  • 工具栏可见性、询问模式、结果面板可见性。
  • 上次操作类型、自定义提示词、保存的选中文本。
  • 工具栏工具配置缓存、图标精简模式。
  • 流式内容、渲染节流令牌、Token 使用数据。
  • Shadow DOM 选择监听器集合、顶层 frame 判定。
  • frameset 页面宿主判定、拖拽状态、溢出下拉菜单。

悬浮定位与 DOM 操作 ​

工具栏定位依赖：

  • getRangeViewportPosition 计算选区在视口中的位置。
  • appendToDoc 兼容 document.body 不存在的情况，降级到 document.documentElement。
  • 拖拽通过全局 mousemove 和 mouseup 更新 left、top，并限制在视口范围内。
  • 结果面板和工具栏分别挂载到文档，并通过类名控制显示隐藏。

用户交互反馈 ​

  • 按钮支持 Enter/Space 触发。
  • 溢出菜单支持点击、键盘操作。
  • “问问 AI”输入框支持 focus、blur、Enter、Escape。
  • 结果面板支持复制富文本、复制 Markdown、重新生成、发送追问。
  • Token 标签点击弹出消耗明细。
  • 工具名称通过 i18n 动态获取，避免硬编码文案。

性能优化、内存管理与兼容性最佳实践 ​

注入时机选择 ​

当前使用 document_idle，适合大多数读取和交互场景。如果需要更早介入，可考虑 document-start，但需注意：

  • DOM 可能尚未就绪。
  • 大量 DOM 操作可能阻塞首屏。
  • 需要更严格的错误处理和降级逻辑。

Map 与 Set 的使用 ​

  • HANDLERS 使用对象字面量作为路由表，查找接近 O(1)。
  • ASYNC_HANDLERS 和 TOP_FRAME_ONLY_TYPES 使用 Set，成员判断 O(1)。
  • elementRegistry 使用 Map，ref 到元素映射高效。
  • elementRefMap 使用 WeakMap，避免阻止元素 GC，同时复用 ref 编号。

异步工具通道保持 ​

异步工具通过 return true 保持消息通道开放，避免 Chrome 提前关闭响应。这要求：

  • 异步工具必须返回 Promise。
  • 路由层统一用 Promise.resolve(result).then(sendResponse) 处理。
  • 工具内部错误应返回结构化 { success: false, error }，而非抛出未捕获异常。

内存管理 ​

  • Shadow DOM 选择监听器通过 Set 管理，并提供 removeSelectionListeners 清理。
  • 工具栏工具配置缓存避免重复读取 storage。
  • 高亮样式通过固定 id 替换，避免累积 style 节点。
  • 区域截图遮罩层在完成后主动移除 DOM 节点。

兼容性处理 ​

  • 跨域 iframe 访问被 try-catch 保护，失败时跳过。
  • chrome.runtime 调用被 try-catch 包裹，扩展上下文失效时静默忽略。
  • 全局 error 和 unhandledrejection 过滤 Extension context invalidated。
  • CSS 注入前进行安全净化，剔除危险构造。
  • QRCode 库未加载时使用 Canvas 降级方案。

结论 ​

本项目 Content Script 注入机制以 document_idle 为默认注入点，通过集中式消息路由表统一管理页面读取、交互、提取、高级能力和用户界面。其核心优势包括：

  • 清晰的模块划分和依赖关系。
  • 高效的 Map/Set 路由与异步处理模型。
  • 完善的 Shadow DOM 与 iframe 穿透能力。
  • 健壮的错误处理和扩展上下文失效防护。
  • 可扩展的选区工具栏和结果面板。

在实际使用中，应根据页面特性选择合适的注入时机，合理使用 ref 机制避免脆弱选择器，并注意异步工具通道的正确保持。对于复杂页面，优先使用 query_elements 和 collectSnapshotOps 提供的结构化快照，再结合 interactByRef 进行稳定交互。
