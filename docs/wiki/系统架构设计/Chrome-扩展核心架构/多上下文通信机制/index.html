引言 ​

本扩展采用 Manifest V3 双进程架构：Chrome 扩展端位于 src/，版本为 2.3.1；独立本地 Agent 端为 Node.js 服务，入口为 agent/src/server.js。两者通过本地 HTTP/WebSocket 通信，但本文聚焦于 Chrome 扩展内部四个核心上下文的通信机制：Background Service Worker、Side Panel、Content Scripts 和 Offscreen Document。

在 MV3 中，Service Worker 生命周期受系统控制，空闲时可能被终止；Side Panel 是用户交互主界面；Content Script 注入网页执行页面级工具；Offscreen Document 则用于突破 MV3 对剪贴板等 API 的限制。这些上下文之间通过 chrome.runtime.sendMessage、chrome.runtime.connect、chrome.tabs.sendMessage 以及 Offscreen 文档的 chrome.runtime.onMessage 进行协作。

核心上下文职责划分 ​

Background Service Worker ​

Background 是扩展的核心调度层。它承担以下职责：

  1. 消息路由中心：统一接收 Side Panel、Content Script、Options Page 发来的 chrome.runtime.sendMessage，按 message.type 分发处理。
  2. ReAct 执行循环：协调工具预筛选、工具执行、流式输出、完成度校验、Token 统计。
  3. Side Panel 生命周期管理：打开/关闭侧边栏、脱离窗口、Tab 分组、作用域模式。
  4. Keepalive 长连接：通过 chrome.runtime.connect 建立命名端口，防止 SW 被系统回收。
  5. Agent 健康检查与心跳：定期检测本地 Agent 可达性，自动重连并刷新 MCP/RAG 工具。
  6. 通知与可见性判定：根据焦点、面板状态、发起实例身份决定是否弹出桌面通知。
  7. Checkpoint 恢复：SW 被回收后通过闹钟唤醒，从 IndexedDB 恢复 ReAct 任务。

Side Panel ​

Side Panel 是用户交互主界面，负责：

  1. 聊天与会话管理：发送消息、流式渲染、历史恢复、压缩摘要。
  2. 工具面板与技能选择器：展示 MCP/Skill/RAG 工具，支持 @ 引用知识库。
  3. 截图与图片识别：全屏截图、区域截图、图片附件。
  4. Agent 管理：配对、连接、重启、更新、停止。
  5. 配置同步：监听 chrome.storage.onChanged，实时更新记忆限制、自动压缩等开关。
  6. 与 Background 双向通信：通过 sendMessage 发起请求，通过 connect 维持长连接保活。

Content Scripts ​

Content Script 注入所有匹配 URL，提供页面级能力：

  1. 消息路由表：使用 HANDLERS Map 实现 O(1) 查找，按 message.type 分发到具体处理器。
  2. 页面读取：获取文本、HTML、选中内容、表格、元数据、链接、表单、图片。
  3. 页面交互：点击元素、填写表单、滚动、键盘输入、文件上传。
  4. 异步工具标记：通过 ASYNC_HANDLERS Set 判断是否需要保持消息通道开放。
  5. 顶层帧保护：通过 TOP_FRAME_ONLY_TYPES 避免 iframe 响应覆盖主页面。
  6. 区域截图选择：在页面创建遮罩层，让用户拖拽选择截图区域。

Offscreen Document ​

Offscreen Document 是 MV3 下剪贴板访问的专用上下文：

  1. 剪贴板读写桥：通过 navigator.clipboard.writeText/readText 实现复制粘贴。
  2. 降级回退：当现代剪贴板 API 失败时，回退到 document.execCommand('copy/paste')。
  3. 国际化文案：复用 ../shared/i18n.js 的多语言支持。
  4. 最小化 HTML：仅包含一个隐藏 textarea 作为剪贴板操作容器。

短消息与长连接选择策略 ​

chrome.runtime.sendMessage 的使用场景 ​

sendMessage 适用于短消息、一次性请求-响应场景：

  1. Side Panel → Background：CALL_API、CAPTURE_TAB、GET_CHAT_CONFIG
  2. Content Script → Background：SELECTION_TOOLBAR_ACTION、FILL_SIDEPANEL_INPUT、DIRECT_SEND
  3. Background → Offscreen：COPY_TO_CLIPBOARD、PASTE_FROM_CLIPBOARD
  4. Background → Content Script：SCREENSHOT_RESULT、STREAM_PRESELECT

特点：

  • 单次请求，立即响应
  • 最大消息大小 64MiB（Background 中对 executionLog 做了截断）
  • 适合状态查询、工具调用、截图等

chrome.runtime.connect 的使用场景 ​

connect 适用于长连接、双向通信、保活场景：

  1. Side Panel → Background Keepalive：命名端口 keepalive-{sessionId}
  2. 身份上报：KEEPALIVE_IDENTITY 携带 windowId 和 hostTabId
  3. SW 重启检测：SW_RESTARTED 通知前端可恢复的 checkpoint
  4. 面板断开提醒：延迟复核后触发桌面通知

特点：

  • 持久连接，可多次 postMessage
  • 防止 SW 被系统回收
  • 适合长时间运行的任务（如 ReAct 循环）

选择策略总结 ​

场景推荐方式原因
一次性工具调用sendMessage简单、轻量、有超时
实时流式输出sendMessage + StreamController分片传输，避免大消息
保活防回收connect长连接保持 SW 活跃
双向身份同步connect端口级别的状态共享
剪贴板操作sendMessage to Offscreen隔离敏感 API

MV3 安全沙箱与剪贴板绕过方案 ​

MV3 限制背景 ​

MV3 的 Service Worker 和 Content Script 无法直接访问某些浏览器 API，特别是剪贴板。这是出于安全考虑，防止恶意扩展随意读取用户剪贴板内容。

Offscreen Document 解决方案 ​

项目通过 Offscreen Document 绕过限制：

  1. 权限声明：manifest.json 中声明 offscreen、clipboardRead、clipboardWrite
  2. 按需创建：Background 通过 chrome.offscreen.createDocument 按需创建 Offscreen 文档
  3. 单例保护：通过 creatingOffscreenDocument Promise 避免重复创建
  4. 剪贴板桥接：Offscreen 文档暴露 COPY_TO_CLIPBOARD 和 PASTE_FROM_CLIPBOARD 消息

降级策略 ​

当现代剪贴板 API 失败时，Offscreen 文档会回退到 document.execCommand('copy/paste')：

  1. 创建一个隐藏的 textarea
  2. 设置值并 select()
  3. 调用 execCommand 执行复制/粘贴
  4. 清理临时元素

这种双重策略确保在不同浏览器版本和环境下的兼容性。

序列化、大数据与安全验证 ​

消息序列化限制 ​

Chrome 扩展的消息传递基于结构化克隆算法，不支持函数、循环引用、undefined 等类型。Background 中对大消息的处理：

  1. executionLog 截断：truncateLogForMessage 函数保留最后 1000 条日志，同时确保 subtask_plan 条目不被丢弃
  2. MAX_LOG_ENTRIES_FOR_MSG：常量定义最大日志条目数
  3. JSON.stringify 安全：所有跨上下文消息都经过 JSON 序列化

大数据传输优化 ​

  1. 流式传输：ReAct 循环通过 STREAM_* 消息分片传输 AI 响应
  2. 缓存机制：MCP 工具列表 30s 缓存，Skill Prompts 60s 缓存
  3. 按需加载：Offscreen Document 按需创建，避免启动开销
  4. 分页处理：Content Script 的页面交互工具支持 waitTime/timeout 参数

安全验证机制 ​

  1. Source 校验：Content Script 中部分消息处理检查 sender.tab?.id
  2. Frame 隔离：TOP_FRAME_ONLY_TYPES 防止 iframe 响应污染主页面

故障排查指南 ​

常见问题与解决方案 ​

1. Service Worker 被回收导致消息丢失 ​

现象：长时间运行任务后，Side Panel 无响应或显示“未连接”

原因：MV3 Service Worker 空闲时被系统回收，内存中的 activeReactLoops 清空

解决方案：

  • 使用 Keepalive 长连接防止回收
  • 利用 Checkpoint 机制自动恢复任务
  • 监听 SW_RESTARTED 消息提示用户继续执行

2. 侧边栏无法打开或关闭 ​

现象：快捷键无效，或点击插件图标无反应

原因：手势上下文丢失、Tab 分组状态异常、Chrome 版本兼容性问题

解决方案：

  • 确保在用户手势同步栈内调用 sidePanel.open()
  • 检查 _openPanelsByWindow 镜像状态
  • 使用 bindSidePanelToTab 绑定 Tab 专属面板

结论 ​

本项目实现了完整的 Chrome 扩展多上下文通信机制，通过精心设计的消息路由表、长连接保活策略和 Offscreen Document 权限绕过方案，解决了 MV3 架构下的核心挑战。

关键设计要点包括：

  1. 分层职责清晰：Background 负责调度和状态管理，Side Panel 专注 UI，Content Script 处理页面交互，Offscreen 隔离敏感 API
  2. O(1) 消息路由：使用 Map 实现高效的消息分发，支持异步处理器和顶层帧保护
  3. 保活与恢复：Keepalive 长连接防止 SW 回收，Checkpoint 机制支持任务自动恢复
  4. 权限最小化：Offscreen Document 仅暴露必要接口，降低安全风险
  5. 容错设计：所有跨上下文调用都有错误处理和降级策略

这套架构不仅满足了当前功能需求，也为未来的扩展提供了良好的基础。通过持续优化消息序列化、大数据传输和安全验证机制，可以进一步提升性能和安全性。
