引言 ​

本文件面向“AI Helper”双进程架构的服务生命周期管理，覆盖 Chrome 扩展端（Manifest V3，Service Worker）与独立本地代理端 Agent（Node.js）。文档重点说明：

  • 服务启动流程、依赖初始化与环境适配；
  • 运行模式检测、安装模式切换；
  • 健康检查、监控、自动重启与优雅关闭；
  • 日志轮转、指标收集与诊断信息；
  • 信号处理、进程守护与服务注册；
  • 部署、运维与故障恢复策略。

本项目版本以 2.3.1 为准，Agent 包入口为 agent/src/server.js，CLI 入口为 agent/bin/agent.js。两端通过本地 HTTP/WebSocket 通信，Agent 源码修改后必须重启进程才生效。

项目结构与职责边界 ​

  • 扩展端 background Service Worker：负责 UI 交互、任务编排、SW 保活、侧边栏状态、Agent 可达性检测与心跳。
  • Agent 端 Node.js 服务：提供 HTTP API 与 WebSocket，实现文件操作、命令执行、MCP/Skill/RAG 能力、认证与安全控制。
  • CLI 工具：负责后台守护、PID 管理、健康检查、在线更新与自启管理。

核心组件与生命周期阶段 ​

  • 启动阶段
    • CLI 解析参数、创建必要目录、写入 PID 文件、启动前台或后台进程。
    • Agent 加载配置、开启终端日志、异步探测搜索工具与 RAG 能力、启动 HTTP 服务。
  • 运行阶段
    • 扩展端周期性健康检查与心跳；Agent 端提供 /api/status、/api/heartbeat 等接口。
    • keepalive 长连接维持 SW 存活，支持 SW 静默重启检测与任务续跑。
  • 维护阶段
    • 在线重启、在线更新、RAG 依赖安装互斥保护、冷却时间防抖。
  • 关闭阶段
    • 优雅关闭：写停止标记、延迟关闭、清理 PID、整棵进程树终止。

启动流程与依赖初始化 ​

  • CLI 启动
    • 前台模式：写入 PID，动态导入 server.js 并调用 startServer。
    • 后台模式：spawn 子进程，轮询 /api/status 最多 8 秒，成功后写入 PID。
  • Agent 启动
    • 设置控制台输出、记录系统日志、异步初始化搜索工具与 RAG 可用性检测。
    • 启动 HTTP 服务，CORS 仅放行 chrome-extension 来源。

运行模式检测与安装模式切换 ​

  • 安装模式
    • 内嵌模式：由 install.sh/ps1 安装，runtime+app 位于 ~/.ai-helper-agent。
    • npm 全局模式：传统 npm -g 路径。
    • 判断依据：agent 包入口是否在 ~/.ai-helper-agent/app/ 下。
  • 运行时工具
    • getNodePath/getNpmPath：根据模式选择 Node/npm 可执行路径。
    • getRegistryUrl/getHfEndpoint：按 mirrors.json 切换 npm registry 与 HuggingFace 端点。
    • readInstallManifest/getStoppedFlagPath：读取安装清单与主动停止标记。

健康检查、监控与自动重启 ​

  • 扩展端健康检查
    • 每 30 秒对活跃代理发起 /api/status，失败时触发指数退避重连。
    • 每 60 秒发送 /api/heartbeat 刷新 Agent 端 lastAuthTime，保持“插件在线”。
  • Agent 端健康与心跳
    • /api/status：返回版本、平台、searchTools、ragAvailable。
    • /api/heartbeat：轻量刷新认证时间，不返回敏感信息。
  • 自动重启
    • /api/agent/restart：两阶段重启（spawn helper → 等待旧进程退出 → 启动新进程），带 10s 冷却。
    • /api/agent/update：npm 全局安装最新版本，超时 90s，失败不回滚老进程。

优雅关闭与进程守护 ​

  • 优雅关闭
    • /api/shutdown：本机来源免认证，远程需认证；写 .stopped 阻止 autostart；延迟 200ms 关闭。
    • CLI stop：优先调用 /api/shutdown，失败回退到 PID kill。
  • 进程守护
    • PID 文件：~/.ai-helper-agent/agent.pid。
    • 后台启动：spawn detached，健康检查通过后写入 PID。
    • 进程树终止：POSIX 对进程组发信号，Windows 使用 taskkill /T。

日志轮转、指标与诊断 ​

  • 日志
    • JSON Lines 格式，按日切分，保留最近 30 个文件，单文件上限 10MB，每分钟清理一次。
    • 分类标签：auth/fs/exec/security/system，支持中英文。
    • 查询接口：/api/logs（由 logger.queryLogs 提供）。
  • 指标
    • /api/status/detail 返回内存占用、CPU user/system、uptime、runningProcesses 等。
  • 诊断
    • 错误日志统一 logError，包含 action 与 details。
    • 扩展端 SW 重启检测通过 keepalive port 上报 HOST_TAB_RESOLVED 与 SW_RESTARTED。

信号处理、进程守护与服务注册 ​

  • 信号处理
    • CLI stop：优先 /api/shutdown，失败则 killByPid（POSIX SIGTERM，Windows taskkill /F /T）。
    • process-tree：POSIX 负 PID 向进程组发信号，Windows 使用 taskkill /T。
  • 进程守护
    • PID 文件读写原子化，后台启动 spawn detached，健康检查通过后写入 PID。
  • 服务注册
    • 自启：macOS LaunchAgents、systemd user service、Windows Task Scheduler。
    • 卸载：移除 plist/service/task，删除 runtime/app/bin 目录（保留数据）。

扩展端 SW 保活与侧边栏状态 ​

  • keepalive 长连接

    • 全局模式 vs 标签页绑定模式，窗口焦点与活跃 tab 镜像同步。
    • 快捷键 toggle 必须在用户手势同步栈内调用 open/close。

  • 模块耦合

    • server.js 内部模块化拆分避免直接循环；background 与 side_panel 通过 chrome.runtime 消息解耦。

性能与资源特性 ​

  • 文件上传/下载
    • multipart/form-data 与 raw binary stream 两种上传方式，流式传输避免大文件 OOM。
    • 目录下载打包为 zip，分块写入降低前端解码压力。
  • 搜索与预览
    • MAX_SEARCH_RESULTS=5000，XLSX 预览服务端裁剪空行列，限制行数。
  • 资源限制
    • MAX_BODY_SIZE=200MB，MAX_UPLOAD_SIZE=200MB，默认文件读取大小限制 50MB。
  • CPU/内存指标
    • /api/status/detail 暴露 heapUsed/heapTotal/rss、uptime、cpuUser/cpuSystem。

故障排查与恢复指南 ​

  • 无法启动
    • 检查 PID 文件是否存在且有效；确认端口未被占用；查看后台健康检查日志。
    • 前台模式直接观察 stderr 日志；后台模式查看 ~/.ai-helper-agent/logs/agent-YYYY-MM-DD.log。
  • 无法连接 Agent
    • 确认已配对且 token 有效；检查 /api/status 可达性；关注扩展端可达性缓存与心跳。
  • 更新失败
    • /api/agent/update 失败不会回滚老进程；查看 npm 输出与超时日志；手动执行 npm install -g ai-helper-agent@latest。
  • 进程残留
    • 使用 CLI stop 或 /api/shutdown；必要时 killByPid（Windows taskkill /F /T）。
  • SW 崩溃重启
    • 关注 SW_RESTARTED 通知；side_panel 会拒绝当前 Promise 并提示继续执行（如有 checkpoint）。

结论 ​

本项目的服务生命周期管理围绕“CLI 守护 + Agent HTTP 服务 + 扩展端健康检查/心跳”展开，具备：

  • 稳健的启动与依赖初始化流程；
  • 内嵌/npm 双模式自适应；
  • 完善的健康检查、心跳与自动重连；
  • 优雅关闭与进程树终止；
  • 日志轮转与指标暴露；
  • 在线重启与更新机制；
  • 针对 MV3 Service Worker 的保活与恢复策略。

这些机制共同保障了扩展端与 Agent 端的稳定协作与可观测性。

附录：部署与运维要点 ​

  • 官方安装渠道
    • 唯一推荐：GitHub Releases 自动构建产物下载；不要将 clone 源码构建作为推荐路径。
  • 启动与守护
    • 使用 ai-helper-agent start -b 后台启动；通过 status 查看健康状态；通过 stop 优雅关闭。
  • 自启管理
    • macOS：LaunchAgents plist；Linux：systemd user service；Windows：Task Scheduler。
    • 可通过 autostart on/off 管理。
  • 更新与卸载
    • update 在线更新并重启；uninstall 移除自启与运行时目录（保留数据）。
  • 运维监控
    • 定期巡检 /api/status/detail 指标；结合日志目录进行问题定位。
  • 故障恢复
    • 优先 /api/shutdown；失败再 killByPid；必要时清理 PID 与 .stopped 标记后重新启动。
