简介 ​

本文件面向“AI Helper”双进程架构（Chrome 扩展端 + 本地 Agent 端）的配置管理系统，覆盖以下主题：

  • 配置文件结构与字段含义
  • 环境变量注入与运行时参数处理
  • 配置验证机制、默认值合并与动态更新
  • 国际化配置、语言检测与区域设置管理
  • 配置加载流程图、环境变量映射表与优先级规则
  • 配置热重载、版本兼容性与迁移脚本机制
  • 敏感信息加密、配置备份恢复与审计追踪
  • 配置模板、最佳实践与故障排除

本项目为 MV3 扩展（src/）与独立 Node.js Agent（agent/src/server.js）组成，两端版本号同步为 2.3.1。扩展侧通过本地 HTTP/WebSocket 调用 Agent 能力；Agent 源码修改后需重启进程以生效。

核心组件 ​

  • 扩展端配置管理器（options/config-manager.js）
    • 负责模型下拉列表、上下文窗口设置、API Base URL 管理、图片识别模型管理等 UI 层配置交互与存储同步。
    • 使用 chrome.storage.local 持久化 customModels、imageModels、customApiBases、deletedPresetApiBases 等键。
  • 扩展后台配置读取（background/config.js）
    • 从 chrome.storage.local 聚合默认值与用户配置，返回 ReAct、流式输出、网络访问白名单、完成度校验等结构化配置对象。
    • 对 apiKey 进行解密后再暴露给上层逻辑。
  • Agent 端配置（agent/src/config.js）
    • 基于 ~/.ai-helper-agent/config.json 的 JSON 配置，提供内存缓存、mtime 失效、写互斥锁、字段白名单校验、单字段更新、配对 token 加密落盘等能力。
    • 内置 DEFAULTS 默认值，支持 memoryEmbedding、ragUrlIngest 等高级开关。
  • 密钥混淆（src/shared/secret.js）
    • 统一采用 enc: 前缀 + Base64 的轻量混淆方案，兼容旧明文，写入自动升级。
  • 厂商配置与 Profile（src/options/profile-manager.js、src/shared/model-profiles.js）
    • 提供新建/复制/重命名/删除/切换 Profile 的能力，并联动刷新基础表单字段与下拉列表。

架构总览 ​

扩展端通过 options 页面编辑配置，保存到 chrome.storage.local；background 在需要时读取并合并默认值，必要时解密敏感字段。Agent 端通过 HTTP 接口接收请求，按当前语言解析错误消息，并从 config.json 加载配置（带缓存与写锁）。

详细组件分析 ​

扩展端配置管理器（options/config-manager.js） ​

  • 功能要点
    • 模型下拉列表增删改查、排序、搜索过滤、上下文窗口 badge 显示与滑杆设置。
    • API Base URL 预设与自定义项管理，记录被删除的预设项以便恢复。
    • 图片识别模型管理与主模型管理类似，但允许删除预设模型。
    • 所有变更均立即持久化到 chrome.storage.local，并同步到当前厂商配置的 models 字段。
  • 关键数据结构
    • customModels: Array<{name, contextWindow}>
    • imageModels: Array<{name, contextWindow}>
    • customApiBases: Array<{url, label}>
    • deletedPresetApiBases: string[]
  • 复杂度与性能
    • 渲染采用全量重建 + 排序，适合中小规模模型列表；若未来增长较大可考虑虚拟滚动或增量更新。
  • 错误处理
    • DOM 元素不存在时提前返回；旧格式数据兼容迁移；清空选中项时回退到首个可用项。

扩展后台配置读取（background/config.js） ​

  • 功能要点
    • 聚合 ReAct、流式输出、网络访问控制、完成度校验等配置。
    • 对 apiKey 进行解密；对布尔型与数值型字段做缺省值保护。
    • 提供 getChatConfig() 供 side_panel 使用，包含自动压缩阈值等对话行为配置。
  • 默认值合并策略
    • 对 reflection、completionVerification 等嵌套对象采用深合并打底，避免部分覆盖导致字段缺失。
  • 环境变量注入
    • 当前实现未直接读取系统环境变量；如需注入，可在 getStoredConfig 中增加环境变量读取与合并步骤。

Agent 端配置（agent/src/config.js） ​

  • 功能要点
    • 基于 ~/.ai-helper-agent/config.json 的 JSON 配置，提供内存缓存、mtime 失效、写互斥锁、字段白名单校验、单字段更新、配对 token 加密落盘。
    • 内置 DEFAULTS 默认值，支持 memoryEmbedding、ragUrlIngest 等高级开关。
    • 自动将 skills/workspace 目录加入 allowedPaths。
  • 配置加载流程
    • 首次启动创建默认配置；存在则根据 mtime 判断是否重新读取；解析失败回退默认值。
    • 磁盘密文 → 内存明文（兼容旧版无 enc: 前缀的明文），落盘前再混淆。
  • 并发与一致性
    • withWriteLock 串行化写操作，防止 TOCTOU 竞态；writeConfigBody 先写后读确保缓存一致。

密钥混淆（src/shared/secret.js） ​

  • 设计要点
    • 采用 enc: 前缀 + Base64 的轻量混淆，非密码学安全，仅防明文一眼可辨。
    • 读取时若无 enc: 前缀视为旧明文原样返回；下次写入自动升级。
  • 使用范围
    • 扩展端 background/config.js 对 apiKey 解密；Agent 端对 memoryEmbedding.apiKey 与 pairing token 进行加解密。

性能与并发特性 ​

  • Agent 端配置缓存
    • 使用内存缓存与 mtime 失效，避免频繁 IO；仅在文件变化时重新读取。
  • 写互斥锁
    • withWriteLock 串行化写操作，防止并发覆盖；saveConfig 与 updateConfigField 共用 writeConfigBody。
  • 扩展端渲染
    • 模型下拉全量重建，适合中小规模；若未来增长较大建议引入虚拟滚动或增量更新。

国际化与区域设置 ​

  • 扩展端 i18n
    • src/shared/i18n.js 提供 t 函数与订阅机制，用于界面文案动态查询。
  • Agent 端 i18n
    • agent/src/i18n.js 提供 translate 函数，由 server.js 在请求入口处设置当前语言，用于错误消息翻译。

    • Agent 端通过 mtime 检测 config.json 变化，下次 loadConfig 时自动重新读取；无需重启即可生效。
  • 版本兼容
    • 扩展端 imageModels 支持字符串旧格式与对象新格式，加载时自动迁移为新格式。
    • secret.js 兼容旧明文，写入自动升级为 enc: 前缀。
  • 迁移脚本
    • 当前迁移逻辑内嵌于加载流程（如 loadImageModels、decodeSecret），未提供独立迁移脚本；如需批量迁移，可在 build 或安装阶段新增脚本。

模板与最佳实践 ​

  • 配置模板
    • Agent 端 DEFAULTS 可作为最小可用模板；扩展端 PRESET_MODELS/PRESET_API_BASES 可作为预设模板。

    • 始终通过 updateConfigField 更新单字段，避免覆盖其他字段。
    • 对敏感字段使用 encodeSecret/decodeSecret，避免明文落盘。
    • 在扩展端使用 normalizeCustomModels 与 formatContextWindow 保持上下文窗口一致性。
    • 在 Agent 端启用 ragUrlIngest.allowPrivateNetwork=false 且 allowedPrivateHosts 为空时拒绝内网访问，遵循最小权限原则。

故障排除指南 ​

  • 常见问题
    • 模型下拉不显示：检查 customModels 是否为空或格式不正确；确认 renderModelDropdownFromList 被调用。
    • API Base 无法选择：确认 addCustomApiBase/removeApiBase 正确调用并触发 saveApiBases。
    • Agent 配置未生效：确认 config.json 已更新且 mtime 变化；必要时重启 Agent 进程。
    • 密钥解密失败：检查 secret.js 的 enc: 前缀是否正确；确认 decodeSecret 未被异常捕获。
  • 调试建议
    • 在 background/config.js 中打印 getStoredConfig 返回值，确认默认值合并与密钥解密结果。
    • 在 agent/config.js 中打印 loadConfig 返回对象，确认 DEFAULTS 与 userConfig 合并结果。

结论 ​

本配置管理系统在扩展端与 Agent 端分别实现了稳健的配置加载、默认值合并、敏感信息混淆与缓存机制。通过 Profile 管理、i18n 支持与导入导出能力，覆盖了多厂商配置、国际化与备份恢复场景。Agent 端的 mtime 热重载与写互斥锁提升了可靠性与并发安全性。未来可考虑增强环境变量注入、审计追踪与批量迁移脚本，以满足更复杂的运维需求。
