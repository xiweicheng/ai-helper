引言 ​

本文件聚焦 Chrome 扩展端的状态管理与持久化机制，覆盖以下目标：

  • 解释应用状态的层次结构：内存状态、会话状态、配置数据、用户偏好。
  • 说明变更追踪与同步机制：侧边栏状态、后台 Service Worker 状态、IndexedDB、chrome.storage.local 的读写路径。
  • 详细说明 IndexedDB 数据模型设计、事务处理与并发访问控制。
  • 解释 ReAct Checkpoint 的双写策略、TTL 清理与恢复流程。
  • 说明状态迁移方案、数据备份恢复思路与版本兼容性管理。
  • 提供状态转换图、数据库 schema 图和数据流图。
  • 讨论大数据量场景下的查询优化、缓存策略和性能监控。

本项目为双进程架构：Chrome 扩展端（Manifest V3，Service Worker + Side Panel）与独立本地代理端 Agent（Node.js）。本文仅关注扩展端的状态与持久化；Agent 端的记忆与 RAG 数据不在本文件范围内。

架构总览：状态层次、存储分层与数据流 ​

状态层次 ​

  • 内存状态：侧边栏 state.js 维护 UI 渲染与交互所需状态；后台 state.js 维护任务生命周期、取消控制、端口路由。
  • 会话状态：活跃会话与归档会话持久化到 IndexedDB；当前活跃会话 ID 单独存储。
  • 配置数据：扩展配置、主题、工具列表、输入历史等保存在 chrome.storage.local。
  • 用户偏好：语言偏好、模型选择、温度、TopP 等可通过配置或会话级参数体现。
  • 运行态快照：ReAct Checkpoint 作为长任务中断后的断点续接数据，采用 IndexedDB + chrome.storage.local 双写。

IndexedDB 数据模型与版本管理 ​

数据库名称为 ai-helper-db，当前版本为 6。对象存储包括：

  • sessions：活跃会话，主键 id，索引 updatedAt。
  • activeSession：单条记录，keyPath key，用于保存当前活跃会话 ID。
  • archivedSessions：归档会话，主键 id，索引 createdAt。
  • uiPrototypes：UI 原型，主键 id，索引 createdAt、sessionId。
  • tokenStats：Token 使用统计，主键 id，索引 sessionId、timestamp。
  • reactCheckpoints：ReAct Checkpoint，主键 sessionId，索引 updatedAt。
  • bookmarks：消息收藏，主键 id，索引 sessionId、createdAt。
  • scheduledTasks：定时任务，主键 id，索引 nextRunAt、enabled。

事务处理与并发访问控制 ​

withStore 是统一的事务包装器，负责：

  • 检查 store 是否存在，若缺失则关闭连接并重置单例，延迟重试以触发 onupgradeneeded。
  • 捕获 transaction() 同步异常，在失败时重置连接并重试一次。
  • 在 tx.oncomplete 中 resolve，确保事务提交后再返回结果。
  • 在 tx.onerror 与 tx.onabort 中执行连接重置与重试逻辑。
  • 支持 isRetry 标志，避免无限重试。

此外，openDB 中处理了 onversionchange 与 onblocked：

  • onversionchange：当其他连接触发版本变更时主动关闭当前连接，避免阻塞 DB 升级。
  • onblocked：当升级被阻塞时记录警告，等待后续重试。

会话状态与变更追踪 ​

session-store.js 提供与旧 API 兼容的会话操作：

  • init()：首次调用时执行 ensureMigration()，并清理孤儿 scrollPosition_* key。
  • loadSessions()：并行加载会话列表与活跃会话 ID，按 order 排序。
  • saveCurrentSession()：将当前内存状态映射到会话对象并持久化。
  • createSession() / importSessions() / appendMessageToSession()：创建、导入、追加消息。
  • switchToSession()：并发保存当前会话、读取目标会话、设置活跃会话 ID、恢复模型/温度/工具等状态。
  • deleteStoreSession()：删除会话、清理 scrollPosition、checkpoint、收藏，并就近激活相邻会话。
  • archiveCurrentSession() / restoreArchivedSession() / duplicateSession() / createScheduledSession()：归档、恢复、复制、定时任务宿主会话。

ReAct Checkpoint 双写与恢复 ​

ReAct Checkpoint 是长任务中断后的断点续接数据，采用双写策略：

  • 先写 chrome.storage.local（可靠），再尝试写入 IndexedDB（性能优化）。
  • 读取时优先 IndexedDB，失败降级到 chrome.storage.local。
  • 删除时同时清理两处存储。
  • SW 启动时清理超过 7 天的过期 checkpoint。

状态迁移与版本兼容性 ​

  • migrateFromChromeStorage()：将旧 chrome.storage.local 中的 sessions 与 conversationSessions 迁移到 IndexedDB，并清理旧的大数据 key。
  • ensureMigration()：若 IndexedDB 无数据且无活跃会话标记，则尝试迁移。
  • session-store.js 的 init() 在首次加载时调用 ensureMigration()。
  • db.js 的 DB_VERSION = 6，并在 onupgradeneeded 中按需创建 store 与索引。

增强的会话取消键收集机制 ​

更新 新增了 collectSessionCancelKeys 函数来改进子任务进度数据结构处理，支持更精确的会话取消范围控制。

collectSessionCancelKeys 函数实现了智能的取消键收集逻辑：

性能优化与大数据量策略 ​

查询优化 ​

  • getSessionTokenSummary 使用 sessionId 索引与 IDBKeyRange.bound 缩小候选集，避免全表扫描。
  • getDailyTokenSummary 与 getOverallTokenSummaryByRange 使用 timestamp 索引进行范围查询。
  • searchActiveSessionsMessages 在指定 sessionId 时使用 O(1) 主键查询，避免加载所有会话。

缓存策略 ​

  • db.js 的 getDB() 返回单例连接，减少重复打开开销。
  • session-store.js 的 loadSessions() 并行加载会话列表与活跃会话 ID。
  • switchToSession() 并行发起保存当前会话与读取目标会话，提升切换性能。

  • 监控 IndexedDB 事务错误与 abort 次数，识别连接不稳定场景。
  • 监控 ReAct Checkpoint 双写成功率，评估 IndexedDB 可用性。
  • 监控 Token 统计聚合查询耗时，评估索引有效性。

故障排查指南 ​

IndexedDB 连接问题 ​

  • 现象：store 不存在导致写入静默失败。
  • 原因：其他连接持有旧版本，阻塞升级。
  • 解决：withStore 自动关闭连接并重置单例，延迟重试；onversionchange 主动关闭当前连接。

Checkpoint 恢复失败 ​

  • 现象：前端显示"继续执行"但后端无法恢复。
  • 原因：checkpoint 未成功双写或 sessionId 不匹配。
  • 排查：检查 chrome.storage.local 中 react_checkpoint_* 是否存在；查看 getAllReactCheckpoints 输出。

会话切换卡顿 ​

  • 现象：切换会话时 UI 卡顿。
  • 原因：全量加载所有会话或消息历史过大。
  • 优化：使用 order 排序、分页加载、懒加载消息历史。

Token 统计查询缓慢 ​

  • 现象：Token 统计页面加载慢。
  • 原因：全表扫描 tokenStats。
  • 优化：使用 sessionId 与 timestamp 索引，限制返回记录数。

子任务进度丢失 ​

  • 现象：子任务中断后进度信息不完整。
  • 原因：部分进度记录未正确保存或失败恢复逻辑异常。
  • 排查：检查 recordSubtaskPartialProgress 调用点和 buildSubtaskFailureResult 返回值。

结论 ​

本项目的状态管理与持久化体系围绕三层展开：

  • 内存状态：侧边栏与后台分别维护运行时状态，支持多会话并行与取消控制。
  • 会话状态：IndexedDB 作为主存储，支持活跃会话、归档会话、收藏、原型、定时任务等。
  • 配置与偏好：chrome.storage.local 作为轻量配置与后备存储，语言偏好跨环境同步。

更新后的关键设计亮点：

  • withStore 统一事务包装，增强连接稳定性与错误恢复能力。
  • ReAct Checkpoint 双写策略保障长任务可靠性。
  • 数据迁移与版本管理确保平滑升级。
  • 查询优化与索引设计应对大数据量场景。
  • 新增 智能会话取消键收集机制，支持精确的子任务取消范围控制。
  • 新增 增强的标签页状态管理，改进派生会话祖先链和 keepalive 端口路由。
  • 新增 改进的子任务进度数据结构处理，提供更好的错误处理和恢复机制。

未来改进方向：

  • 引入增量聚合记录（如 overall 汇总）减少全表扫描。
  • 增加更细粒度的性能埋点与监控。
  • 探索分片存储与异步批量写入，进一步提升高并发场景下的稳定性。
  • 进一步优化子任务进度记录的准确性和完整性。
