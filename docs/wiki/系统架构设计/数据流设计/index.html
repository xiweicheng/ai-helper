引言 ​

本文件面向“从用户输入到 LLM 响应”的完整数据流转，覆盖消息序列化、工具调用结果聚合、上下文压缩、会话状态管理、持久化存储、RAG 知识检索、Token 统计与上下文窗口管理。系统采用双进程架构：Chrome 扩展端（Manifest V3，Service Worker + Side Panel）与独立本地 Agent 进程；两端通过 HTTP/WebSocket 通信契约协作。Agent 负责文件系统、命令执行、长期记忆与 RAG 索引；扩展端负责 ReAct 推理循环、工具调度、界面交互、会话与 Token 统计。

项目结构与数据边界 ​

  • 扩展端 background 是 Service Worker 入口，承担任务编排、保活、自动续跑、ReAct 循环、工具注册、Token 统计和 IndexedDB 访问。
  • side panel 负责聊天 UI、知识库引用注入、流式渲染、会话加载与保存。
  • agent 进程提供 HTTP API 与 WebSocket，暴露文件、命令、MCP、Skill、RAG、日志等能力。
  • 持久化层以 IndexedDB 为主，checkpoint 使用 IndexedDB + chrome.storage.local 双写降级。

端到端数据流总览 ​

用户输入在侧边栏组装后进入后台 ReAct 循环；后台根据模型能力与工具集选择工具，必要时调用 Agent 的 MCP/Skill/RAG/文件/命令接口；LLM 返回流式内容，后台聚合工具结果、维护执行日志、进行上下文预算评估与压缩；最终将消息写入会话并持久化，同时记录 Token 使用。

核心组件与职责 ​

  • 侧边栏聊天管理：组装用户输入、知识库引用、流式渲染、会话加载与保存、上下文指标。
  • 后台 ReAct 循环：推理迭代、工具预筛选与执行、流式控制、循环检测、确认交互、检查点持久化。
  • 工具执行器：动态注册 MCP/RAG 工具、参数压缩、执行代理、审计与活动记录。
  • Agent 客户端：配对、认证、HTTP/WebSocket 封装、可达性缓存、多代理支持。
  • Agent 服务器：HTTP 路由、认证、CORS、文件上传/下载、命令执行、MCP/Skill/RAG 集成。
  • 上下文压缩：批量摘要生成、结构化历史摘要、手动压缩摘要。
  • Token 统计与估算：消息 token 估算、上下文窗口预算、校准因子、统计持久化。
  • 存储层：会话、归档、UI 原型、Token 统计、ReAct Checkpoint、迁移与升级。

详细数据流分析 ​

消息序列化与工具调用结果聚合 ​

  • 侧边栏将用户输入与知识库引用组合为消息，必要时注入固定标记的知识库上下文文本。
  • 后台 ReAct 循环对 assistant(tool_calls) 与 tool 消息进行配对校验，过滤非法字段，修复缺失 tool_call_id 的情况。
  • 工具执行器动态注册 MCP/RAG 工具，压缩 schema 描述，合并强制下发的 MCP 服务工具，避免被预筛选丢弃。
  • Agent 客户端统一封装认证、超时、错误映射，附加 httpStatus 区分网络错误与业务错误。

上下文压缩算法 ​

  • 增量对话摘要：当 ReAct 上下文 token 超阈值时，批量提取最旧一轮轮次，构建 transcript，调用 LLM 生成结构化摘要（任务目标/已完成/关键事实/未决问题）。
  • 手动压缩摘要：用户显式触发，按 UI 语言生成摘要，失败不静默降级。
  • 预算裁剪：基于模型上下文窗口减去系统提示词、工具定义、输出预留，计算消息历史预算；从旧到新移除消息，保持 tool_calls/tool 配对。

会话状态管理与持久化 ​

  • 会话状态保存在 IndexedDB，包含 messageHistory、model、temperature、topP、enabledTools、agentId、contextCompaction 等。
  • ReAct Checkpoint 双写策略：先写 chrome.storage.local（可靠），再尝试 IndexedDB（性能优化）；读取优先 IndexedDB，失败降级到 storage.local。
  • 自动清理过期 checkpoint（TTL 7 天），SW 启动时重建定时任务闹钟并从 DB 恢复。

Token 计数统计与上下文窗口管理 ​

  • Token 估算：中文约 1.5 字符/token，英文约 4 字符/token；图片按分辨率 tile 公式估算，避免 Base64 高估。
  • 上下文窗口：内置模型映射 + 自定义模型配置 + 全局覆盖；计算消息预算 = 窗口 - 系统提示词 - 工具定义 - 输出预留。
  • 校准因子：基于 API 返回 prompt_tokens 与估算值对比，EWMA 平滑修正估算偏差。
  • 统计持久化：每次 API 调用后记录 sessionId/model/usage/callType，存入 IndexedDB。

依赖关系分析 ​

  • 扩展端依赖 Agent 提供的 HTTP/WebSocket 接口，所有认证请求携带 Bearer Token。
  • 工具执行器依赖 MCP/Skill/RAG 的动态注册与元信息，支持会话级强制下发。
  • ReAct 循环依赖 token-counter 的估算与裁剪、stream-controller 的流式控制、notifier 的交互提醒。
  • 存储层依赖 IndexedDB 事务包装 withStore，具备连接恢复重试与 store 不存在时的自动重建。

性能与容量特征 ​

  • 消息日志内存窗口：执行日志仅保留最近 1000 条，防止长任务期间 SW 内存失控。
  • MCP schema 压缩：description 截断、properties 嵌套深度限制、参数数量上限，防止上下文膨胀。
  • RAG 命中内容截断：单条命中最大字符数限制，避免注入过大上下文。
  • Token 估算校准：EWMA 平滑因子，样本不足时不校准，避免单次异常波动。
  • 文件上传大小限制：JSON body 解析上限 200MB，流式上传支持原文件 200MB。

故障排查指南 ​

  • Service Worker 生命周期：keepalive port 重连检测 SW 重启，若存在 checkpoint 则自动续跑；面板断开延迟复核避免误报。
  • IndexedDB 升级阻塞：onversionchange 主动关闭连接，withStore 检测 store 不存在时重置连接并重试。
  • Checkpoint 双写降级：IndexedDB 不可用时 fallback 到 chrome.storage.local，读取优先 IndexedDB。
  • 工具确认通道：关联键唯一性保证并发安全，面板关闭或超时默认拒绝（fail-closed）。
  • Agent 可达性缓存：已知不可达时直接返回错误，避免阻塞等待超时。

结论与建议 ​

  • 数据流设计围绕“扩展端编排 + Agent 能力 + 持久化保障”展开，强调认证、安全、可恢复性与性能。
  • 建议在生产环境中监控 IndexedDB 升级事件、Checkpoint 双写成功率、Token 估算校准因子变化。
  • 对于大规模 RAG 场景，建议关注向量索引构建耗时、检索命中率与注入上下文大小。
  • 对于长任务，建议启用自动续跑与执行日志内存裁剪，避免 SW 终止导致任务丢失。
