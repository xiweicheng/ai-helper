引言 ​

本文件面向 AI Helper Chrome 扩展（Manifest V3，版本 2.3.1）的端到端测试体系。文档聚焦 Playwright e2e 测试框架的配置与环境搭建、浏览器自动化配置、测试环境准备、测试数据管理、E2E 场景设计、测试执行策略、具体测试脚本示例、视觉回归与 UI 一致性验证，以及测试维护指南。

本项目采用双进程架构：Chrome 扩展端与独立本地 Agent 端。Agent 端源码修改后必须重启进程，新接口才生效；但当前仓库中的 Playwright e2e 主要覆盖扩展侧内容脚本工具、侧边栏交互、选项页保存按钮栏等前端行为，不直接启动或连接 Agent HTTP/WebSocket 服务。因此，本节 E2E 文档以扩展端真实 Chromium 页面和 content script 工具为主。

核心组件 ​

Playwright e2e 的核心由三部分构成：

组件职责关键实现位置
Playwright 配置定义测试目录、并行策略、重试、headless、动作超时、Chromium 设备playwright.config.js
模块加载器使用 esbuild 将 content script 相关模块打包为 IIFE，注入到被测页面并暴露全局调用能力test/e2e/helpers/load-module.js
测试用例集覆盖内容工具链路、商品录入 Demo、消息跳转交互、消息跳转布局、选项页保存按钮栏吸附、iframe 跨帧 ref各 .e2e.spec.js 文件

Playwright 配置要点 ​

  • 测试目录：./test/e2e
  • 并行执行：开启 fullyParallel
  • CI 模式：forbidOnly 在 CI 下启用，避免误提交 test.only
  • 失败重试：CI 下重试 1 次，本地默认 0 次
  • 浏览器运行：headless 模式，动作超时 10 秒
  • 项目：仅 Chromium，使用桌面 Chrome 设备描述

模块加载器 ​

load-module.js 通过 esbuild 把以下 content script 模块聚合为 IIFE：

  • src/content/page-utils.js
  • src/content/shadow-dom-utils.js
  • src/content/page-interaction.js
  • src/content/page-extract.js
  • src/content/interaction-tools.js
  • src/shared/page-snapshot-renderer.js

打包结果挂载到 window.__tools，并提供：

  • getContentBundle()：缓存 bundle，避免重复构建
  • callTool(page, fnName, ...args)：在 page 上下文调用工具函数
  • callToolInFrame(page, frameName, fnName, ...args)：在指定 iframe 上下文中调用工具

该设计使 e2e 测试能在真实 Chromium 中直接验证 content script 的工具链，而不必依赖扩展安装流程。

内容工具端到端测试 ​

content-tools.e2e.spec.js 是内容脚本工具链的代表性 e2e 用例，覆盖：

  • queryInteractiveElements → interactByRef 完整链路
  • fillForm 多类型表单填充
  • selectDropdown 原生 select 选择
  • clickByText 文本点击
  • Shadow DOM 穿透查询与点击
  • scrollAndCollect 无限滚动收集
  • extractLinks、pageToJson 链接与表格提取
  • searchInPage 正则搜索
  • getIframeContent 同源 iframe 内容获取
  • queryInteractiveElements 分页、叠加层提升、去重、ref 稳定性

该用例通过 addInitScript 注入 window.__tools，再使用 callTool 调用工具方法，最后用 Playwright 断言 DOM 状态、返回值字段和交互结果。

flowchart TD
Start(["进入用例"]) --> LoadBundle["加载 content 工具 bundle"]
LoadBundle --> Inject["addInitScript 注入 window.__tools"]
Inject --> Navigate["导航到 fixtures 页面"]
Navigate --> Query["调用 queryInteractiveElements"]
Query --> ValidateQuery{"查询成功？"}
ValidateQuery --> |否| Fail["断言失败"]
ValidateQuery --> |是| Interact["调用 interactByRef 或 fillForm/select/click"]
Interact --> AssertDOM["断言 DOM 值、属性、可见性"]
AssertDOM --> End(["用例结束"])

消息跳转交互测试 ​

message-jump-interaction.e2e.spec.js 用真实鼠标、键盘事件驱动侧边栏消息跳转把手，覆盖：

  • 悬停把手展开列表
  • 鼠标移出自动收起，钉住后移出保持展开
  • Tab 键盘可达，↑/↓ 移动焦点
  • 搜索过滤命中子集，编号仍为全局组序
  • 中文输入法组合期间不销毁输入框，上屏后才过滤
  • Esc 优先清空搜索词，再按一次退钉住/收起

  • 点击条目后移开鼠标再滚对话，当前项会滚进列表可视区

性能与执行策略 ​

并行测试 ​

Playwright 配置开启 fullyParallel: true，意味着每个 spec 文件内的用例可在不同 worker 中并行执行。这能显著缩短 CI 时间，但也要求用例之间保持隔离，避免共享全局状态。

重试机制 ​

  • 本地环境：retries: 0
  • CI 环境：retries: 1

建议在新增不稳定用例时先定位根因，而不是盲目增加重试次数。对于网络或外部资源依赖的用例，应优先改为本地 fixture 或 mock。

动作超时 ​

actionTimeout: 10000 表示每次 action 最多等待 10 秒。若某个用例频繁超时，应检查：

  • 是否缺少 waitForSelector 或 waitForFunction
  • 是否动画未结束就断言
  • 是否 fixture 页面加载过慢
  • 是否使用了错误的定位器

调试模式 ​

可通过 npm run test:e2e:headed 启动 headed 模式，便于观察浏览器行为。该命令对应 package.json 中的脚本定义。

结论 ​

该项目的 Playwright e2e 测试体系围绕真实 Chromium、真实样式与真实 DOM 展开，重点验证内容脚本工具链、侧边栏交互、选项页吸附行为与 iframe 跨帧能力。测试通过 esbuild 动态打包模块、通过 addInitScript 注入工具、通过 fixture 页面模拟业务场景，既避免了安装扩展的复杂度，又保留了足够的真实性。

未来可扩展的方向包括：

  • 引入截图对比进行视觉回归
  • 增加更多跨页面流程验证
  • 补充 Agent 集成测试（需启动本地 Agent 进程）
  • 细化性能基准用例
  • 完善测试数据管理与版本化
