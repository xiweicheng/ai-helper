引言 ​

本文件面向 AI Helper 扩展（Manifest V3，版本 2.3.1）的“内置工具集”，聚焦浏览器工具、内容提取工具、存储工具、标签页管理工具、调试工具、媒体工具与 AI 工具。文档从执行环境、参数契约、并行能力、确认机制、错误处理、分类体系与设计原则出发，给出可操作的调用模式与优化建议，帮助读者在页面交互、表单自动化、数据抓取和跨进程协作中稳定工作。

项目结构 ​

内置工具以“定义 + 执行”双层组织：

  • 定义层：按类别拆分到 background/tools/*.js，集中声明 id、category、execution、parallelizable、requiresConfirmation、function.name/description/parameters。
  • 执行层：background/tool-executor.js 负责注册、调度、参数校验、确认弹窗、截图、Agent 通信、MCP/RAG 动态注入等；content/* 提供页面侧 DOM 操作与提取实现。

架构总览 ​

工具调用通常经历以下阶段：

  1. LLM 选择工具并传入参数。
  2. tool-executor.js 校验参数、判断是否需要用户确认。
  3. 根据 execution 字段分发到 content_script 或 background 处理器。
  4. content_script 执行 DOM 操作或提取；background 执行浏览器 API、网络请求、截图、Agent 命令等。
  5. 结果回传，必要时触发截图下载、通知或流式输出。

详细组件分析 ​

浏览器工具（页面交互、表单、内容提取） ​

覆盖 interact_element、scroll_to、wait_element、fill_form、keyboard_input、file_upload、select_dropdown、page_content、extract_data、query_elements、search_in_page、iframe_content、scroll_collect。

  • 执行环境
    • content_script：interact_element、scroll_to、wait_element、fill_form、keyboard_input、file_upload、select_dropdown、search_in_page、iframe_content、scroll_collect。
    • background：page_content、extract_data、query_elements。
  • 并行能力
    • page_content、extract_data、query_elements、search_in_page、iframe_content 标记为可并行。
  • 定位策略
    • 优先使用 query_elements 返回的 ref 编号进行 interact_element/fill_form/select_dropdown，避免脆弱 CSS selector。
    • 当 ref 失效时，会尝试基于缓存 selector 重查，失败则提示重新查询。
  • 表单自动化
    • fill_form 批量填写，支持 text/select/checkbox/radio/contenteditable。
    • keyboard_input 绕过 React/Vue 受控组件，适合单字段输入或快捷键。
    • file_upload 通过 DataTransfer 注入文件。
    • select_dropdown 兼容原生 select 与自定义下拉。
  • 内容提取
    • page_content 获取文本或 HTML，支持 selector 与长度限制。
    • extract_data 结构化提取 table/metadata/links/forms/images。
    • query_elements 返回树形快照，包含可见 iframe 子帧与打开的弹层。
    • search_in_page 支持 plain/regex、大小写敏感、上下文片段与高亮。
    • iframe_content 仅同源可读取，支持嵌套。
    • scroll_collect 滚动收集长内容，去重拼接。

性能考虑 ​

  • 优先使用 query_elements 的 ref 定位，减少 CSS selector 复杂度与匹配成本。
  • 对长列表/无限滚动使用 scroll_collect，合理设置 maxScrolls 与 pauseMs，避免频繁滚动导致卡顿。
  • 并行工具（page_content、extract_data、query_elements、search_in_page、iframe_content）可在同一轮中并发调用，但注意目标页面状态一致性。
  • 控制 page_content/extract_data 的输出规模（maxLength、maxResults），避免过大结果影响上下文预算。
  • 截图 analyze 模式有额外视觉模型开销，按需启用 visionMaxDim/visionQuality。
  • 使用 wait_navigation/wait_element 等待关键状态后再继续，减少无效重试。
  • 对耗时较长的 Agent 命令，合理设置 timeoutMs，避免长时间占用资源。

故障排查指南 ​

  • 未知工具/未知 action：检查工具定义与参数枚举是否匹配。
  • 标签页不可用：确认 tabId 是否存在且可访问；系统页面不允许使用工具。
  • Content Script 注入失败：检查页面是否允许注入，或目标是否为错误页。
  • 内网地址访问被拒：fetch_url 与 manage_tab(open) 均受内网访问策略限制，需在扩展设置开启“内网地址访问”并将主机加入允许列表。
  • 用户未确认：requiresConfirmation 或 confirmationActions 触发的操作需用户确认，否则中止。
  • 导航/DOM 变化导致 ref 失效：重新调用 query_elements 获取最新快照。
  • 截图分析失败：检查视觉模型 API 配置与可用性。
  • 命令执行超时/无 exitCode：查看命令输出与退出码，必要时缩短命令或调整超时。

结论 ​

内置工具集以清晰的分类与统一的定义-执行分离架构，提供了从页面交互、表单自动化、内容提取到存储、标签页、媒体、AI 协作与本地代理的全链路能力。通过 ref 定位、并行化、确认机制与安全边界，既提升了自动化效率，也保障了安全性与稳定性。建议在复杂任务中使用 plan_task 分解步骤，结合 query_elements 与 scroll_collect 提升鲁棒性，并通过截图与日志辅助排障。
