引言 ​

本文件面向“工具执行框架”的完整技术文档，覆盖以下目标：

  • 工具定义与注册机制：内置工具、MCP 动态工具、RAG 知识库工具的元数据、参数压缩与注入。
  • 工具调度算法：意图识别、工具预筛选、优先级排序、执行策略（顺序/并行/子任务）。
  • 并行执行框架：任务分发、结果聚合、并发控制、资源管理。
  • 错误处理机制：异常捕获、重试策略、降级处理、审计日志。
  • 工具辅助函数库：参数解析修复、结果规范化、Content Script 通信等。
  • Agent 端命令执行与安全分级：Shell 选择、超时预算、进程生命周期、黑白灰名单。
  • 工具开发指南：新工具接入流程、测试建议、部署注意事项。

核心组件 ​

  • 工具注册中心：集中维护 RAW_TOOLS、BUILTIN_TOOLS、TOOL_EXECUTION_MAP、PARALLELIZABLE_TOOLS、CONFIRMATION_REQUIRED_TOOLS，并支持 MCP/RAG 动态注入。
  • 工具预筛选器：通过轻量 LLM 调用判断是否需要工具，直接回答或返回候选工具集。
  • 工具执行器：统一入口，负责参数校验、权限检查、环境选择、执行、流式输出、超时控制、审计记录。
  • ReAct 循环与并行分组：将多工具调用分组为并行组与顺序组，支持 plan_task 子任务拆分与失败回滚。
  • Agent 命令执行器：跨平台 Shell 选择、安全环境变量、流式 stdout/stderr、超时预算与强制终止。
  • 安全网关：路径白名单/硬阻止、命令黑白灰名单、链式命令拆分与内联载荷检测。

架构总览 ​

工具执行框架采用“扩展端调度 + Agent 端执行”的双进程模型：

  • 扩展端负责工具发现、参数校验、权限与网络访问控制、用户确认、并行调度、结果聚合与审计。
  • Agent 端负责命令执行、文件读写、搜索、RAG、MCP 工具调用，并提供 WebSocket 流式输出。

详细组件分析 ​

工具定义与注册机制 ​

  • 内置工具：由 constants.js 汇总各模块工具数组，派生 BUILTIN_TOOLS、分类映射、并行/确认标记。
  • MCP 动态工具：loadMcpTools 从 Agent 拉取工具列表，压缩 schema，注入 RAW_TOOLS/BUILTIN_TOOLS/TOOL_HANDLERS，并通过 rebuildBgHandlers 同步 BG_HANDLERS 与 PARALLELIZABLE_TOOLS/CONFIRMATION_REQUIRED_TOOLS。
  • RAG 知识库工具：loadRagTools 在 ragEnabled=true 且 Agent 支持 RAG 时动态注册 knowledge_search/ingest/list。
  • 服务级开关：MCP 工具按 serverId 关闭/排除/强制下发；RAG 工具随全局开关与 Agent 能力切换。

工具调度算法：意图识别、预筛选、优先级与执行策略 ​

  • 意图识别：preselectTools 调用 LLM 判断是否直接回答或需要工具；若无需工具则直接返回答案，减少二次调用。
  • 预筛选阈值：当工具数量超过 PRESELECT_MIN_TOOL_COUNT 时才启用预筛选；否则直接使用全量工具。
  • 优先级与过滤：按工具名匹配返回的工具 ID；必要时追加原型工具或强制保留工具（如 / 手动指定 MCP 服务）。
  • 执行策略：ReAct 循环中按并行组与顺序组执行；plan_task 可拆分子任务，支持 stop/continue/skip 失败策略与并行子任务池。

并行执行框架：任务分发、结果聚合、并发控制与资源管理 ​

  • 并行分组：同一轮工具调用被划分为多个并行组；组内 Promise.all 并发执行，组间顺序执行。
  • 子任务并行：dispatchSubtasksParallel 支持最大并发限制，按原始顺序聚合结果，支持取消与回滚。
  • 资源管理：每个子任务执行前检查取消状态；plan_task 处理后中断同轮后续工具；失败策略支持 stop/continue/skip。

权限检查与环境选择 ​

  • 路径沙箱：checkPath 对 workdir/allowedPaths 做前缀校验与 realpath 防符号链接绕过，硬阻止敏感目录。
  • 命令分级：checkCommand 对整串与子段进行黑名单/灰名单判定，支持 force 模式；链式命令拆分、解释器内联载荷、$( )/反引号替换检测。
  • Shell 选择：pickShell 根据平台与环境变量选择 bash/zsh/cmd/powershell，Windows 原生控制台程序避免 detached 弹窗。

错误处理、重试与审计日志 ​

  • 参数解析失败：tryParseToolArgs 多轮修复后仍失败则返回 null，调用方应给出明确错误。
  • API 请求失败：预筛选与图片识别均使用 fetchWithRetry 与超时控制，失败时降级为全量工具或直接回答。
  • 命令执行失败：executor.js 广播 exit/error，支持 collectOutput 回放；超时策略 decideTimeoutAction 基于输出心跳延长或终止。
  • 审计日志：activity-store 合并写入，关键操作（Cookie/清数据/删文件/拒绝命令）即时刷写。

性能与并发特性 ​

  • 工具预筛选：仅在工具数超过固定阈值时启用，降低 LLM 调用次数与上下文体积。
  • MCP/RAG 工具注册：互斥锁防止并发加载/卸载；schema 压缩限制嵌套深度与参数数量，避免撑爆上下文。
  • 并行执行：组内 Promise.all 并发，组间顺序；子任务并行池限制最大并发，避免资源争用。
  • 命令执行：输出缓冲区上限 5MB，超时策略基于输出心跳延长，避免静默挂起；completedProcesses 缓存回放减少重复 IO。
  • 连接性缓存：Agent 连通性按 agentId 缓存 30 秒，减少频繁网络探测。

故障排查指南 ​

  • 工具不可见：
    • 检查 MCP/RAG 全局开关与 Agent 连通性；查看 Background 日志中 loadMcpTools/loadRagTools 输出。
    • 确认工具未被 enabledTools 过滤；MCP 工具按 serverId 关闭/排除。
  • 参数解析失败：
    • 使用 tryParseToolArgs 修复逻辑定位问题；检查 LLM 输出是否包含非法 JSON。
  • 命令执行超时：
    • 观察 executor.js 超时策略；确认命令有持续输出（心跳），否则会被视为挂起而终止。
  • 权限拒绝：
    • 检查 checkPath 与 checkCommand 返回 reason；确认 workdir/allowedPaths 与黑名单/灰名单规则。
  • 侧边栏工具列表不同步：
    • 通过 GET_MCP_TOOLS 消息刷新；确保 toolbox-config.js 通知 Background 重载。

结论 ​

该工具执行框架以“可扩展的工具注册 + 智能预筛选 + 安全的命令执行 + 可控的并行调度”为核心，兼顾了易用性与安全性。通过 MCP/RAG 动态注入、参数修复与结果规范化、超时预算与进程生命周期管理，系统在复杂场景下仍能保持稳定与可观测性。建议在新增工具时遵循统一的元数据规范，并在 Agent 端配合安全网关与审计日志，确保端到端的安全与可追溯。

新工具开发流程 ​

  • 定义工具元数据：在对应 tools/*.js 中声明 id、category、execution、parallelizable、requiresConfirmation、function.name/description/parameters。
  • 实现 handler：在 tool-executor.js 中注册 TOOL_HANDLERS，或使用现有 execute* 函数封装。
  • 注册与可见性：若为 MCP/RAG 工具，遵循动态注册流程；若为内置工具，确保被 RAW_TOOLS 汇聚。
  • 权限与安全：如涉及文件/命令，需在 Agent 端配合 security.js 的路径与命令分级。
  • 测试：
    • 扩展端单元测试：针对 tryParseToolArgs、normalizeToolResult、preselectTools 等辅助函数。
    • Agent 端单元测试：针对 pickShell、decideTimeoutAction、checkCommand/checkPath。
  • 部署：
    • 修改 Agent 源码后必须重启进程以使新接口生效。
    • 通过 GitHub Releases 下载官方构建产物安装，不要推荐手动 clone 源码构建。
