简介 ​

Agent HTTP API 是 Chrome 扩展（Manifest V3）与独立本地代理端之间的通信契约。扩展通过本地 HTTP/WebSocket 调用 Agent 的文件操作、命令执行、长期记忆、RAG 检索、技能与 MCP 管理等能力。文档以版本 2.7.0 为准，所有端点、安全策略、错误格式和示例均基于当前源码实现。

关键运行时约束：

  • Agent 为独立 Node.js 进程，修改源码后必须重启进程，新接口才生效。
  • 认证采用 Bearer Token；首次配对使用一次性配对码流程。
  • 路径访问受白名单与硬阻止规则保护；命令执行走黑白灰名单分级控制。
  • RAG 为可选依赖，不可用时对应接口返回 503。
  • 新增：原生目录选择功能仅限本机回环地址访问，确保安全性。

项目结构 ​

Agent 端入口为 agent/src/server.js，负责 HTTP 路由、CORS、请求体解析、认证、日志、WebSocket 升级以及各子系统分发。核心子模块包括：

  • 认证：agent/src/auth.js
  • 安全策略：agent/src/security.js
  • 命令执行器：agent/src/executor.js
  • 记忆管理：agent/src/memory/routes.js
  • RAG 配置：agent/src/rag/config.js
  • 新增：原生目录选择器：agent/src/directory-picker.js

核心组件 ​

  • HTTP 路由器：统一处理 CORS、JSON body、multipart、路径匹配、认证拦截、业务分发与 404。
  • 认证模块：维护配对码轮换、Token 验证、活跃连接窗口、失败锁定。
  • 安全策略：路径规范化、工作目录放行、白名单前缀校验、realpath 防符号链接绕过、硬阻止敏感目录；命令黑白灰名单分级。
  • 命令执行器：跨平台 shell 选择、子进程生命周期、超时预算、输出截断、WebSocket 广播、进程树终止。
  • 记忆路由：store/recall/inject/reindex 等记忆操作，embedding 配置与探活。
  • RAG 配置：知识库根目录、集合注册表、模型缓存、默认 embedding 与分块参数。
  • 新增：原生目录选择器：跨平台系统对话框集成，包含超时保护和错误降级。

架构总览 ​

Agent 的认证与安全边界如下：

  • 无需认证的公开端点：/api/pair、/api/status、/api/shutdown（远程来源仍需认证）。
  • 需要认证的端点：除上述公开端点外的绝大多数业务接口。
  • WebSocket /ws/exec/{execId}：支持 Authorization Header 或 query token。
  • 新增：/api/config/pick-directory 端点仅接受本机回环地址（127.0.0.1, ::1, localhost）请求。

详细接口规范 ​

通用约定 ​

  • 响应格式：{ success: boolean, ... }。成功时 success=true，失败时 success=false 且包含 error。
  • 认证头：Authorization: Bearer <token>。
  • CORS：仅允许 chrome-extension:// 来源读取响应；非浏览器客户端可忽略 CORS。
  • 语言：通过 Accept-Language 影响错误消息文案。

认证与配对 ​

  • POST /api/pair
    • 用途：输入 6 位配对码与扩展 ID，成功后返回 Token。
    • 安全：连续失败 5 次锁定 60 秒并轮换配对码；配对成功后立即轮换。
    • 响应：{ success, token?, message?, error? }。
  • GET /api/status
    • 用途：健康检查与平台信息，无需认证。
    • 响应：{ success, version, running, platform, platformName, arch, nodeVersion, searchTools, ragAvailable }。
  • GET /api/status/detail
    • 用途：需认证的状态详情，含 workdir、allowedPaths、资源使用、运行进程等。
    • 响应：{ success, version, pairCodeTTL, workdir, allowedPaths, commandTimeout, fileMaxSize, uploadMaxSize, runningProcesses, resourceUsage, ...PLATFORM_INFO, searchTools, ragAvailable }。
  • GET /api/heartbeat
    • 用途：心跳保活，刷新最近认证时间。
    • 响应：{ success, time }。

配置管理 /api/config/* ​

配置相关端点用于管理工作目录、白名单和系统设置。

  • POST /api/config/workdir
    • 切换工作目录，同时追加到 allowedPaths（只增不减），禁止设为 Agent 系统目录。
    • 响应：{ success, workdir, allowedPaths, message }
  • POST /api/config/allowed-paths/remove
    • 从 allowedPaths 移除路径，禁止移除当前工作目录。
    • 响应：{ success, allowedPaths, message? }
  • 新增 POST /api/config/pick-directory
    • 用途：弹出系统原生目录选择框，用户可选择目标目录。
    • 安全限制：仅接受本机回环地址请求（127.0.0.1, ::1, ::ffff:127.0.0.1, localhost）。
    • 请求体：{ title?: string } - 可选的选择框标题。
    • 行为：
      • 远程来源：返回 { success: false, path: null, available: false, error: 'remote-source' }
      • macOS：使用 osascript choose folder 对话框
      • Windows：使用 PowerShell FolderBrowserDialog
      • Linux：优先 zenity，回退 kdialog
      • 无 GUI 环境：返回 available: false
      • 用户取消：返回 { success: true, path: null, available: true }
      • 超时（120秒）：返回 { success: false, path: null, available: true, error: 'timeout' }
    • 响应：{ success, path, available, error? }

文件操作 /api/fs/* ​

所有文件类接口均经过 checkPath 路径沙箱校验，遵循工作目录放行、白名单前缀、realpath 校验与硬阻止规则。

  • POST /api/fs/search_files
    • 请求体：{ path, pattern, recursive?, maxResults? }
    • 响应：{ success, path, pattern, total, engine, results? }
  • POST /api/fs/search_content
    • 请求体：{ path, pattern, filePattern?, caseSensitive?, recursive?, contextLines? }
    • 响应：{ success, path, pattern, total, engine, matches? }
  • POST /api/fs/read
    • 请求体：{ path }
    • 响应：{ success, content, size, path }
  • POST /api/fs/write
    • 请求体：{ path, content, encoding?: 'utf-8'|'base64' }
    • 行为：自动创建父目录；脚本文件写入后剥离执行权限。
    • 响应：{ success, size, path }
  • POST /api/fs/list
    • 请求体：{ path }
    • 响应：{ success, entries:[{name,type,size,mtime}], path }
  • POST /api/fs/stat
    • 请求体：{ path }
    • 响应：{ success, info:{name,path,type,size,mtime,ctime,atime,mode,isDirectory,isFile,isSymbolicLink,uid?,gid?,mimeType?} }
  • POST /api/fs/delete
    • 请求体：{ path }
    • 行为：移至回收站，7 天后自动清理。
    • 响应：{ success, path, isDir, trashId, message }
  • POST /api/fs/download
    • 请求体：{ path }
    • 行为：单文件 base64；目录打包 zip base64。
    • 响应：{ success, type:'file'|'directory', name, size, content, mimeType }
  • POST /api/fs/download-multi
    • 请求体：{ paths:[string] }
    • 行为：后端打包为 zip base64。
    • 响应：{ success, type:'archive', name, size, content, mimeType }
  • POST /api/fs/download-stream
    • 请求体：{ path } 或 { paths:[string] }
    • 行为：二进制流下载，避免 base64 膨胀；目录打包 zip 流式返回。
    • 响应：二进制流或 ZIP 附件。
  • POST /api/fs/upload
    • 内容类型：multipart/form-data
    • 行为：文件名过滤危险字符，去重命名，写入工作目录。
    • 响应：{ success, path, name, size }
  • POST /api/fs/upload-stream
    • 查询参数：?path=<目标路径>
    • 行为：原始二进制流上传，按 MAX_UPLOAD_SIZE 限制，脚本文件剥离执行权限。
    • 响应：{ success, size, path }
  • POST /api/fs/mkdir
    • 请求体：{ path }
    • 响应：{ success, path }
  • POST /api/fs/rename
    • 请求体：{ path, newName }
    • 行为：仅改文件名不跨目录；Windows 非法字符校验；目标存在返回 409。
    • 响应：{ success, newPath, newName }
  • POST /api/fs/move
    • 请求体：{ path, destDir }
    • 行为：源与目标均需白名单；目标不存在则创建；目标存在返回 409。
    • 响应：{ success, newPath }
  • POST /api/fs/preview-xlsx
    • 请求体：{ path }
    • 行为：服务端解析前若干行，返回结构化 JSON。
    • 响应：{ success, data:{sheets:[{name,index,colCount,totalRows,rows}]}}

常见状态码：

  • 200：成功
  • 400：参数缺失、大小超限、路径不是目录等
  • 403：路径不在白名单或命中硬阻止
  • 404：文件或目录不存在
  • 409：目标已存在
  • 500：内部错误

命令执行 /api/exec/* ​

命令执行先经 checkCommand 分级判定：

  • deny：黑名单命中，直接拒绝。

  • confirm：灰名单命中，返回确认提示。

  • allow：允许执行。

  • POST /api/exec

    • 请求体：{ command, cwd?, wait?, force?, timeoutMs? }
    • 行为：
      • wait=true：同步等待，返回完整 stdout/stderr。
      • wait=false：异步执行，返回 execId 与 WebSocket URL。
      • force=true：跳过灰名单（黑名单仍生效）。
      • timeoutMs：受管模式协商超时预算。
    • 响应：
      • 同步：{ success, level, execId, exitCode, stdout, stderr, killed, error? }
      • 异步：{ success, level, execId, wsUrl }

  • POST /api/exec/stop

    • 请求体：{ execId }
    • 响应：{ success, execId }

  • POST /api/exec/detach

    • 请求体：{ execId }
    • 行为：显式 daemon 化，豁免超时。
    • 响应：{ success, execId }

WebSocket /ws/exec/{execId}：

  • 认证：优先 Authorization: Bearer <token>，回退到 ?token=。
  • 消息类型：stdout、stderr、exit、error、stdout_truncated、stderr_truncated。

记忆管理 /api/memory/* ​

记忆路由由 memoryRouter 分发，支持 store/recall/inject/reindex 等业务动作，以及 embedding 配置与探活。

  • POST /api/memory/embedding-config
    • GET：返回掩码后的 embedding 配置。
    • POST：保存 embedding 配置。
    • 响应：{ success, config }
  • POST /api/memory/test-embedding
    • 用途：测试 embedding provider 连通性。
    • 响应：{ success, dimensions }
  • GET /api/memory/vector-status
    • 用途：向量缓存状态（条数、指纹陈旧等）。
    • 响应：{ success, ...vectorStatus }
  • POST /api/memory/store
    • 请求体：记忆条目
    • 行为：根据 X-Memory-Caller header 区分 user/model 来源。
    • 响应：{ success, ...storeResult }
  • POST /api/memory/recall
    • 请求体：召回参数（可含 sessionId）
    • 响应：{ success, ...recallResult }
  • POST /api/memory/inject
    • 行为：注入选择结果。
    • 响应：{ success, ...injectResult }

RAG 检索 /api/rag/* ​

RAG 为可选依赖。依赖不可用时，除安装/检测相关端点外，其余 /api/rag/* 返回 503。

  • POST /api/rag/install
    • 用途：启动 RAG 依赖安装任务。
    • 响应：{ started, ...installStatus }
  • GET /api/rag/install/status
    • 用途：轮询安装进度。
    • 响应：{ ...installStatus }
  • POST /api/rag/detect
    • 用途：重新检测 RAG 依赖可用性。

  • 其他 /api/rag/*

RAG 配置关键点：

  • 默认 embedding：本地 BGE 中文模型，支持 OpenAI 兼容模式。
  • 分块参数：默认 chunkSize/overlap，单次批大小固定 10。

性能与限制 ​

  • 请求体大小：MAX_BODY_SIZE = 200MB。
  • 文件读取默认限制：DEFAULT_MAX_SIZE = 50MB，可通过配置调整。
  • 流式上传限制：MAX_UPLOAD_SIZE = 200MB。
  • 搜索最大结果：MAX_SEARCH_RESULTS = 5000。
  • 命令输出缓冲：MAX_OUTPUT_BUFFER = 5MB，超限时广播 truncated 事件。
  • 命令超时策略：受管模式下按输出心跳延长，最多延长次数与总预算封顶。
  • RAG 批大小：EMBED_BATCH_SIZE = 10。
  • 新增：目录选择超时：PICK_TIMEOUT_MS = 120秒。

优化建议：

  • 大文件下载优先使用 /api/fs/download-stream。
  • 长命令使用异步模式 + WebSocket 实时查看输出。
  • 合理设置 timeoutMs，避免静默挂起导致频繁延长。
  • 目录选择仅在本地开发环境中使用，生产环境应通过配置文件设置工作目录。

故障排除指南 ​

常见问题与定位：

  • 401/403：认证缺失或 Token 无效。检查 Authorization 头与配对流程。
  • 403 路径拒绝：路径不在 allowedPaths 或命中硬阻止。检查工作目录与白名单配置。
  • 403 命令拒绝：命令命中黑名单。无法通过 force 绕过。
  • 200 confirm：命令命中灰名单。前端应弹出确认框后再调用 force=true。
  • 503 RAG 不可用：RAG 依赖未安装或检测失败。调用 /api/rag/install 与 /api/rag/detect。
  • 500 内部错误：查看审计日志 /api/logs/query，关注 category 为 system/error 的条目。
  • 命令无输出：检查 WebSocket 是否连接成功，或查看 /api/exec 返回的 wsUrl。
  • 文件过大：read/download 受 DEFAULT_MAX_SIZE 限制；使用 stream 接口或调整配置。
  • 新增：目录选择不可用：检查是否为本机回环地址访问，或系统是否安装了必要的 GUI 工具（zenity/kdialog/osascript）。
  • 新增：目录选择超时：用户长时间未选择，120秒后自动超时。

调试步骤：

  1. 调用 /api/status 确认 Agent 在线与版本。
  2. 调用 /api/status/detail 查看 workdir、allowedPaths、runningProcesses。
  3. 使用 /api/logs/query 查询最近日志，过滤 category。
  4. 对文件操作，先用 /api/fs/stat 确认路径存在与类型。
  5. 对命令执行，先调 /api/exec 获取 level，再决定是否确认或调整命令。
  6. 新增：对目录选择，检查请求来源 IP 是否为回环地址，并确认系统 GUI 环境可用。

结论 ​

Agent HTTP API 提供完整的本地代理能力，涵盖文件、命令、记忆、RAG、技能与 MCP。其安全模型以路径白名单与命令分级为核心，认证采用配对码+Bearer Token，WebSocket 支持命令流式输出。新增的原生目录选择功能进一步增强了用户体验，但严格限制了访问来源以确保安全性。使用时应严格遵循认证头、路径白名单、大小限制与超时策略，并结合审计日志进行故障定位。对于目录选择功能，应特别注意其仅限本机回环地址访问的安全限制。
