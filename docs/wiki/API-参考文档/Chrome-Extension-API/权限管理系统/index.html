引言 ​

本文面向权限管理系统，围绕 Chrome 扩展 Manifest V3 的权限声明、运行时权限检查机制、不同权限级别的安全模型与访问控制策略展开。文档重点说明 manifest.json 中的基础权限、主机权限和运行时权限分类与用途，解释敏感操作的用户确认流程，并给出权限最小化实践、常见问题解决方案与调试方法。

本项目为双进程架构：Chrome 扩展端（Manifest V3，src/ 目录，版本 2.3.1）与独立本地代理端 Agent（Node.js，agent/src/server.js 入口）。扩展端通过本地 HTTP/WebSocket 调用 Agent 的文件读写、命令执行、长期记忆与 RAG 能力；Agent 源码修改后必须重启进程，新接口才生效。该运行时约束对权限与安全审计同样重要：扩展侧权限不能替代 Agent 侧安全边界。

项目结构 ​

权限相关代码主要分布在以下位置：

  • 权限声明：根目录 manifest.json
  • 权限理由与主机权限说明：docs/Chrome商店上架发布内容.md
  • 工具级权限与确认开关：src/background/constants.js
  • 用户确认流程与 ReAct 循环集成：src/background/react-loop.js

  • 内网网络访问控制：src/shared/network-scope.js
  • 敏感操作审计日志：src/background/activity-store.js

核心组件 ​

权限管理由“声明层 + 决策层 + 执行层 + 审计层”构成：

  • 声明层：manifest.json 声明基础权限、主机权限与 CSP；Chrome 商店文档提供逐项权限理由。
  • 决策层：constants.js 定义工具确认开关、内网访问策略默认值；network-scope.js 实现内网访问白名单判定。
  • 执行层：react-loop.js 在 ReAct 循环中拦截敏感工具调用并发起用户确认；tool-executor.js 负责工具执行、命令拒绝与结果处理。
  • 审计层：activity-store.js 对不可逆操作与授权边界事件进行即时审计落盘。

架构总览 ​

权限系统的关键交互如下：

  • 扩展安装时，浏览器根据 manifest.json 授予基础权限与主机权限。
  • 运行期，ReAct 循环遇到敏感工具或特定 action 时，react-loop.js 暂停超时并请求用户确认。
  • 用户确认后，tool-executor.js 执行工具；若用户拒绝，则记录拒绝原因并返回失败。
  • 涉及网络访问时，network-scope.js 按“总闸 + 白名单”策略判定是否允许内网访问。
  • 所有敏感操作与授权边界事件写入 activity-store.js 的审计日志。

详细组件分析 ​

manifest.json 权限声明与用途 ​

manifest.json 定义了扩展的基础权限、主机权限与内容安全策略。基础权限包括 activeTab、storage、unlimitedStorage、sidePanel、scripting、bookmarks、history、downloads、notifications、tabs、tabGroups、cookies、offscreen、clipboardRead、clipboardWrite、commands、alarms、debugger、webNavigation。主机权限包含 <all_urls>、http:///、https:///。CSP 限制 extension_pages 仅加载自身脚本与对象。

Chrome 商店文档对每项权限提供了用途说明，例如：

  • activeTab：用户唤起助手时访问当前激活标签页，读取页面内容、显示划词工具栏、执行用户请求的操作。
  • scripting：按需注入内容脚本，实现页面内容读取与元素交互。
  • debugger：用户主动调用的高级页面调试工具，附着到当前标签页录制网络请求/响应，空闲自动脱离。
  • webNavigation：枚举 iframe 帧结构以正确定位嵌套框架中的元素，不监听导航事件。
  • 主机权限 <all_urls>：助手必须在用户选择的任意网站上工作，仅用于读取页面内容、执行用户明确请求的页面操作、显示划词工具栏。

运行时权限检查与用户授权流程 ​

权限检查并非仅在安装阶段完成，而是在工具执行路径中进行二次校验与用户确认：

  • react-loop.js 在 ReAct 循环中检测工具级确认（requiresConfirmation）与 action 级确认（如 manage_tab 的 close），并在开启 toolConfirmationEnabled 时弹出确认对话框。
  • 用户拒绝时，loop 记录取消状态并返回错误；用户同意后恢复超时计时并继续执行。
  • tool-executor.js 对命令执行路径提供用户拒绝处理，记录审计日志并返回失败结果。

权限级别与安全模型 ​

权限级别可划分为三类：

  • 基础权限：扩展功能所需的最小浏览器 API 集合，如 storage、tabs、notifications。
  • 主机权限：对网页内容的访问范围，<all_urls> 表示可在任意网站工作，但实际使用需受用户意图与代码逻辑约束。
  • 运行时权限：工具执行时的动态确认与策略判定，如敏感操作确认、内网访问白名单。

安全模型要点：

  • 工具确认：通过 constants.js 的 CONFIRMATION_REQUIRED_TOOLS 与 CONFIRMATION_ACTION_MAP 精确控制哪些工具或 action 需要用户确认。
  • 内网访问：network-scope.js 采用“总闸 + 白名单”策略，公网目标放行，内网目标需显式白名单；总闸关闭或白名单为空均拒绝。
  • 审计日志：activity-store.js 对 cookie_write、page_data_clear、file_delete、command_exec 等不可逆操作与授权边界事件即时落盘。

权限最小化原则与实践指南 ​

权限最小化原则要求：

  • 仅申请必要权限：manifest.json 中的权限应与实际代码用途一致，避免过度声明。
  • 用户意图驱动：所有敏感操作必须由用户主动发起，未经用户请求不收集或上传数据。
  • 动态确认：对高风险工具或 action 启用 requiresConfirmation，并通过 toolConfirmationEnabled 控制全局开关。
  • 内网访问白名单：默认关闭总闸，白名单为空时仍拒绝；仅放行显式配置的主机。
  • 审计追踪：对不可逆操作与授权边界事件即时落盘，便于事后审计与问题定位。

最佳实践：

  • 新增工具时，评估其风险等级，必要时设置 requiresConfirmation。
  • 新增网络访问时，优先使用公网 URL；如需内网访问，需在设置页开启总闸并逐台主机加白名单。
  • 对用户可见文案使用 i18n，避免硬编码；示例不应体现缓存写法的做法。
  • 构建验证统一走 npm run build:silent，确保权限相关改动不影响整体构建。

常见权限问题与调试方法 ​

常见问题：

  • 权限未生效：检查 manifest.json 是否正确声明权限，以及 Chrome 商店权限理由是否与代码用途一致。
  • 用户确认未弹出：确认 toolConfirmationEnabled 是否开启，以及工具或 action 是否在 CONFIRMATION_REQUIRED_TOOLS 或 CONFIRMATION_ACTION_MAP 中。
  • 内网访问被拒：检查 networkAccessEnabled 是否开启，allowedHosts 是否包含目标主机；注意总闸开启但白名单为空仍会拒绝。
  • 命令执行被拒绝：查看 tool-executor.js 的命令拒绝日志，确认是否为黑名单命令或用户拒绝。

调试方法：

  • 使用 Chrome DevTools 的 Extension 面板检查权限状态与消息传递。
  • 查看 activity-store.js 的审计日志，定位敏感操作与授权边界事件。
  • 在 react-loop.js 中增加调试日志，观察确认流程与超时控制。
  • 在 network-scope.js 中打印 classifyUrlTarget 与 decideNetworkAccess 的结果，确认内网判定逻辑。

依赖关系分析 ​

权限系统的依赖关系如下：

  • manifest.json 依赖 Chrome 商店文档提供权限理由。
  • constants.js 提供默认配置与工具确认映射，被 react-loop.js 与 tool-executor.js 引用。
  • react-loop.js 依赖 constants.js 的配置，并调用 tool-executor.js 执行工具。
  • tool-executor.js 依赖 network-scope.js 进行内网访问判定，并调用 activity-store.js 记录审计日志。
  • activity-store.js 依赖 chrome.storage.local 存储审计日志。

性能与安全性考量 ​

性能方面：

  • 工具结果截断与卸载：react-loop.js 对大结果进行智能截断或卸载到 Agent workspace，防止上下文溢出与 sendMessage 限制。
  • 超时控制：react-loop.js 对澄清工具与工具执行设置超时，避免任务悬挂。
  • 缓存机制：react-loop.js 对工具结果进行 TTL 缓存，减少重复计算。

安全方面：

  • 内网访问白名单：network-scope.js 严格限制内网访问，避免模型被提示词诱导攻击本机服务。
  • 命令执行安全：tool-executor.js 对命令执行进行用户确认与拒绝处理，结合 Agent 端的三级安全模型（黑名单、灰名单、白名单）。
  • 审计日志：activity-store.js 对敏感操作即时落盘，支持事后审计与问题定位。

故障排查指南 ​

排查步骤：

  1. 检查 manifest.json 权限声明是否与 Chrome 商店文档一致。
  2. 确认 toolConfirmationEnabled 是否开启，以及工具或 action 是否在确认列表中。
  3. 检查 networkAccessEnabled 与 allowedHosts 配置，确保内网访问策略符合预期。
  4. 查看 activity-store.js 的审计日志，定位敏感操作与授权边界事件。
  5. 在 react-loop.js 与 tool-executor.js 中增加调试日志，观察确认流程与执行路径。

常见问题解决：

  • 权限未生效：重新安装扩展或刷新权限状态。
  • 用户确认未弹出：检查工具配置与全局开关。
  • 内网访问被拒：添加目标主机到白名单，并确保总闸开启。
  • 命令执行被拒绝：查看命令类型与用户确认状态。
