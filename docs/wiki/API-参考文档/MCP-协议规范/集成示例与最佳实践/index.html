引言 ​

本文件面向希望将外部工具接入 AI Helper 的开发者，聚焦 MCP（Model Context Protocol）在该项目中的集成方式、客户端调用流程、错误处理、安全策略、性能优化与调试方法。文档同时给出 Python 与 Node.js 两种 MCP Server 的实现模式参考，帮助读者快速搭建可被 Agent 调用的工具服务。

本项目采用双进程架构：Chrome 扩展端（Manifest V3，src/）与独立本地代理端 Agent（Node.js，agent/src/server.js）。两端版本号保持同步，当前以 2.3.1 为准。Agent 通过 HTTP/WebSocket 暴露接口，扩展端通过本地 Agent Client 调用；MCP 工具由 Agent 自动发现并注入到扩展端的工具列表中，供 ReAct 执行循环使用。

核心组件 ​

  • MCP 客户端封装（client.js）：负责根据传输类型创建连接、建立会话、列出工具、调用工具、断开连接。
  • MCP 注册表（registry.js）：维护已连接的多个 MCP Server，提供统一工具发现与调用入口。
  • MCP 配置（mcp-config.js）：持久化 MCP Server 列表，支持增删改查与启用状态切换。
  • Agent 路由（server.js）：暴露 MCP 管理 API（添加/删除/连接/断开/启用/禁用/工具列表/工具调用），并对 stdio 命令进行安全检查。
  • 扩展端 Agent 客户端（local-agent-client.js）：封装对 Agent 的 MCP 相关 HTTP 请求。
  • 工具加载器（tool-executor.js）：从 Agent 拉取 MCP 工具列表，合并到扩展端工具集，参与预筛选与执行。

详细组件分析 ​

MCP 客户端封装（client.js） ​

  • 传输层抽象：支持 stdio、SSE、Streamable HTTP、WebSocket 四种传输。
  • 连接生命周期：connect() 创建传输、初始化 SDK Client、获取版本与能力、列出工具、标记 connected。
  • 工具调用：callTool() 封装 JSON-RPC 调用，过滤 text 类型内容，统一 success/content/raw 返回结构。
  • 断开与状态：disconnect() 关闭 SDK 与传输；getStatus() 返回连接状态与工具数量。

MCP 注册表（registry.js） ​

  • 启动时初始化：initializeMcpRegistry() 遍历配置中启用的 Server，逐个连接并缓存。
  • 工具发现：getMcpTools() 扁平化所有已连接 Server 的工具，附带 serverId、serverName、inputSchema。
  • 工具调用：callMcpTool() 校验 Server 存在且已连接，转发到对应 client.callTool。
  • 连接管理：connectMcpServer()/disconnectMcpServer() 支持单 Server 重连与断开。
  • 生命周期：shutdownMcpRegistry() 清理所有连接。

Agent 路由与 MCP API（server.js） ​

  • MCP 管理接口：
    • POST /api/mcp/servers：添加 Server，校验 id/url/command，stdio 命令走 checkCommand 安全分级。
    • DELETE /api/mcp/servers：删除 Server。
    • POST /api/mcp/servers/connect：连接指定 Server。
    • POST /api/mcp/servers/disconnect：断开指定 Server。
    • POST /api/mcp/servers/toggle：启用/禁用 Server，禁用时先断开。
    • POST /api/mcp/call：调用工具，校验 serverId/toolName，转发到 registry.callMcpTool。
  • GET 接口：
    • GET /api/mcp/servers：返回所有 Server 状态与工具数。
    • GET /api/mcp/tools：返回扁平化工具列表，可选 serverId 过滤。

性能考虑 ​

  • 连接池管理：registry.js 维护 Map<serverId, McpClient>，避免重复连接；toggle 时先断开再启用，减少资源泄漏。
  • 批量调用：registry.getMcpTools() 扁平化工具列表，扩展端一次性注入，减少多次网络往返。
  • 缓存策略：mcp-config.js 使用 mtime 缓存配置；tool-executor.js 在加载前清理旧工具，避免冗余计算。
  • 传输选择：优先使用官方推荐的 Streamable HTTP，降低长连接复杂度；stdio 适合本地 CLI 场景。
  • 超时与限流：server.js 对重启/更新等敏感操作设置冷却时间，防止 DoS；npm 安装带超时保护。

安全与合规 ​

  • 命令安全检查：stdio 传输的 command+args 经 checkCommand 分级（deny/confirm/pass），防止 MCP 成为命令管控后门。
  • CORS 与来源限制：仅放行 chrome-extension:// 来源，恶意网页无法跨域读取无认证端点。
  • 认证与令牌：除 /api/status 与 /api/pair 外，其他接口需 Bearer Token；/api/shutdown 远程来源仍需认证。
  • 输入大小限制：parseBody/parseMultipartBody 限制 MAX_BODY_SIZE，防止大体积请求。
  • 输出过滤：client.js 仅提取 text 类型内容，避免富文本或二进制直接透传。

  • MCP 工具未出现在工具列表：
    • 检查全局 MCP 开关是否开启。
    • 确认 Agent 已连接且 Server 已连接。
    • 查看 Server 是否被禁用或被排除。
  • 工具调用失败：
    • 检查 serverId 与 toolName 是否正确。
    • 查看 MCP Server 是否返回 error 或 isError。
    • 确认传输配置（url/command/headers/env）正确。
  • stdio 命令被拒绝：
    • 检查 command+args 是否命中 deny 规则。
    • 若需要确认，前端应引导用户确认后再提交。
  • 连接不稳定：
    • 优先使用 Streamable HTTP 或 WebSocket。
    • 检查网络可达性与证书（HTTPS/WSS）。
  • 配置未生效：
    • 修改 Agent 源码或配置后需重启 Agent 进程。
    • 确认 mcp_servers.json 权限与路径正确。

附录：Python 与 Node.js MCP Server 实现模式 ​

以下为两类常见 MCP Server 实现模式的参考思路，帮助读者快速搭建可被 Agent 调用的工具服务。注意：这些模式为概念性说明，实际实现需遵循 MCP 协议规范与本项目使用的 SDK 行为。

  • 同步工具（Node.js）

    • 使用 @modelcontextprotocol/sdk/server 创建 Server。
    • 定义 tools/list 返回工具 schema。
    • 在 tools/call 中同步执行业务逻辑，返回 text 内容。
    • 通过 stdio 传输与 Agent 通信。

  • 异步工具（Python）

    • 使用 MCP Python SDK 定义异步 handler。
    • 在 tools/call 中执行异步任务（如数据库查询、API 调用）。
    • 返回结构化 content，Agent 端会提取 text 片段。

  • 流式工具（Node.js/Python）

    • 使用 SSE 或 Streamable HTTP 传输。
    • 在 tools/call 中逐步推送增量内容，最终 finalize。
    • 注意控制流式输出的大小与速率，避免阻塞。

  • 文件操作工具（Python）

    • 在 tools/call 中执行安全的文件读写（受限于工作目录与白名单）。
    • 返回文件摘要、路径、大小等信息，避免直接返回大文件内容。
    • 结合 Agent 的文件上传/下载接口，实现大文件分块处理。
