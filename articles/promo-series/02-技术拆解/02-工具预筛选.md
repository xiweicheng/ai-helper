# 工具预筛选：44 个工具如何智能选出 5-10 个

> 本文来自 AI Helper 项目的真实工程实践。AI Helper 是一个开源的 Chrome 智能助手扩展，采用 ReAct 推理循环架构，内置 44 个工具覆盖内容提取、页面交互、表单输入、标签管理、存储管理、网络请求、媒体输出、调试开发、AI 协作、Agent 服务等场景。

## 问题：44 个工具的定义有多吃 Token

AI Helper 内置了 44 个工具，每个工具的 JSON Schema 定义（名称、描述、参数类型、参数说明）大约占 200 tokens。44 个工具全量传给 LLM，光工具定义就吃掉约 8800 tokens。

这带来两个问题：

1. **Token 消耗巨大**——每次 API 调用都要把所有工具定义塞进去，多轮推理循环下来费用可观。
2. **干扰决策**——用户只是想提取一下页面文本，LLM 却要从 44 个工具里大海捞针，无关工具的定义会干扰模型的选择判断。

有没有办法在主模型调用前，先筛选出跟当前问题相关的少数工具？

## 方案：跑一次轻量 API 预检

思路很直接：在 ReAct 主循环启动前，先调一次轻量 API 调用，让模型根据用户问题从全量工具列表中选出相关的工具子集。主模型只用这个子集来推理。

这就是 `tool-preselector.js` 做的事情。核心流程：

```
用户提问 → 提取最近对话历史 → 构建工具清单 → 轻量 API 调用 → 解析结果 → 返回工具子集
```

## 实现：tool-preselector.js

### 可配置的触发门槛

预筛选不是无脑开启的。先看工具数量是否超过阈值：

```js
export async function preselectTools(messages, model, tools, apiParams = {}, callCount = 1) {
  const config = await getStoredConfig();
  const preselectMinToolCount = config.reactConfig?.preselectMinToolCount ?? 3;

  // 工具数量未超过阈值，直接跳过预筛选
  if (totalCount <= preselectMinToolCount) {
    return { type: 'tools', tools, executionLog: [...] };
  }
  // ... 继续预筛选
}
```

默认最小触发数量是 3（用户可配置）。这意味着如果你只启用了 3 个工具，预筛选不会触发，避免为了一点 Token 节省而额外消耗一次 API 调用。

### 构建精简的工具清单

预筛选不需要把完整的工具定义发给模型——那样就没有节省的意义了。只提取名称、描述和最多 3 个参数名：

```js
function buildPreselectPrompt(tools) {
  const toolList = tools.map(t => {
    const params = t.function.parameters?.properties;
    const paramNames = params ? Object.keys(params).slice(0, 3) : [];
    const paramInfo = paramNames.length > 0 ? ` (params: ${paramNames.join(', ')})` : '';
    return `- ${t.function.name}${paramInfo}: ${t.function.description}`;
  }).join('\n');

  return `You are an intelligent assistant. Based on the user's question, determine whether tools are needed.
// ...
Available tools:
${toolList}

Output in JSON format:
- For direct answers: {"type": "answer", "data": "your answer text"}
- When tools are needed: {"type": "tools", "data": ["tool_name_1", "tool_name_2"]}`;
}
```

这个精简清单只有几 KB，比 44 个工具的完整定义小一个数量级。

### 关键设计：预筛选能直接回答简单问题

预筛选 API 有两种返回模式，这是一个重要的设计决策：

- **`{"type": "answer", ...}`**——模型认为问题太简单（打招呼、常识问答），直接给出答案，跳过整个 ReAct 循环。
- **`{"type": "tools", ...}`**——返回需要的工具名称列表，进入主循环。

```js
const parsed = parsePreselectResponse(rawContent);

if (parsed.type === 'answer') {
  // 简单问题，模型直接回答，不需要二次调用
  return { type: 'answer', content: parsed.content, executionLog: [...] };
}

// parsed.type === 'tools'
const selectedNamesLower = new Set(parsed.tools.map(n => String(n).toLowerCase()));
const selectedTools = tools.filter(t =>
  selectedNamesLower.has(t.function.name.toLowerCase())
);
```

对于简单问题，预筛选本身就完成了回答——省掉了一整轮主模型调用，Token 节省 100%。

### 鲁棒的解析：三层兜底

模型返回的结果不能假设永远是规范 JSON。`parsePreselectResponse` 实现了三层解析策略：

1. **直接 JSON.parse**——优先尝试标准 JSON 格式。
2. **代码块提取**——从 ` ```json ... ``` ` 代码块中提取。
3. **括号匹配**——从文本中查找 `[` 到 `]` 的配对，尝试解析为工具数组。

还包含常见的 JSON 修复逻辑：移除尾部多余逗号、给未加引号的元素补引号等。

### 提取对话历史作为上下文

预筛选不是只看最后一条消息。`extractHistoryContext` 会提取最近 4 条 user+assistant 对话消息（排除 system 和 tool 消息），截断后作为上下文一并发给预筛选模型。这样模型能理解"上一轮在聊什么"，更准确地判断需要哪些工具。

## 效果

在实际使用中，大部分场景下 44 个工具会被缩减到 5-10 个相关工具。Token 消耗降低 60-80%，而且因为工具选择更聚焦，任务完成质量反而有所提升——模型不再被无关工具定义干扰。

## 设计考量：默认关闭

预筛选本身也要消耗一次 API 调用，所以它默认是关闭的。用户可以在配置中开启：

- **适合开启的场景**：工具数量多（20+）、API 费用敏感、希望减少 Token 消耗。
- **不适合开启的场景**：工具数量少（10 个以内）、对延迟敏感（多一次 API 往返增加延迟）、使用不支持 `response_format: json_object` 的模型。

## 总结

工具预筛选的核心思想很简单：**与其让主模型在 44 个工具里大海捞针，不如先花一次轻量调用做初筛**。这个方案在工具数量多的 Agent 系统中通用性很强——关键是控制好预筛选本身的成本和解析的鲁棒性。
