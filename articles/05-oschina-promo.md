## 问题的根源

市面上的 AI 工具可以分为两类：

**第一类：网页端 AI 对话（ChatGPT、Kimi、通义千问）**
- 它们擅长"聊天"，但对你的浏览器一无所知
- 你想让它帮你提取网页数据？先手动复制粘贴
- 你想让它帮你操作网页？对不起，做不到

**第二类：浏览器 AI 插件**
- 大部分只能在侧边栏和你聊天，本质上还是"ChatGPT 套了个壳"
- 少数能做网页总结的，也只是读一读页面文本，谈不上"操控"
- 跟本地文件的交互几乎为零

**根本原因**：现有的 AI 工具都是"浏览器的访客"，而不是"浏览器的一部分"。它们没有接入浏览器的能力体系——无法点击按钮、无法填写表单、无法操作标签页、无法访问本地文件系统。

## AI Helper 是什么

[AI Helper](https://github.com/xiweicheng/ai-helper) 是一个开源的 Chrome 浏览器智能助手扩展，它做的事情很简单也很彻底：

> **把大语言模型的推理能力，和浏览器的全部操控能力，深度结合在一起。**

它不是又一个"侧边栏聊天机器人"。它是一个**完整的 AI Agent 平台**，运行在你的浏览器里，采用 **ReAct（Reasoning + Acting）推理循环**架构，能够像人类一样：观察网页 → 思考策略 → 执行操作 → 分析结果 → 继续推理 → 完成任务。

```
用户任务 → AI 思考 → 决定调用工具 → 执行 → 分析结果 → 继续推理 → 完成
```

用一句话概括它的能力边界：

> ChatGPT 的对话能力 + 浏览器的操作能力 + 多智能体协作 + 本地文件/命令执行，全部装在你的浏览器侧边栏里。

## 核心能力拆解

### 1. 50+ 内置工具：浏览器就是你的操作系统

AI Helper 不是只能"读网页"。它内置了 9 大类 50+ 个工具，覆盖了你能想到的几乎所有浏览器操作：

| 工具类别 | 能做什么 |
|---------|---------|
| 内容提取 | 页面转 Markdown、表格自动识别、无障碍树解析、Shadow DOM 穿透 |
| 页面交互 | 点击按钮、填写表单、拖拽元素、滚动页面、等待元素出现 |
| 标签页管理 | 打开/切换/关闭标签页、获取所有标签页信息 |
| 网络请求 | 发起 HTTP 请求、获取 API 数据 |
| 媒体输出 | 页面截图、二维码生成、文件下载 |
| 存储管理 | Cookie 读写、LocalStorage/SessionStorage 操作 |
| 书签历史 | 书签搜索、浏览历史搜索 |
| AI 协作 | 子任务分派、任务规划、UI 原型生成与预览 |

这意味着什么？你可以说：

- 「把这个页面的价格表提取出来，导出为 Excel」→ 它自动识别表格、提取数据、触发下载
- 「帮我在这个表单里填入测试数据并提交」→ 它逐字段填写、找到提交按钮、点击
- 「打开这三个竞品网站，把功能特点整理成对比表」→ 它依次打开页面、提取内容、生成对比矩阵

### 2. ReAct 推理循环 + 三级反思：不只是执行，还会自我纠错

这是 AI Helper 最独特的设计。

AI 会犯错，工具调用会失败，页面结构会变化。如果只是"调用工具 → 返回结果"，一个环节出错整个任务就崩了。

AI Helper 实现了 **三级质量保障体系**：

```
第 1 级：工具预筛选
  ↓  从 50+ 工具中智能选出 5-10 个相关项，节省 Token 成本
第 2 级：工具级反思 + 子任务反思
  ↓  每次工具调用后评估结果有效性，每个子任务完成后检查完整性
第 3 级：后置反思（7 维度评分）
  ↓  最终答案按 完整性/准确性/相关性/工具使用/清晰度/安全性/效率 打分
  ↓  低于阈值 → 自动修订或重试
```

这个设计的实际效果是：**即使中间步骤出了错，AI 能自己发现、自己纠正，不需要你盯着它干活。**

### 3. 多智能体协作：一个插件，多个 AI 专家

一个人不可能什么都精通，AI 也一样。AI Helper 内置了 5 个专业助手角色：

- **代码审查专家** — 安全漏洞、性能问题、最佳实践审核
- **网页自动化助手** — 表单填写、数据抓取、页面操作编排
- **数据分析师** — 数据提取、统计分析、可视化图表
- **文档撰写助手** — 技术文档、分析报告、内容总结
- **默认助手** — 通用对话与网页问答

更关键的是：**你可以创建自己的 Agent**，为每个 Agent 配置专属的系统提示词和工具权限。复杂任务还可以自动拆解、分派给不同 Agent **并行处理**——这才是真正的多智能体协作。

### 4. 可选代理服务：突破浏览器沙箱

浏览器的安全沙箱是必要的，但它也限制了 AI 的能力边界——你没法让浏览器里的 AI 读你本地的代码仓库、执行构建命令、或者批量处理文件夹里的 CSV。

AI Helper 提供了一个可选的 **Node.js 本地代理服务**，一键启动后就能解锁：

- **文件系统操作**：读写本地文件、目录浏览、文件搜索（支持正则）
- **命令执行**：运行终端命令，WebSocket 实时输出流
- **Skill 技能系统**：把常用的多步骤工作流沉淀为可复用的技能
- **MCP 协议扩展**：接入第三方 MCP Server，无限扩展工具能力

安全方面也不含糊：路径沙箱 + 操作黑白名单 + 关键操作确认的三层防护。

### 5. 智能上下文管理：对话再长也不崩

用 AI 对话最烦什么？**聊着聊着就开始胡言乱语。** 这是因为 Token 超出了模型的上下文窗口。

AI Helper 的上下文管理策略：

- **自适应 Token 预算**：根据模型上下文窗口动态计算可用 Token
- **三级压力监测**：safe → warning → critical，不同级别触发不同策略
- **引用压缩**：网页内容引用自动摘要，不永久占位
- **增量摘要**：Token 超标时自动压缩旧的工具调用轮次

结果就是：**即使处理了十几个网页、执行了几十个工具调用，对话质量也不会断崖式下跌。**

## 真实场景：不是「如果」，是「现在就能」

### 场景一：开发者的代码审查

```
用户（在 GitHub PR 页面）："审查这个 PR 的代码变更，重点关注安全问题"
```

AI Helper 的实际执行过程：
1. 识别页面中的代码 diff 区域
2. 提取变更内容
3. 逐文件审查：安全问题 → 性能问题 → 最佳实践
4. 输出结构化报告，标注严重等级和修改建议

不是"把代码贴给 ChatGPT"的体验，而是**直接在 PR 页面上完成审查**。

### 场景二：数据分析师的日常

```
用户（在竞品定价页面）："把这个价格表和隔壁那家的价格表做个对比分析"
```

AI Helper：
1. 提取当前页面表格
2. 自动打开竞品页面标签
3. 提取竞品定价表格
4. 生成对比矩阵 + 差异分析
5. 可选导出为 Excel 或 PDF 报告

原本需要 30 分钟的手工操作，**一句话 + 30 秒完成**。

### 场景三：启用代理后的超能力

```
用户："分析我项目里所有 .js 文件的代码复杂度，找出最需要重构的 5 个文件"
```

AI Helper + 代理服务：
1. 递归扫描项目目录
2. 逐个读取 JS 文件
3. 分析圈复杂度、函数长度、重复代码
4. 排名输出 TOP 5 + 重构建议

**AI 直接操作你的本地文件系统，这在传统浏览器扩展中是不可想象的。**

## 技术栈与架构

```
┌─────────────────────────────────────────┐
│           Side Panel (UI 层)             │
│  对话面板 · Token 统计 · 执行日志 · 质量评估  │
├─────────────────────────────────────────┤
│     Background Service Worker (核心层)    │
│  ReAct 推理引擎 · 工具调度 · 反思系统       │
│  上下文管理 · 多 Agent 协作 · 流式控制      │
├─────────────────────────────────────────┤
│       Content Script (页面执行层)          │
│  页面内容提取 · DOM 操作 · Shadow DOM 穿透  │
│  划词工具栏 · 表单交互 · 截图              │
├─────────────────────────────────────────┤
│     Agent 代理服务 (可选层，Node.js)       │
│  文件系统 · 命令执行 · Skill · MCP 扩展    │
├─────────────────────────────────────────┤
│         Storage (数据持久化层)             │
│    IndexedDB · chrome.storage            │
└─────────────────────────────────────────┘
```

- **构建工具**：Vite + @crxjs/vite-plugin
- **扩展协议**：Manifest V3（Chrome 114+）
- **前端技术**：Vanilla JS（无框架依赖，极致轻量）
- **LLM 兼容**：OpenAI Chat Completions 协议，支持 DeepSeek / 通义千问 / GPT-4 / Claude 等 30+ 模型
- **许可证**：MIT

## 如何开始

```bash
# 1. 克隆项目
git clone https://gitee.com/xiweicheng/ai-helper.git
或者
git clone https://github.com/xiweicheng/ai-helper.git
cd ai-helper

# 2. 安装依赖 & 构建（可选，仓库根目录已经存在打包好的dist目录）
npm install && npm run build

# 3. Chrome 加载扩展
# 打开 chrome://extensions/ → 开启开发者模式 → 加载已解压的扩展程序 → 选择 dist 目录

# 4. 配置 API Key（填写自己已购买模型平台申请的api key）
# 右键扩展图标 → 选项 → 填入 API Key → 选择模型

# 5.（可选）启动本地代理服务
cd agent && npm install && npm start
或者
npm install -g ai-helper-agent && aha start

启动后终端界面会输出6位配对码，复制后填入插件配置页中代理配置中的【配对码】输入框，点击【连接】即可完成配对
```

**不需要付费订阅，不需要注册账号。** API 费用直接付给你选择的模型厂商（DeepSeek 等国产模型有大量免费额度）。

## 开源，意味着什么

AI Helper 采用 MIT 许可证，这意味着：

- 你可以**完全免费使用**所有功能
- 你可以**查看每一行代码**，知道 AI 在做什么
- 你可以**自定义任何行为**——换模型、加工具、改 UI
- 你可以**部署在企业内网**，数据不出公司

在 AI 工具越来越封闭、越来越贵的趋势下，一个**开源、透明、可控**的选择，本身就是价值。
